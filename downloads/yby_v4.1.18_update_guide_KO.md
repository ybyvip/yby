# YBY V4.1.18 업데이트 안내

엑셀 한 행이 과거 신청·지급·사용결과를 함께 담은 자료라는 요청에 따라, 기본 업로드 경로를 **두 이력대장 직접 반영**으로 바꿨습니다. 기존 수신함에만 저장하는 방식도 반영 방식에서 선택할 수 있습니다.

## ‘선택 행 업로드’가 반응 없어 보인 원인

첨부 화면에서는 행 선택은 되어 있지만 하단 확인란은 체크되지 않았습니다. V4.1.17은 작은 안내 문구만 바꿔 작업이 멈춘 이유를 알아보기 어려웠습니다. V4.1.18은 확인란을 놓치면 선택 행 수·합계금액·금액미기재·미반납 건수를 보여주는 확인창을 띄웁니다. 확인 후 저장 중, 완료, 실패를 눈에 띄게 표시하며 실패 시 입력값을 유지합니다. 선택 행이 없거나 재검사가 필요하면 별도 안내합니다.

## 새 반영 순서

1. 전체백업을 만들고 보관합니다. 실행 중 서버 창에서 **Ctrl+C**로 종료합니다.
2. 새 ZIP을 **새 폴더**에 모두 압축 해제하고, 기존과 같은 Windows 계정으로 **RUN_LAN_WINDOWS.bat**를 실행합니다. 기존 `%LOCALAPPDATA%\YBY\app\data`와 인증서·설정은 유지합니다. 일반 업데이트에는 백업 복구를 하지 않습니다.
3. **법인카드 관리 → 외부자료 매칭 → 엑셀 대량 업로드**를 엽니다.
4. 반영 방식 **두 이력대장에 직접 반영**, 기본 소속 지점과 원본 Excel을 선택합니다.
5. **미리보기 · 다시 검사**로 원본 행·지점·사용자·끝자리·날짜·합계금액을 확인합니다. 지점 등 값을 바꿨다면 다시 검사합니다.
6. 정상 행을 선택하고 **선택 행 업로드**를 누릅니다. 확인란을 체크하지 않았으면 나타나는 구체적인 확인창에서 내용을 확인합니다.
7. 완료 후 **사용정산이력대장**이 열리고, 결과 안내의 **불출반납이력대장 보기**로 다른 대장도 확인합니다.

‘신청·정산 수신함으로만’을 선택하면 이전처럼 수신 → 매칭 → 실제 불출·반납·결재 경로를 이용합니다. 과거 완료 자료의 일괄 이관에는 기본값을 사용하세요.

## 원본을 보존하는 기준

| 원본 항목 | 사용정산이력대장 | 불출반납이력대장 |
|---|---|---|
| 지급일 | 원본 지급일을 사용일로 표시 | 불출일/처리 날짜로 표시 |
| 반납일 | 원본 반납일 보관 | 날짜가 있는 행만 반납 이력 추가 |
| 반납일 없음 | 원본 미반납 | 불출 이력만 추가, ‘원본 미반납’ 표시 |
| 합계금액 양수 | ‘이관완료’, 원본 합계금액 | 연결된 원본 정산 이관 상태 |
| 금액 빈칸 | ‘금액미기재’, 금액을 0으로 만들지 않음 | 반납일이 있으면 금액미기재 표시 |
| 0원 명시 | ‘금액0원’ | 금액0원 표시. 미사용 여부를 임의 확정하지 않음 |
| 카드 끝 4자리 | 그대로 보존 | 그대로 보존. 전체 카드번호 생성 안 함 |
| 사용자·부서·목적·사용목적 | 해당 항목에 반영 | 해당 항목에 반영 |
| 별도 신청일·신청자·예정일 누락 | 지급일·사용자를 대체값으로 사용하고 미리보기에서 안내 | 동일 기준 |
| 원본 사용횟수·전표·정리 등 | 상세 보기에서 원본 스냅샷 보존, 사용횟수는 참고값 | 임의의 세부 거래나 YBY 승인으로 변환하지 않음 |

한 행은 합계 1건입니다. **이관완료는 YBY 승인완료가 아닙니다.** 승인자·승인일·세부 사용처·수량·단가를 만들어 넣지 않습니다. 금액이 있는 이관은 유효 사용금액/통계에 포함하며 빈 금액과 0원은 제외합니다. 원본 사용횟수를 여러 거래로 늘리지 않습니다. 현재 운영 카드의 대여 상태나 승인대기 정산은 바꾸지 않습니다. 원본 미반납은 과거 자료의 표시이며 현재 카드 불출로 처리하지 않습니다.

## 대장 표시와 중복 검사

- 사용정산이력대장: 첫 열 **일련번호**, 다음 열 **입력경로**. 일련번호는 조회 권한 내 전체 이력의 저장 순서를 기준으로 하며 필터를 바꿔도 같은 화면 권한 안에서는 유지됩니다.
- 불출반납이력대장: **이력 ID 다음에 입력경로**. 목적 칸에 있던 출처 표시는 별도 열로 이동합니다.
- 새 직접 이관의 입력경로는 **엑셀 이관**입니다. 기존 YBY/Oracle/엑셀 수신 출처도 같은 열에서 구분합니다. 과거 출처가 없는 자료는 출처 미기록으로 표시합니다.
- Excel 및 인쇄/PDF 출력에도 앞쪽의 입력경로 열을 반영합니다. 이관 원본 상세 보기에는 실제 이관 처리자·시각을 별도 표시합니다.
- 같은 파일/이름 변경/행 순서 변경/파일 내 반복 행은 중복 제외합니다. 식별 기준이 같은데 금액 등 내용이 달라졌다면 충돌로 막습니다. 실제 별도 건이 식별 기준까지 같다면 원본에 서로 다른 ‘외부행ID’를 넣어 구분해야 합니다.
- V4.1.17에서 **수신만 했고 업무에 적용하지 않은** 원본은 같은 Excel을 새 기본 방식으로 다시 올려 이력으로 전환할 수 있습니다. 기존 원문·매칭 자료는 남기고 이관완료 처리하여 다시 적용하지 못하게 합니다.
- 이미 실제 불출/반납/정산에 적용한 원본은 다시 이관하지 않습니다. 기존 YBY 업무 이력과 이중 계산하지 않도록 차단합니다.
- 저장 전체를 하나의 트랜잭션으로 처리합니다. 일부 저장 실패 시 대장·원본 등록·중복 기록을 모두 취소합니다. 지점별 접근 권한은 서버에서 검사합니다.

제목 5행, 업무 6~9행의 원본을 카드가 0장인 시험 환경에서 검사했습니다.

| 금액 있는 이관 | 1건 / 225,000원 |
| 금액미기재 | 3건 |
| 불출 이력 | 4건 |
| 반납 이력 | 3건 |
| 원본 미반납 | 1건 |

| 현재 카드·승인대기 정산·YBY 승인 자동 생성 | 0건 |

이 결과는 시험 수치입니다. 실제 회사 자료, 계정·암호, DB, 인증서 개인키와 첨부 Excel은 배포 파일에 포함하지 않았습니다. 업데이트만으로 과거 수신 자료를 자동 변환하지 않으므로 필요한 원본을 확인해 직접 이관하세요. 이관 자료의 사후 수정·취소 도구는 이번 추가 범위에 포함하지 않았으므로 잘못된 원본을 올리지 않도록 미리보기를 확인하세요.

Linux 시험 환경에서 서버·브라우저를 검증했습니다. 실제 회사 Windows/Edge/WebView2·방화벽·인증서 정책과 실제 Oracle 연결은 직접 실행하지 못했습니다. Oracle 담당 자료를 기다리는 기존 연계 준비 기능은 유지했습니다.
