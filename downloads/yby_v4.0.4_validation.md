# YBY V4.0.4 수정 및 검증 보고서

검증일: 2026년 10월 15일, 한국 시간. V4.0.3에서 반복된 실행·배포·인증서 사용성 문제를 수정한 전체 패키지입니다.

## 오류 원인과 수정

1. 첨부된 자료 잠금 오류는 다른 서버/유지보수 프로세스의 실제 OS 잠금입니다. 파일이 남아 있다는 이유로 발생하는 오류가 아닙니다. 이전 bootstrap은 중복 실행에도 업데이트 잠금을 먼저 시도했습니다. 이제 PID 파일의 앱 경로, 실제 프로세스 인자, HTTPS 체인/localhost, 서버 버전/DB를 확인해 같은 정상 서버로 재접속합니다. 실행 중인 코드·DB를 덮어쓰거나 잠금을 삭제하지 않습니다.
2. 구버전 서버가 실행 중이면 현재 실제 버전을 보여 주고 종료 후 업데이트하도록 안내합니다. 새 ZIP 실행만으로 업데이트됐다고 표시하지 않습니다. 설치/시작을 별도 잠금으로 직렬화하며 유지보수 충돌은 기다린 뒤 명확히 안내합니다.
3. 서버 PC의 CA는 개인 저장소(My)에 발급만 하고 신뢰 저장소(Root)에 등록되지 않아 브라우저 경고가 발생했습니다. 이제 HTTPS 준비 후 현재 사용자에게 최초 1회 등록 동의를 받고 Windows CurrentUser Root에 등록한 뒤 로그인 화면을 엽니다. 등록 취소/정책 차단 시 성공으로 표시하지 않고 서버를 유지합니다.
4. 다른 PC에서는 지문 확인/예 버튼, Windows 신뢰 등록, 실제 HTTPS/정확한 CA/버전/DB 검사 후 브라우저를 엽니다. 재실행 시 이미 등록된 CA는 다시 묻지 않습니다. Python과 일반적인 관리자 권한은 필요하지 않습니다.
5. 실행 폴더의 LAN_CLIENT를 찾기 어려운 문제에 대응해 공개 파일 6개만 포함하는 LAN_CLIENT.zip과 OPEN_LAN_CLIENT.bat를 제공합니다. 서버 개인키/DB는 포함하지 않습니다.
6. STOP_SERVER.bat는 새 패키지의 종료 도구로 AppData의 검증된 해당 서버만 종료하고 종료를 기다립니다. 다른 PID/프로그램은 종료하지 않습니다. Windows 포트는 SO_EXCLUSIVEADDRUSE로 보호하며 Linux는 TIME_WAIT에 불필요하게 오래 기다리지 않도록 실제 서버와 같은 재사용 정책으로 검사합니다.
7. 방화벽 도구는 일반 실행 후 필요한 시점에 UAC를 요청하며 원래 사용자의 설정 경로를 유지합니다. 지정 Python·포트·Domain/Private·사내 출발지 범위를 유지합니다.
8. V4.0.2에서 이미 손상된 인증서 ACL 복구 도구도 포함합니다. 원래 사용자를 캡처하고 UAC 후 인증서 파일 소유권/권한만 복구한 뒤 원래 일반 권한 Python의 실제 키 로드를 검사합니다.

## 자동 검증

- 서버·권한·동시성·업무 API·백업·마이그레이션·실행 회귀: **117개 테스트 통과**.
- 실제 사설 인터페이스 HTTPS: 최초 인증서 생성, localhost/사내 IP 주소 검증, 초기 로그인, 강제 비밀번호 변경, Secure/HttpOnly/SameSite 쿠키, 잘못된 CA/주소 거부, 설정·인증서·비밀번호 유지 및 동일 포트 재시작.
- 실제 중복 실행: 동일 PID 유지, 서버 중단 없음, CA/설정 재생성 없음. 서버가 자료를 점유하면 직접 재설정은 계속 거부.
- 읽기 전용 속성의 한글 경로 원본 → 사용자 실행 폴더: 실제 bootstrap 실행, 재실행 시 같은 서버, 실제 로그인/카드 저장, 원본 DB SHA-256 유지, 반복 설치 시 사용 자료 유지.
- 실제 V4.0.3 → V4.0.4: 구버전 실행 중 업데이트 차단/재접속 안내, 종료 후 업데이트, 첫 시작 전 DB 바이트 보존, 기존 관리자 비밀번호/카드 자료/CA·키 바이트 보존, 이전 프로그램 백업.
- 실제 Chromium HTTPS: 격리된 테스트 사용자 NSS 저장소에 해당 테스트 CA를 신뢰 등록한 후 localhost 및 사설 IP 로그인, 강제 최초 변경 및 보안 쿠키 확인. ignore_https_errors/인증서 검증 우회 옵션을 사용하지 않음.
- 실제 업무 화면: 문서 제출·최종 결재, 저장 실패 시 입력 유지, XLSX/전체 백업 다운로드, 하이패스 등록, 민원 처리, 공지·개인 메모·채팅, 모바일 폭, 키보드 모달, JS 오류 부재.
- PowerShell 파일의 실제 문법 트리 파싱, Python 3.11 구문 호환 검사, ZIP CRC·경로·모든 MANIFEST SHA-256 확인.

검증 도중 테스트 환경 프록시가 사설 IP 브라우저 접속을 막은 경우 격리된 시험 브라우저의 내부 주소 직접 접속 설정으로 수정했습니다. 생성된 진단 로그가 시험용 manifest에 잘못 들어간 경우 배포 대상에서 제외해 다시 확인했습니다. 검증 실패를 통과로 계산하지 않습니다. 배포물의 별도 package_verification.json에 최종 ZIP 해시와 결과를 기록합니다.

## 실제 Windows/회사망에서 남는 확인

클라우드 실행 환경은 **Linux/Python 3.12/Chromium**입니다. 실제 Windows 10/11·Python 3.14·Windows CSP/NTFS/UAC/인증서 등록/Defender·Edge·회사 프록시·VPN·방화벽 정책은 이 클라우드에서 실행하지 못했습니다. 문법 파싱/모의 명령 검사는 실제 Windows 통과와 구분합니다. 무조건적인 전 PC/회사망 정상 동작이나 완벽한 보안을 보장하지 않습니다.

서버의 **VERIFY_WINDOWS.bat**는 실제 일반 사용자 Windows에서 패키지 해시, 앱/PID/버전/DB, 서버 키 읽기, Windows 신뢰 저장소를 이용한 localhost/사내 IP의 HTTPS 로그인 HTML, .NET의 정확한 CA, 네이티브 자료 잠금 충돌 차단, bootstrap 재실행·동일 PID/CA를 검사합니다. 결과 JSON은 `%LOCALAPPDATA%\YBY\diagnostics`에 저장됩니다. Linux에서는 Windows 검사 통과를 출력하지 않습니다.

다른 PC는 **LAN_CLIENT/CHECK_CONNECTION.bat**로 해당 Windows 사용자의 인증서 및 실제 회사망 HTTPS 경로를 별도로 검사합니다. 이 확인이 있어야 그 PC의 연결을 검증했다고 말할 수 있습니다. 회사 정책이 루트 등록 또는 TCP 경로를 막으면 IT의 인증서 배포/망 허용이 필요합니다. 사내 IT 발급 인증서를 쓰는 운영도 가능합니다.

실제 고객 운영 DB는 제공되지 않았으므로 원본을 보존하는 시험용 DB/업무 자료로 이전을 검증했습니다. 업그레이드 전 운영 자료 백업과 현장 검증을 권장합니다.
