# V4.0.1 接속 수정 검증 기록

검증일: 2026년 10월 15일(한국 시간). 첨부된 V4.0.0 ZIP의 SHA-256은 0f9b0355bfd0b2c9d54653e7b951f2dbbfe45f863079fad5f738d4203f96f6cc였으며, 기존 manifest 99개 파일을 모두 확인하고 수정했습니다. 실제 고객 DB·개인키·업무 첨부는 제공되지 않았고 테스트에 사용하지 않았습니다.

## 원인과 수정

화면은 10.10.0.121:5000에서 ERR_CONNECTION_REFUSED를 표시합니다. 이는 로그인·정산 처리 이전의 TCP 연결 문제입니다. V4.0.0의 기본 HOST와 런처 기본값이 127.0.0.1이므로 같은 서버의 사내 IP 또는 다른 PC에서 접근할 수 없습니다. V4.0.0은 공유 인터페이스에 HTTPS를 요구하지만 자동 설정 도구가 없었으며, 기존 방화벽 도구는 기본 포트/Private 프로필만 처리했습니다. 화면만으로 실제 PC의 서버 종료·IP 변경·방화벽 상태까지 확정할 수는 없습니다.

V4.0.1에서 사내망 HTTPS 설정·실행, 서버에 실제 할당된 RFC1918 IPv4 확인, OS 인증서 도구 기반 개별 CA/서버 인증서 생성, 설정 저장과 일반 런처 재사용, 클라이언트 공개 인증서·지문 확인 설치·TCP/HTTPS 진단 도구, 실제 포트/Python 경로/Domain·Private/사설 IPv4 범위의 방화벽 도구를 추가했습니다. 공유 HTTP와 인증서 검증 우회는 허용하지 않습니다. 서버 CA/키·설정과 업무 DB 백업의 범위도 안내했습니다.

인증서 및 업무 자료는 임시 폴더에서만 생성했고 테스트 종료 시 삭제했습니다. 장애 주입 테스트의 예상 ERROR 로그는 unittest 결과와 구분합니다. ZIP에는 실제 DB·인증서·개인키·기기별 설정을 넣지 않으며 각 서버에서 생성합니다.

## 직접 검증하지 못한 범위

- 실제 Windows PowerShell New-SelfSignedCertificate/CSP·인증서 저장소·NTFS ACL·방화벽 규칙·클라이언트 certutil 설치·Edge. Windows 실행 파일과 스크립트는 포함했지만 Linux에서 해당 Windows API가 실행됐다고 주장하지 않습니다.
- 실제 고객의 두 PC 간 통신, 회사 VPN 라우팅·보안 ACL·프록시/PAC·인증서 정책. 클라우드의 사설 인터페이스 접근을 고객 사내망 실측으로 표현하지 않습니다.
- 실제 고객 업무 DB 이전·복원, Windows Excel 및 장시간 운영.
- 신규 인터넷 공개, 포트포워딩, 카드사·은행·ERP 연동. 이번 수정 대상은 같은 사내망/회사 VPN입니다.
