# V4.1.23 실제 검증 결과

V4.1.22 전체 ZIP을 별도 작업 폴더에 해제해 수정했습니다. 기존 V4.1.22 ZIP과 원래 저장소는 보존했습니다. Linux/Python 3.12, Node.js, Chromium/Playwright에서 임시 DB·시험 계정·가상 자료로 검증했습니다.

## 실제 통과한 검사

- 전체 서버 회귀: `python -m unittest discover -s tests -v` **393개 통과**, 실패·건너뜀 없음.
- 이후 스키마 10→11의 기존 분실 이력·점검기록 보존 검사를 추가했습니다. `python -m unittest discover -s tests -p test_v4123.py -v` **16개 통과**. 위 393개에 포함된 15개와 중복을 제외하면 서로 다른 서버 검사 총 **394개**입니다.
- 새 서버 검사: 이상징후 필수 정보·시각 검증, 권한 차단, 기존 이력 보존, 양방향 대체 연결, 불출중/중복 번호 대체 금지, 저장 장애 전체 롤백, 동시 대체 중 하나만 성공, 대시보드 전용 권한의 지점별 이상 숫자, 민원 중복접수 방지, 문서 첨부 용도/지점/권한, 민원 실패 때 자료 불변, 승인완료 대상 선별, 완료 시 원래 업무자료 불변, 변경된 원본 재점검, 위조 대상 거절, 관리자 전체 조회에서 지점 완료 반영, 이전 기록 보존.
- `node --test tests/ledger_v418.test.cjs tests/stats_v4115.test.cjs`: 기존 대장·통계 순수 계산 **2개 통과**.
- `python tests/browser_v4123.py`: 실제 클릭·입력·다운로드로 아래 흐름 통과. JavaScript 런타임 오류 없음.
  - 정상 이외 선택의 음영, 인지 시점·제보자·접수자·내용·조치 저장, 상태 문구 클릭 후 기존 내용 확인, 코드 대신 기본 정보 박스 표시.
  - 대체카드 입력, 종료카드목록과 이전 이상징후·대체 연결 상세, 대시보드 붉은 숫자 변경.
  - 세부목적/문서 입력 한 줄 배치, 검색 필터 옆의 빈 수신함 안내, 불출예정·반납처리 첫 열의 일련번호, 임시저장·확정·반납.
  - 민원과 보고서 미리보기 시 DB/파일 업로드가 아직 일어나지 않음, 돌아가기 후 입력 유지, 최종 제출 후 상세 첨부 링크의 실제 다운로드, 보고서함 제목/문서번호 순서.
  - 승인완료 명세대조 완료 후 목록에서 제외, 기존 업무자료 불변, 박스형 저장기록 상세, 점검기록 XLSX 실제 다운로드와 저장한 사유 문자열 확인.
  - 수기정정 읽기 전용 항목의 하단 배치와 원본 출처·배치·스냅샷 표시 제거, 사용정산 열 순서, 불출반납 이력 ID 제거/처리일시 위치와 머리글-값 개수 일치.
  - 1600/1024/768/390 폭에서 불출 입력 화면의 문서 전체 가로 넘침 없음.
- `python tests/browser_v4121.py`: 기존 회사 정책·지점 추가·월별 기록/집계 엑셀·자기승인·암호화 백업 다운로드·틀린/맞는 암호 복원시험·권한 격리 화면 통과. 추가된 두 엑셀 버튼을 정확히 구분하도록 테스트 선택자를 갱신했습니다.
- `python tests/browser_tls.py`: 검증을 끄지 않고 별도 신뢰 CA로 실제 Chromium HTTPS 로그인, HTTP→HTTPS 이동, 로그아웃 후 재접속 통과.
- `python tests/bootstrap_smoke.py`: 읽기전용 한글 경로의 원본 → 실행 폴더 설치, 실제 기동·로그인·업무 저장, 중복 기동 PID 유지와 원본 DB/반복 설치 자료 보존 통과.
- 전체 Python AST와 앱 JavaScript 구문 검사 통과.

기존 테스트 중 승인 전/대여중 자료를 점검 대상으로 사용하던 픽스처는 이번 요구에 맞게 승인완료 자료로 변경했습니다. 이상징후의 새 필수 상세 입력과 스키마 버전 검사도 갱신했습니다. 검증을 통과시키기 위해 권한·무결성 검사를 끄거나 원래 업무 상태를 바꾸지 않았습니다. 장애 테스트 로그의 의도적인 ERROR 주입과 실제 테스트 실패를 구분했습니다.

## 미검증·적용 전 확인

- 실제 Windows BAT/PowerShell/Edge, Windows 사용자별 DPAPI·ACL 및 기존 인증서의 현장 적용.
- 고객의 실제 업무 DB·첨부·계정·실제 사내 인증서로 한 운영 업그레이드, 다른 PC에서의 접속.
- 모든 과거 버전의 선택적 브라우저 스크립트 전체, 모든 인쇄/엑셀 조합과 장시간 대규모 부하.

이전 고객 자료가 첨부되지 않았으므로 가상 자료로 보존·업그레이드를 검사했습니다. 실제 반영 전에는 서버 종료·전체 백업 후 복사본에 먼저 적용해 확인하세요. 기존 계정·인증서 재발급이나 초기화를 요구하는 변경은 하지 않았습니다.
