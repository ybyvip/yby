# 인증서 접근권한 오류 복구 — V4.0.3

보내주신 로그에서는 인증서 생성과 사내망 설정 저장은 완료됐고, 그 뒤 certificates/root-ca.cer를 Python에서 읽을 때 PermissionError가 발생했습니다. 이전 버전의 인증서 권한 처리 코드를 수정했습니다. 업무 DB 문제로 판단하거나 인증서를 삭제할 필요가 없습니다.

## 지금 설치된 V4.0.2를 빠르게 복구

1. 종료된 프로그램 창을 닫습니다. 기존 프로그램과 AppData/YBY 폴더는 삭제하지 않습니다.
2. 작은 인증서 복구 패치 ZIP을 새 폴더에 전체 압축 해제합니다.
3. **REPAIR_CERTIFICATE_ACCESS.bat**를 기존 프로그램을 사용한 동일한 Windows 사용자 계정의 **일반 권한**으로 실행합니다.
4. **PASS: Python에서 인증서 4개 읽기 및 서버 인증서/개인키 로드 확인** 문구를 확인합니다.
5. 기존 **RUN_LAN_WINDOWS.bat**를 다시 실행합니다.

패치는 `%LOCALAPPDATA%\YBY\app\certificates`의 접근권한만 복구합니다. DB·설정·인증서를 삭제하거나 재발급하지 않고 프로그램 코드를 덮어쓰지 않습니다. CA 지문을 출력하며 개인키 내용은 출력하지 않습니다. 회사 전체 폴더 권한이나 Everyone 권한을 변경하지 않습니다. Python 3.11 이상을 사용하며 새 패키지 설치가 필요하지 않습니다.

## 재발 방지 전체 수정본 사용

1. V4.0.3 전체 ZIP을 새 폴더에 압축 해제합니다.
2. 기존 사용자 계정으로 RUN_LAN_WINDOWS.bat를 일반 권한으로 실행합니다.
3. 이미 사용자 실행 폴더에 있는 업무 자료·설정·인증서를 그대로 사용하며, 인증서 읽기 전에 기존 파일 권한을 복구합니다.
4. OPEN_RUN_FOLDER.bat에서 LAN_CLIENT 폴더를 확인하여 다른 PC에 전달합니다.

이미 `%LOCALAPPDATA%\YBY\app`에서 사용 중이라면 원본 다운로드 폴더의 오래된 DB를 다시 복사하지 마세요. 사용자 실행 폴더에 최신 자료가 있습니다. 다른 DB가 들어오면 이전 버전부터 덮어쓰기를 차단합니다. 새 설치/실제 자료 이전은 README_V4.md의 백업·이전 절차를 따르세요.

## 수정 내용과 확인 범위

- 폴더용 `(OI)(CI)F` 상속 규칙과 파일용 직접 `F` 규칙을 분리했습니다. 폴더 상속 규칙을 파일 전체에 `/T`로 한꺼번에 적용하지 않습니다.
- 파일 권한 대상은 현재 Windows 사용자·SYSTEM·관리자이며 Everyone은 추가하지 않습니다.
- 기존 인증서 파일을 열기 전에 잘못된 권한을 복구합니다.
- 권한 설정 명령의 성공뿐 아니라 실제 Python 파일 읽기와 인증서/개인키 로드를 검사합니다.
- 공개 인증서 읽기 단계의 오류 위치를 정확하게 표시합니다.
- 인증서 바이트와 CA 지문이 복구 전후 유지되는 검사를 추가했습니다.

검증 기록은 VALIDATION_V4.md와 배포 검증 JSON에 있습니다. Linux에서 112개 테스트 및 실제 HTTPS 흐름을 검사했으며, Windows ACL 명령 자체를 이 클라우드에서 실행 완료로 표시하지 않습니다. 대신 복구 패치가 해당 Windows PC의 실제 Python 읽기/SSL 로드를 검사합니다. PASS가 나오지 않으면 표시된 오류 내용을 전달해 주세요.
