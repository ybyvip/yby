# YBY V4.1.0 수정·검증 보고서

검증일: 2026년 10월 16일(한국 시간). 기준: V4.0.4 전체 패키지. 사용자 요청의 접속, 세션·관리자 비밀번호, 건별 정산·본인 결재를 개선했습니다. 세부 사용법은 CHANGES_V4_1_KO.md에 있습니다.

## 원인과 구현

- 접속 오류: 기존 TLS 전용 수신 포트에 일반 HTTP를 전송해 연결이 초기화됐습니다. 이제 같은 포트에서 HTTP 탐색만 HTTPS로 308 이동하고 로그인/업무는 TLS 1.2 이상으로 처리합니다. 허용 Host만 사용하며 HTTP POST의 인증 정보를 처리하지 않습니다.
- 로그인 접근: 최초 접속 성공 시 사용자 바탕화면에 로그인 바로가기를 만들고 Edge/Chrome 전용 창을 엽니다. 접속용 공개 파일은 클라이언트 AppData의 안정된 경로에 보관합니다. 서버 시작 창은 별도로 유지해야 합니다.
- 계정 저장: 기존 코드는 변경 대상의 세션을 invalidate했습니다. 일반 저장은 세션을 유지하고 DB 권한을 매 요청에 적용합니다. 관리자 재설정은 다음 로그인에 새 비밀번호/최초 변경 요구를 적용합니다. 사용자별 명시적 접속 종료와 계정 삭제·만료·본인 비밀번호 변경 보호는 유지합니다.
- 관리자 조회: 현재 비밀번호는 인증 해시와 분리해 Windows DPAPI/Linux Fernet로 암호화합니다. 최고관리자 재인증 후 특정 계정 하나만 30초 표시하고 창 이탈·닫기·로그아웃·시간 만료 시 지웁니다. 늦게 도착한 응답도 사용자/역할/화면 일련번호를 확인합니다. 실패 재인증은 제한하고 조회 메타데이터만 감사 기록에 남깁니다.
- 기존 비밀번호: 해시에서 복원하지 않습니다. 새 버전의 성공적인 로그인/비밀번호 변경 시 표시용 암호문을 등록합니다. 이전 해시만 남은 계정에는 조회 불가 이유를 알려 주며 기존 변경 시각을 유지합니다. 화면의 별도 변경 이력은 비밀번호 값 없이 대상·수정자·시각·구분/IP를 제공합니다.
- 정산: 건별 사용일/구분/사용처/상세내역/수량/단가/금액/비고, 행 추가·삭제, 자동 합계, 서버 재계산, 반납과 정산의 원자적 저장. 1~100행, 양의 정수 수량/단가, 총 1조원 이하. 이전 단일 금액 정산도 호환합니다.
- 결재: ALL 최고관리자의 본인 정산 승인·반려를 허용하고 본인 처리 여부·결재자·시각을 기록합니다. 일반 지점자의 결재 및 내부 보고서의 본인 문서 결재는 허용하지 않습니다.
- 이력/출력: 대기·최종 정산의 건별 상세, 인쇄/PDF, 엑셀의 행별 명세. 문서 합계와 통계에는 같은 금액을 중복 반영하지 않습니다. 기존 정정은 원본과 반대 금액 기록을 유지합니다.
- 업데이트: 실제 자료/계정/인증서를 보존하고 프로그램 이전본을 보관합니다. 최초 V4.1.0 DB 초기화 전에 기존 DB·첨부의 전체 백업을 생성합니다. Linux의 표시용 Fernet 키도 전체 백업/복원에 포함합니다.

## 수행한 자동 검증

1. **138개 단위·API·회귀 테스트 통과**: 기존 업무/권한/동시성/마이그레이션/백업/로그인 보호와 새 요구 사항 21개. 기존의 강제 로그아웃/본인 정산 승인 금지 테스트는 요청된 정책에 맞게 접속 유지·본인 처리 기록·권한 즉시 차단 검증으로 변경했습니다.
2. 새 테스트에는 대상·다른 계정의 접속 유지, 재설정 후 새 로그인 최초 변경, 명시적 대상 접속 종료, 최고관리자 재인증/시도 제한, 암호문 변조·다른 사용자로의 복사 거부, 암호문 백업·복원, 일반 상태·로그의 원문 부재, 미등록 해시의 로그인 후 등록, 건별 합계/잘못된 행/원자적 반납, 본인 승인·반려와 일반 사용자 거부, 같은 포트 HTTP 이동/허용 Host/평문 인증 거부가 포함됩니다.
3. 실제 Chromium 다중 사용자 UI: 지점자가 로그인한 상태로 관리자 권한/비밀번호 저장, 접속 유지와 메뉴 권한 갱신, 별도 비밀번호 이력, 관리자 재인증 후 현재 값 표시/창 이탈 삭제/일반 상태 비노출, 늦은 응답 폐기, 두 건의 수량×단가/23,000원 합계, 반납·정산 저장, 상세 이스케이프, 최고관리자 본인 승인, 엑셀 건별 합계 확인.
4. 실제 Chromium HTTPS: 격리된 NSS 사용자 저장소에 시험 CA를 정식 신뢰 등록한 뒤 localhost/사설 IP의 HTTP 탐색이 HTTPS로 이동하는지 확인했습니다. 초기 비밀번호 변경, 보안 쿠키, 로그아웃 → 창 닫기 → HTTP 주소 재입력 → HTTPS 재로그인을 확인했습니다. 인증서 검증 우회 옵션을 사용하지 않습니다.
5. 기존 업무 UI 회귀: 문서 제출/최종 승인, 실패 시 입력 유지, XLSX/전체 ZIP 백업 다운로드, 하이패스 등록, 민원, 공지, 메모, 채팅, 모바일 폭/키보드 모달, JS 오류 부재.
6. 실제 V4.0.4 → V4.1.0 시험: 실행 중인 구버전의 코드/자료를 교체하지 않고 재접속 안내, 종료 후 업데이트, 시작 전 DB 바이트/CA·개인키 보존, 기존 비밀번호/시험 카드 자료 유지, 자동 이전 백업, HTTP→HTTPS 접속.
7. 최종 ZIP의 CRC·경로·MANIFEST 전체 SHA-256·고객 DB/인증서/키/로그 미포함, PowerShell 문법 트리 및 Python 3.11 구문, 압축 해제본의 전체 138개 테스트·실제 bootstrap·사설 IP HTTPS/로그인/재시작 검증.

실패를 성공으로 계산하거나 HTTPS 검증을 끄지 않습니다. 테스트의 DB/권한 장애 주입으로 출력되는 예상 오류 로그는 테스트 러너의 최종 결과와 구분합니다. 최종 ZIP 해시와 수행 결과는 별도 package_verification.json에 기록합니다.

## 현장 확인과 한계

이 클라우드의 실제 실행 환경은 **Linux/Python 3.12/Chromium**입니다. 실제 Windows 10/11·Python 3.14·DPAPI·NTFS·PowerShell 실행·바탕화면 바로가기·Edge 전용 창·방화벽·회사 VPN/망 정책을 여기서 실행한 결과로 주장하지 않습니다. Windows 명령과 문법 검사는 실제 Windows 실행과 다릅니다.

서버 **VERIFY_WINDOWS.bat**에 실제 Windows DPAPI 암호화 왕복, 일반 권한의 서버 키 읽기, Windows 신뢰 저장소의 HTTPS/로그인 HTML, HTTP→HTTPS 이동, 프로세스 경로·버전, 네이티브 자료 잠금·중복 실행 유지 검사를 포함했습니다. 다른 PC는 **CHECK_CONNECTION.bat**로 해당 사용자의 실제 인증서·회사망 경로를 확인해야 합니다. 정책 차단은 회사 IT의 허용/배포가 필요합니다.

실제 고객 운영 DB가 제공되지 않아 시험용 업무 자료로 업데이트를 검증했습니다. 암호화된 비밀번호 보관은 사용자 요청에 따른 기능이며 백업/서버 사용자 권한을 엄격히 관리해야 합니다. Windows 사용자를 바꾸면 DPAPI 표시 자료를 다시 등록해야 할 수 있습니다. 기존 비밀번호 해시를 복원하거나 운영 자료를 임의 삭제하지 않습니다.
