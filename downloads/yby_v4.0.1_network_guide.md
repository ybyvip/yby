# V4.0.1 사내망·회사 VPN 접속 안내

V4.0.0 기본 실행은 127.0.0.1에서만 요청을 받아 다른 PC의 10.10.0.121:5000 접속이 거부될 수 있었습니다. V4.0.1은 사내망 HTTPS 설정·실행과 클라이언트 인증서 설치 도구를 제공합니다. Python 3.11 이상, Windows 10/11의 기본 Windows PowerShell 5.1을 사용하며 서버 일반 실행에 pip 설치가 필요하지 않습니다.

## 서버 PC에서 할 일

1. 기존 서버를 종료하고 기존 프로그램 폴더 전체를 별도로 백업합니다.
2. 새 ZIP을 새 폴더에 전체 압축 해제합니다. 기존 폴더에 덮어쓰지 않습니다.
3. 기존 자료를 계속 쓰려면 기존 `data` 폴더 전체를 새 프로그램의 `data`로 복사합니다. DB·첨부·기존 키를 함께 보존합니다. 계정과 비밀번호는 유지됩니다.
4. **RUN_LAN_WINDOWS.bat**를 일반 사용자로 실행합니다. 여러 IPv4가 발견되면 `ipconfig`에서 확인한 서버 사내망 IPv4를 입력합니다. 화면에 나온 실제 주소를 사용하며 10.10.0.121을 무조건 입력하지 않습니다.
5. 최초 실행에 이 서버의 HTTPS 인증서를 만들고 사내망 수신을 시작합니다. 서버 화면에서 `LAN HTTPS 확인 완료`를 확인합니다. 실행 창을 열어 둡니다. 서버 로컬 브라우저는 인증서 설치 전 신뢰 경고를 표시할 수 있으므로 경고를 무시하지 말고 다음 클라이언트 절차를 이 PC에도 적용합니다.
6. **SETUP_SERVER_FIREWALL.bat**를 마우스 오른쪽 버튼 → **관리자 권한으로 실행**합니다. 최초 1회, 포트나 Python 설치 위치를 바꿀 때 다시 실행합니다. 설정된 TCP 포트 하나만 Domain/Private 프로필, 로컬 서브넷·사설 IPv4 출발지와 해당 Python 실행 파일에 허용합니다.
7. 필요하면 **DIAGNOSE_NETWORK.bat**로 이 PC의 주소·TCP·인증서·HTTPS·DB 상태를 확인합니다. 이 검사가 통과해도 다른 PC에서의 실제 경로는 별도 확인이 필요합니다.

사내망 설정은 `lan_settings.json`에 저장됩니다. 설정 후에는 기존 RUN_WINDOWS.bat도 저장된 사내망 설정을 사용합니다. 로컬 전용 실행이 필요하면 `python run_ready.py --local`을 사용합니다. 종료는 Ctrl+C 또는 STOP_V3.bat입니다. 절전·종료·실행 창 닫기는 서비스를 중단합니다.

## 접속하는 다른 PC에서 할 일

1. 서버에서 생성된 **LAN_CLIENT 폴더만** 다른 PC로 복사합니다. 원본 프로그램 전체, data, certificates 폴더는 공유하지 않습니다.
2. LAN_CLIENT 안의 **INSTALL_AND_CONNECT.bat**를 실행합니다. Python 설치나 관리자 권한은 보통 필요하지 않습니다.
3. 표시되는 CA 인증서 SHA-256을 서버 실행 창의 값과 비교합니다. 일치하고 서버 관리자가 전달한 폴더가 맞으면 `YES`를 입력합니다. 현재 Windows 사용자의 신뢰할 수 있는 루트에 이 서버용 CA를 등록합니다. 회사 정책에서 차단하면 IT 관리자에게 요청합니다.
4. TCP·HTTPS·인증서·프로그램/DB 확인 후 브라우저가 열립니다. **https://서버의실제IPv4:포트/** 로 접속해야 합니다. 서버 주소가 10.10.0.121이고 포트가 5000이면 **https://10.10.0.121:5000/** 입니다.
5. 서버 PC 자체에서도 LAN_CLIENT의 같은 설치 절차를 수행하면 로컬 브라우저의 인증서를 신뢰할 수 있습니다.
6. 실패하면 LAN_CLIENT 안의 **CHECK_CONNECTION.bat**로 TCP 실패와 인증서/HTTPS 실패를 구분합니다. 인증서 검증을 끄거나 브라우저 경고를 무시하는 방법은 사용하지 않습니다.

공개 CA 인증서를 신뢰하는 것은 해당 CA로 발급한 인증서를 이 Windows 사용자가 신뢰하게 만드는 작업입니다. 서버의 CA 개인키를 보호하고, 전달받은 지문을 서버 관리자의 값과 비교하세요. 신뢰 해제는 LAN_CLIENT/접속안내.txt의 지문 확인 절차를 따릅니다.

## 오류별 확인

| 증상 | 확인 및 조치 |
| --- | --- |
| ERR_CONNECTION_REFUSED 또는 TCP 실패 | 서버 실행 창, 실제 IPv4, 포트, 방화벽 Domain/Private 프로필, VPN 경로·사내 ACL 확인. 기본 RUN_WINDOWS만 처음 실행한 경우 RUN_LAN_WINDOWS로 설정 |
| 인증서 오류 | 클라이언트 인증서 설치 여부, SHA-256, PC 시각, 실제 접속 IP와 인증서 일치 확인. 경고 무시 금지 |
| HTTP 주소로 실패 | V4 사내망 공유는 HTTPS. `http://` 대신 화면에 나온 `https://` 주소 사용 |
| 서버에 지정 IP가 없다고 표시 | DHCP·VPN·네트워크 변경 가능. `ipconfig`의 현재 서버 IPv4 확인 후 RUN_LAN_WINDOWS 재실행 |
| 여러 네트워크 어댑터 | 다른 PC에서 도달 가능한 사내망/VPN 어댑터 주소를 선택. Docker·가상 어댑터 주소를 무조건 선택하지 않기 |
| 방화벽 도구 실패 | 관리자 권한·회사 보안 정책 확인. Public 프로필은 열지 않음. 신뢰하는 회사 네트워크의 올바른 Domain/Private 분류는 IT 관리자와 확인 |
| VPN에서만 실패 | VPN이 서버의 사설 IP 대역을 라우팅하는지, 출발지 대역·회사 방화벽 정책이 허용하는지 IT 확인. 인터넷 포트포워딩으로 우회하지 않기 |
| 진단은 통과하지만 브라우저 실패 | 같은 HTTPS 주소인지 확인하고 회사 프록시/PAC·브라우저 인증서 정책을 IT에 확인. 진단 요청은 해당 사내 주소로 직접 연결 |
| 포트 사용 중 | 기존 YBY 서버를 정상 종료. 다른 프로그램을 임의 종료하지 않으며 포트를 몰래 변경하지 않음 |

## IP·인증서·운영 변경

서버는 가능하면 고정 IPv4 또는 DHCP 예약 주소를 사용하세요. IP가 바뀌면 기존 서버를 종료하고 RUN_LAN_WINDOWS를 다시 실행하여 새 IP를 선택한 뒤 LAN_CLIENT 폴더를 다시 전달합니다. 기존 CA가 유지되면 지문은 유지되며, 서버 인증서의 IP만 갱신합니다. 서버 인증서는 1년이며 RUN_LAN 실행 시 만료 30일 전부터 갱신합니다. 일반 RUN_WINDOWS가 만료 오류를 표시하면 RUN_LAN_WINDOWS로 갱신하세요.

Windows의 CA 개인키는 인증서를 만든 Windows 사용자의 인증서 저장소에 있고, 서버 인증서/키는 certificates 폴더에 있습니다. Linux에서는 CA 개인키도 이 폴더에 있으며 권한을 제한합니다. certificates는 실행 사용자·SYSTEM·관리자용 접근권한을 설정합니다. 설정과 인증서는 서버에서만 보호해 보관하며 별도 운영 백업이 필요합니다. 프로그램의 **업무 전체 백업 ZIP은 data 기준이며 lan_settings.json, certificates, Windows 인증서 저장소를 포함하지 않습니다.** 새 PC 이전·CA 교체 시에는 새 인증서 신뢰 설치가 필요할 수 있습니다. CA 유효기간은 5년이며 조직 CA로 교체하거나 만료 전에 갱신·재배포해야 합니다.

Linux 사내망 실행: `sh RUN_LAN_LINUX.sh --server-ip 실제IPv4 --no-browser`. Linux 최초 인증서 생성/갱신에는 OpenSSL 명령이 필요합니다. 자체 CA 도구 대신 사내 IT가 발급한 인증서를 V3_TLS_CERT/V3_TLS_KEY/V3_TLS_CA로 지정하는 기존 방식도 유지합니다.

## 검증 범위

클라우드에서 실제 사설 네트워크 인터페이스에 바인딩하여 HTTPS 상태 조회·로그인·보안 쿠키·인증서 검증·주소 불일치 거부·재시작·설정/비밀번호 보존을 확인했습니다. 일반 서버 테스트 95개와 브라우저 업무 회귀도 통과했습니다. 구체적인 결과는 VALIDATION_V4.md에 기록합니다.

실제 Windows PowerShell 인증서 생성·NTFS ACL·Windows 방화벽·클라이언트 루트 설치·Edge 및 고객 VPN/사내망은 이 Linux 환경에서 직접 실행하지 못했습니다. 해당 도구는 포함했지만 현장 검증 완료라고 주장하지 않습니다. 실제 업무 DB도 제공되지 않아 고객 자료를 사용한 이전은 별도 확인해야 합니다.
