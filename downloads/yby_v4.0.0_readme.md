# 법인카드·하이패스 통합관리시스템 V4.0.0

첨부된 V3.9.8과 정밀분석보고서를 기준으로 수정한 전체 배포본입니다. 프로그램, 화면, 로컬 라이브러리, 회귀 테스트, 백업·복원 도구를 포함합니다. Python 3.11 이상이 필요하며 EXE 파일은 아닙니다. 일반 실행에는 추가 pip 패키지나 인터넷 연결이 필요하지 않습니다.

## 실행

1. ZIP을 **새 폴더에 전체 압축 해제**하세요. ZIP 내부에서 바로 실행하지 마세요.
2. Windows: **RUN_WINDOWS.bat** 더블클릭. Python 설치 시 Add Python to PATH를 선택하세요.
3. Linux: 터미널에서 `sh RUN_LINUX.sh` 실행. 브라우저가 없는 서버는 `sh RUN_LINUX.sh --no-browser`를 사용하세요.
4. 서버 확인 후 브라우저가 열립니다. 새 설치의 계정별 임시 비밀번호는 최초 실행 창에서만 확인할 수 있으며 첫 로그인 후 변경해야 합니다.
5. 실행 창을 열어 두세요. 정상 종료는 Ctrl+C입니다. Windows의 STOP_V3.bat 또는 `python stop_server.py`는 이 폴더의 정확한 app.py 프로세스만 확인해서 종료합니다.

기본은 서버 PC의 로컬 HTTP, 127.0.0.1:5000입니다. 포트가 다른 프로그램에서 사용 중이면 임의 포트로 바꾸지 않습니다. 종료 직후 약 1분의 포트 해제 대기가 발생할 수 있습니다. START_V3 계열의 기존 실행 파일도 같은 V4 시작 정책을 사용합니다.

## V3.9.8 업무 자료 이전

1. 기존 서버를 종료하고 **기존 프로그램 폴더 전체**를 안전한 별도 위치에 백업하세요.
2. V4 ZIP은 새 폴더에 압축 해제하세요. 기존 운영 폴더에 덮어쓰지 마세요.
3. 기존 **data 폴더 전체**를 V4의 data 폴더로 복사하세요. corporate_card_system.db, attachments, 기존 password_display.key를 함께 보존하세요.
4. V4를 실행하면 정상 구형 스키마를 이전합니다. 이전 전 DB와 첨부·기존 키를 포함한 `backups/*_before_upgrade.zip`을 먼저 생성합니다. 백업이 실패하면 이전을 진행하지 않습니다.
5. 계정 로그인, 카드·불출·정산·첨부·기안 자료를 실제 자료로 확인하세요. 공급받은 ZIP에는 고객의 업무 DB가 없어 실제 업무 자료 이전 결과까지 검증한 것은 아닙니다.

DB 무결성 오류는 원본을 삭제하거나 새 빈 DB로 바꾸지 않고 실행을 중단합니다. 권한·저장 공간·손상 상태를 확인하고 전체 백업으로 복원하세요. V4 처리 후의 DB를 이전 프로그램에 그대로 넣지 마세요. 이전 버전으로 돌아갈 때는 **이전 프로그램과 이전 전 백업 DB·첨부·키를 함께** 복원해야 합니다. 실제 업무 자료로 최종 이전을 확인하기 전에는 기존 운영본과 원본 백업을 보관하세요.

## 기능과 달라진 동작

- 카드 등록의 ID와 지점, 불출·반납 이력을 서버에서 생성합니다. 상태·날짜·중복 번호·필수 항목을 검사합니다. 불출 중 카드 삭제는 차단합니다.
- 사용 반납은 카드 반납·이력·정산을 하나의 DB 트랜잭션으로 저장합니다. 잘못된 입력이나 DB 실패면 전부 롤백합니다.
- 요청 ID를 저장해 같은 업무 재시도에서 중복 정산을 방지합니다. 동시 불출에는 한 요청만 성공합니다.
- 정산 금액·필수 항목·등록 카드·지점·신청자·첨부 소유자를 서버에서 확인합니다. 브라우저 상태를 직접 전송하는 경로도 우회할 수 없습니다.
- 정산 승인·반려는 전용 API로 처리하고 본인의 지출은 다른 관리자가 승인해야 합니다.
- 승인 취소·정정은 관리자 재인증과 사유가 필요합니다. 원 승인 자료를 보존하고 **오늘 날짜의 반대 금액 승인 기록**을 추가합니다. 기간별 통계에는 각각의 날짜에 반영됩니다. 카드사 환불이나 ERP 전표를 자동 처리하는 기능은 아닙니다.
- 기안 작성자·지점·시각을 서버에서 확정합니다. 선택적인 1차 검토 → 최종 승인과 반려, 지정 결재자·단계·사유·시각 기록을 지원합니다. 본인 문서는 스스로 승인할 수 없습니다.
- 추가 ALL 관리자 계정을 화면에서 생성할 수 있습니다. ALL 권한 부여에는 현재 관리자 재인증이 필요합니다. ALL은 전 지점 관리자이며 개별 화면 체크박스로 권한을 줄이는 역할이 아닙니다.
- **비밀번호 원문을 저장·조회하지 않습니다.** 기존 인증 해시와 로그인은 유지합니다. 이전의 표시용 암호문은 이전 전 백업에 보존한 뒤 활성 DB에서 제거하며 변경 시각·수정자만 유지합니다. 관리자는 임시 비밀번호 재설정과 최초 변경 요구를 사용할 수 있습니다.
- 이전의 카드 KEY는 API에 반환하지 않으며 새 인증 비밀값 입력을 지원하지 않습니다. 기존 자료는 이전 전 백업과 내부 DB에 보존합니다. 카드 목록은 숫자 카드번호를 끝 네 자리로 표시하며 업무 선택·등록·정산 내보내기의 필요한 번호는 권한에 따라 사용합니다.
- 관리자도 참여하지 않은 개인 대화 내용을 조회하지 않습니다. 메모는 작성자별로 구분합니다.
- 대시보드 권한만 가진 사용자는 지점 요약 수치를 보고, 상세 업무 자료에는 별도 권한이 필요합니다.
- 엑셀 내보내기는 실제 **.xlsx** 파일입니다. 금액은 숫자 셀, 수식처럼 보이는 입력은 텍스트 셀로 저장합니다. 현재 화면의 표를 내보내는 기능이며 서버의 결재 자료와 별개인 사용자 출력 파일입니다. 최대 10,000행·50열입니다.
- 저장 성공 뒤에만 성공 안내·입력 초기화가 일어납니다. 실패 시 입력을 유지합니다. 관련 자료가 바뀌면 새로고침 후 다시 시도하도록 안내합니다.

## 권한과 세션

사용자별 계정을 사용하세요. 지점·업무 권한은 서버에서 확인합니다. 기본 유휴 만료는 사용자 활동 기준 15분, 절대 만료는 8시간이며 계정별 최대 5개 세션을 허용합니다. 자동 자료 조회만으로 유휴 시간을 연장하지 않습니다. 필요 시 `V4_SESSION_IDLE_SECONDS`, `V4_SESSION_ABSOLUTE_SECONDS`를 설정할 수 있습니다.

로그인 화면은 계정 선택을 위해 계정명을 제공합니다. 미로그인 API에는 지점·권한 목록을 제공하지 않습니다. 조직 정책상 계정명조차 비공개여야 한다면 로그인 방식의 추가 변경이 필요합니다. 메신저 화면 가림은 화면 보호 기능이며 로그인 종료·암호화 저장을 대신하지 않습니다.

## 여러 PC에서 사용 / HTTPS

공유 인터페이스 실행에는 TLS 인증서와 키가 필요하며 기본 HTTP를 사내망에 그대로 공개하지 않습니다. 서버와 실제 접속 이름/IP의 SAN을 포함한 인증서를 준비하세요. 런처는 localhost로 검증하므로 localhost SAN도 필요합니다.

Windows 명령 프롬프트 예시:

```bat
set V3_HOST=0.0.0.0
set V3_TLS_CERT=C:\certificates\server-chain.pem
set V3_TLS_KEY=C:\certificates\server-key.pem
set V3_TLS_CA=C:\certificates\company-root-ca.pem
RUN_WINDOWS.bat
```

기본 5000 포트의 Windows 사설망 규칙은 OPEN_FIREWALL_PRIVATE.bat를 관리자 권한으로 실행하여 설정할 수 있습니다. 이 도구는 로컬 서브넷과 5000 포트만 허용하며, 포트를 바꾼 경우 실제 포트에 맞는 별도 규칙을 설정하세요.

다른 PC는 실제 서버 이름/IP의 HTTPS 주소와 설정 포트로 접속합니다. 사내 CA를 클라이언트 PC에서 신뢰해야 합니다. 시스템이 CA를 신뢰하면 V3_TLS_CA는 생략할 수 있습니다. 인증서 검증을 끄는 방법은 지원하지 않습니다. 실제 인증서·방화벽·다른 PC 접속은 해당 업무 환경에서 검증해야 합니다.

## 전체 백업과 복원

관리자 화면에서 **전체 백업 만들기**를 누르고 현재 비밀번호로 재인증하면 전체 ZIP을 다운로드할 수 있습니다. 다운로드 승인은 60초·1회이며 생성자의 세션에 연결됩니다. DB·첨부파일·기존 키·버전·파일별 SHA-256을 포함합니다. 자동 백업도 같은 ZIP 형식이며 일반 변경의 자동 백업은 최대 5분에 한 번 생성합니다. 이전 전·수동 백업은 별도로 생성합니다.

서버를 종료한 후 CLI로 사용할 수도 있습니다.

```sh
python backup_tool.py create full_backup.zip
python backup_tool.py verify full_backup.zip
python backup_tool.py restore full_backup.zip
```

restore는 경로·파일 목록·체크섬·DB 무결성을 검증하고, 기존 data를 `data_before_restore_...` 폴더로 **보존한 뒤** 복원합니다. 검증 실패 시 기존 자료는 바꾸지 않습니다. 별도 작업 폴더에는 `--data-dir 경로`를 사용할 수 있습니다. 체크섬은 파일 일치 확인이며 발행자 서명을 의미하지 않습니다. 신뢰하는 백업만 사용하세요.

백업은 같은 PC에만 두지 말고 접근을 제한한 별도 저장 장치에도 보관하세요. 백업에는 인증 해시와 업무 자료, 이전 키 등이 있으므로 일반 문서처럼 공유하지 마세요. 자동 백업 파일을 무조건 삭제하지 않으며 저장 공간과 보존 정책은 운영자가 관리해야 합니다. 실제 새 PC에서 복원 훈련을 수행하세요.

미사용 첨부 정리 도구는 기본적으로 삭제 없이 대상 목록만 표시합니다. 서버 종료 후 사용하세요.

```sh
python attachment_cleanup.py
python attachment_cleanup.py --apply
```

최소 7일 이상 지난, 상태 데이터 어디에도 참조되지 않는 첨부만 대상이며 --apply도 전체 백업 후 정리합니다. 첨부는 파일당 20MB, 전체 저장 용량 2GB 제한입니다.

## 운영과 오류 확인

- 핵심 DB 저장과 보조 latest_state.json 기록을 분리했습니다. 보조 파일 실패는 핵심 저장 실패로 표시하지 않고 운영 경고로 남깁니다.
- 관리자 화면의 **백업·운영 상태**, **업무 감사 검색**에서 경고·백업·실제 업무 변경 이력을 확인할 수 있습니다.
- 운영 로그는 logs/server.log이며 최대 2MiB, 회전본 5개입니다. 최초 임시 비밀번호는 운영 로그에 기록하지 않고 실행 창에만 표시합니다.
- 요청 처리 작업자는 최대 16개, 대기 포함 연결은 32개이며 본문 읽기 시간 제한과 크기 제한을 적용합니다. 이는 외부 공개 서비스의 모든 보안·가용성을 보증하는 의미가 아닙니다.
- 목록 검색·페이지 API `/api/records`와 변경 없는 상태의 가벼운 응답을 지원합니다. 기존 화면은 호환 상태 API를 사용하므로 전체 목록의 화면 페이지 처리와 장시간 운영은 추가 평가가 필요합니다.
- 동일 자료 폴더의 서버·오프라인 복원·정리 작업은 OS 파일 잠금으로 중복 실행을 차단합니다. 활성 runtime.lock 파일을 수동 삭제하지 마세요. 서버 PC가 종료·절전되면 서비스도 중단됩니다. 별도 자동 재시작 서비스와 관제는 이 배포에 설치하지 않았습니다.
- Linux 파일 접근은 제한 모드로 생성합니다. Windows에서는 관리자가 데이터·백업·로그 폴더의 NTFS 접근권한을 설정하세요.

## 검증

```sh
python -m unittest discover -s tests -v
python tests/tls_smoke.py
python tests/load_smoke.py
```

브라우저 검증에는 Playwright와 Chromium이 추가로 필요합니다. 일반 실행에는 필요하지 않습니다.

```sh
python -m pip install -r requirements-dev.txt
python tests/browser_smoke.py
python tests/browser_v4.py
```

Linux 기본 Chromium 경로는 /usr/bin/chromium이며 다른 경로는 V3_TEST_CHROMIUM에 지정하세요. CI 설정 예시는 .github/workflows/validate.yml에 포함했습니다. 실제 CI 및 Windows 테스트가 실행 완료됐다고 가정하지 마세요.

검증 결과와 미검증 항목은 VALIDATION_V4.md, 분석보고서 항목별 구현 상태는 IMPLEMENTATION_MATRIX.md에 있습니다. docs/legacy의 이전 문서·코드는 참고 기록이며 V4 실행·보안 안내를 대신하지 않습니다.

## 이번 배포에 포함하지 않는 외부 연동

카드사·은행·ERP 실제 연동, SSO/MFA, 악성 첨부 검사 서비스, 회사 마감·대리결재 정책, 외부 인터넷 서비스 관제, 실제 Windows/Edge·Excel·사내망·고객 업무 DB 검증은 별도 자료와 환경이 필요합니다. 이 기능들이 이미 작동한다고 표시하지 않았습니다. 세부 관계형 스키마 고도화, 전체 UI 페이지 처리와 접근성 표준 인증도 향후 보완 대상입니다.
