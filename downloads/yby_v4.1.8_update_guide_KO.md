# YBY V4.1.8 사용·업데이트 안내

2026년 10월 19일 · V4.1.7 이후 개선 전체 패키지

## 화면·메뉴

- 상위 메뉴 6개(메인 대시보드 / 법인카드 관리 / 하이패스 카드 관리 / 정산 및 통계 / 내부보고서 관리 / 시스템 관리)의 아이콘은 유지했습니다.
- 하위 메뉴·업무 화면 제목·일반 제목·정산 관련 창 제목의 장식 아이콘은 없앴습니다. 첨부·알림·인쇄 등 기능 버튼과 업무 상태 표시는 유지했습니다.
- ‘카드 현황 및 대여’를 **‘지역별 배부현황 및 대여현황’**으로 바꿨습니다. 화면 접근 권한과 카드 배부·대여 기능은 같습니다.
- V4.1.7의 차분한 남색·회색 글자 톤과 ‘사용 정산 및 결재 → 사용정산 이력대장’ 메뉴 순서를 유지했습니다.

## 불출/반납 이력대장

- 최신 처리 일시부터 표시합니다. 같은 처리 시각이면 큰 이력 ID부터 표시합니다. 한국 시간으로 저장된 구형 일시와 UTC 서버 일시를 비교하며, 일시 없는 자료는 아래에 표시합니다.
- 엑셀과 이력 인쇄도 현재 조회 조건에 맞는 최신순입니다.
- 사용자 아래에 **누적 불출 N회**를 표시합니다. 같은 지점·같은 사용자명의 전체 보유 불출 이력을 기준으로 하므로 현재 날짜·구분 필터로 목록을 좁혀도 누적 횟수는 바뀌지 않습니다. 여러 카드의 불출을 합산합니다. 다른 지점의 같은 이름은 합치지 않습니다.
- 기존 자료에 직원 고유번호가 없으므로 **같은 지점의 동명이인은 사용자명만으로 구분할 수 없습니다.** 사용자명을 구분해 입력하면 별도 집계됩니다. 이름이 없는 과거 자료는 ‘불출 횟수 확인 필요’로 표시합니다.
- 불출 건마다 **대여중·반납대기 / 반납완료·미사용 / 반납완료·승인대기 / 반납완료·재보고대기 / 반납완료·반려됨 / 반납완료·승인완료** 등을 보여줍니다. 반납 행에서도 해당 회차 상태를 확인할 수 있습니다.
- 새 불출·반납·정산은 연결 정보를 서버가 같은 업무 저장 과정에서 생성합니다. 동일 카드의 다른 회차를 혼동하지 않고 승인취소 후 재보고·재승인된 상태도 따라갑니다.
- 과거 자료에 정산 연결 정보가 없으면 ‘반납완료·정산 이력 확인’으로 표시합니다. 불출·반납 이력이 누락되거나 모호하면 ‘반납 연결 확인 필요’입니다. 날짜나 사용자명이 비슷하다는 이유로 정산을 임의 연결하지 않습니다. 기존 이력을 지우거나 바꾸지 않습니다.

## 사용정산 이력대장의 지표

조회 목록 위에 다음 항목을 표시하며 검색어·지점·사용자·기간·구분·결재 상태를 바꾸면 함께 갱신됩니다.

| 항목 | 계산 기준 |
|---|---|
| 조회 이력 | 현재 목록에 포함된 전체 문서 건수 |
| 유효 승인 정산 | 승인완료 중 취소·교체되지 않은 정산 문서 건수 |
| 승인 사용 횟수 | 유효 승인 문서에 들어 있는 건별 명세 수. 수량 2인 명세도 사용 1회 |
| 승인 사용금액 | 유효 승인 문서의 건별 금액 합계 |
| 반려 이력 | 현재 조회 목록의 반려 문서 건수 |
| 승인취소 이력 | 현재 조회 목록의 승인취소 문서 건수 |

아래에는 **정산 구분별 승인 문서 수·사용 횟수·사용금액**을 표시합니다. 한 문서에 식대와 교통비가 있으면 각 구분에 해당 명세를 나누어 집계합니다. 구분별 문서 수에는 같은 문서가 여러 구분에 포함될 수 있지만 사용 횟수와 금액은 건별로 한 번씩만 합산합니다.

- 명세 없이 저장된 구형 정산은 문서 1건을 사용 1회로 계산합니다.
- 반려·승인취소, 교체된 이전 원본, 예전 버전의 마이너스 차감 정정은 승인 사용금액에서 제외합니다. 원본 이력 자체는 목록과 보고서 상세에 남습니다.
- 기존 조회 조건은 **문서 단위**입니다. 예를 들어 복수 날짜·구분의 명세가 있는 문서는 조회에 포함되면 그 문서의 전체 명세를 집계합니다. 화면과 보고서에 이 기준을 함께 표시했습니다.
- 건별 금액과 문서 합계가 맞지 않거나 금액 형식에 문제가 있으면 ‘확인 필요’를 표시하여 부정확한 합계로 오인하지 않게 했습니다.

## 조회 요약 보고서 열기

1. 사용정산 이력대장에서 원하는 조건을 선택합니다.
2. **‘조회 요약 보고서’**를 누릅니다.
3. 별도 보고서 창 영역에서 조회 범위·조건·기준 시각, 지표, 정산 구분별 사용 현황, 결재 상태별 건수, 조회 이력 상세를 확인합니다.
4. **‘보고서 인쇄 / PDF 저장’**을 눌러 프린터 또는 브라우저의 PDF 저장을 선택합니다.

보고서는 버튼을 누른 시점의 결과입니다. 그 후 다른 사용자가 승인·정정을 처리했다면 보고서를 닫았다가 다시 열어 최신 결과를 확인하세요. 승인취소 음영을 출력하려면 인쇄 옵션의 ‘배경 그래픽’을 켜세요. 기존 명세 엑셀·상세 이력 PDF/인쇄도 계속 사용할 수 있습니다.

## 기존 서버 PC 업데이트

1. 현재 버전의 ‘전체 백업 만들기’로 DB·첨부 등을 백업하고 보관합니다.
2. 사용자들이 저장·로그아웃한 후 기존 서버 검은 실행창에서 **Ctrl+C**로 서버를 종료합니다. 로그인창만 닫으면 서버는 계속 실행됩니다.
3. `yby_v4.1.8_full.zip`을 새 폴더에 **전체 압축 해제**합니다. ZIP 안에서 바로 실행하지 마세요.
4. 기존 서버를 실행하던 **동일한 Windows 계정**으로 새 폴더의 `RUN_LAN_WINDOWS.bat`을 실행합니다.
5. 서버 창의 **READY V4.1.8**과 업무 화면 상단의 **V4.1.8**을 확인합니다. 서버 실행창은 유지하세요.
6. 다른 PC는 로그인창을 닫고 ‘YBY 로그인’으로 다시 엽니다. 일반 브라우저는 새로고침하세요.

실제 실행 위치 `%LOCALAPPDATA%\YBY\app`의 프로그램만 업데이트하는 방식입니다. 기존 업무 DB·계정·비밀번호·첨부·인증서 설정은 유지합니다. `data`·`certificates`·잠금 파일을 삭제하거나 새 배포 폴더의 것으로 수동 덮어쓰지 마세요. 실행 중인 구버전 서버가 남아 있으면 기존 서버로 재접속하므로 업데이트되지 않습니다.

기존 다른 PC의 인증서 재설치는 일반적으로 필요하지 않습니다. 새 PC에는 서버 `OPEN_LAN_CLIENT.bat`에서 찾은 `LAN_CLIENT.zip`만 전달해 압축 해제 후 `INSTALL_AND_CONNECT.bat`을 실행합니다. 업무 DB와 서버 개인키는 전달하지 않습니다.

## 검증·개발 참고

검사 결과와 실제 Windows 확인 범위는 `VALIDATION_V4_1_8.md`에 기록합니다. 이 버전은 기존 SQLite 자료 구조를 유지하며, 새 연결 정보는 기존 레코드에 추가 저장합니다. Oracle 연동 구현은 포함하지 않습니다.

개발 검사는 Python 자동검사와 실제 Chromium 브라우저 검사를 사용합니다. 순수 집계 모듈 검사는 개발 환경에서 `node --test tests/ledger_v418.test.cjs`로 실행할 수 있습니다. 실제 프로그램 실행에는 Node.js가 필요하지 않습니다.
