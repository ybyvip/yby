# V4.1.3 실행 오류 수정 및 적용 방법

2026-10-17. V4.1.2의 정산 화면 개선을 유지하고 Windows PowerShell 실행 오류를 수정한 전체 패키지입니다.

## 원인

READY V4.1.2, LAN HTTPS 확인 완료까지 표시되므로 서버 자체와 업무 DB는 실행 중이었습니다. 그 다음 client_connect.ps1에서 발생한 Unexpected token, Missing closing }, 문자열 종결자 누락은 인증서 등록·로그인창 열기 스크립트의 한글 인코딩 문제입니다.

V4.1.1에는 있던 UTF-8 BOM 표시가 V4.1.2 제작 과정에서 빠졌습니다. Windows PowerShell 5.1은 BOM 없는 파일을 시스템 ANSI 문자셋으로 읽을 수 있어 한글이 깨지고 파서 오류가 발생할 수 있습니다. 콘솔의 chcp 65001이나 출력 인코딩만 바꿔서는 원본 스크립트를 읽는 문제를 해결하지 못합니다.

## 수정 내용

- PowerShell 파일 4개 모두 UTF-8 BOM으로 복구했습니다. client_connect.ps1뿐 아니라 방화벽 설정 도구 등도 함께 확인했습니다.
- 원본 패키지 → 실제 AppData 실행폴더 → LAN_CLIENT 폴더 → LAN_CLIENT.zip 전달 과정에서 원본 바이트를 보존합니다.
- 무결성 목록을 수정한 파일에 맞춰 재생성했습니다. 인코딩이 잘못된 스크립트는 파일 해시가 맞더라도 설치 전에 차단합니다.
- Windows 실행 시 실제 Windows PowerShell Parser.ParseFile로 배포 스크립트의 구문을 먼저 확인합니다. 오류가 있으면 프로그램 파일을 교체하지 않습니다.
- V4.1.2의 반납·재보고 공통 양식, 작성창에 맞춘 건별 명세, 승인취소 음영과 날짜 배치를 유지합니다.

## 현재 바로 접속해 보기

기존 화면에 READY와 LAN HTTPS 확인 완료가 있다면 실행창을 유지하고 서버 PC 브라우저 주소창에 `https://localhost:5000/`을 입력하세요. 인증서가 이미 등록되어 있다면 로그인할 수 있습니다. 인증서 오류가 있으면 경고를 우회하지 말고 아래 수정본을 적용하세요.

## 서버 PC 적용 — 이 순서로 진행하세요

1. 기존 프로그램에 접속 가능하면 전체 데이터 백업을 보관하세요.
2. 현재 READY가 표시된 서버 창에서 Ctrl+C로 정상 종료하세요. 실행 중인 서버를 둔 채 새 버전을 실행하면 기존 서버로 재접속하므로 수정 파일이 설치되지 않습니다. 창을 찾기 어려우면 새 패키지의 STOP_SERVER.bat를 사용할 수 있습니다.
3. 새 ZIP을 새 폴더에 전체 압축 해제하세요. 기존 `%LOCALAPPDATA%\YBY\app` 안에 압축을 풀지 마세요.
4. 기존 서버를 사용하던 동일 Windows 계정에서 새 폴더의 RUN_LAN_WINDOWS.bat를 일반 더블클릭하세요.
5. `[시작 확인] Windows PowerShell 구문 검사` 다음으로 파일 준비, 서버 시작이 진행됩니다. `READY V4.1.3`을 확인하세요.
6. 인증서가 이미 등록되어 있으면 확인 후 로그인창이 열립니다. 최초 등록 질문이 나오면 서버의 CA SHA-256과 비교하여 같은 인증서인지 확인한 뒤 등록하세요.
7. 로그인창이 자동으로 열리지 않으면 새 폴더의 CONNECT_SERVER.bat를 실행하고 오류 출력을 확인하세요. 서버가 실행 중인 상태에서 VERIFY_WINDOWS.bat로 실제 Windows 환경을 확인할 수 있습니다.

업무 DB·계정·비밀번호·첨부·기존 CA/서버 인증서·LAN 설정을 유지합니다. data나 certificates를 삭제할 필요가 없습니다. 현재 반영된 정산 화면 개선도 유지됩니다. DB 스키마 변경은 없습니다.

## 다른 PC

서버 업데이트 후 OPEN_LAN_CLIENT.bat로 새 LAN_CLIENT.zip을 열어 다른 PC에 전달하세요. 다른 PC에서는 새 ZIP을 전체 압축 해제하고 INSTALL_AND_CONNECT.bat를 일반 실행합니다. 기존 바탕화면 로그인 바로가기의 연결 도구도 새 파일로 갱신됩니다. 기존과 같은 CA라면 인증서 재등록 질문은 반복되지 않습니다.

## 검증 범위

자동검사와 ZIP/파일 인코딩 검사, 공개 접속 ZIP의 바이트 보존 및 임시 실행폴더 업데이트를 확인했습니다. Linux에서 실제 HTTPS 서버와 Chromium 접속을 확인하지만 이 환경에서 Windows PowerShell 5.1을 직접 실행한 결과는 아닙니다. Windows 실행 전 실제 구문 검사와 VERIFY_WINDOWS.bat는 해당 PC에서 확인하기 위한 절차입니다.
