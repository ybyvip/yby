# V4.0.2 권한 오류 대응 검증

2026년 10월 15일(한국 시간). 사용자 화면의 Permission denied에는 단계/경로가 없어 정확한 실패 파일은 확정할 수 없었습니다. 바탕화면·문서·다운로드·OneDrive 실행으로 확인되어 사용자 전용 실행 경로를 도입하고 Windows 파일 잠금·오류 진단을 보완했습니다. 오류가 반드시 특정 폴더 보호 정책 때문이었다고 단정하지 않습니다.

- 서버 회귀 105개 실행·105개 통과. 이전 95개와 시작/자료 이전/충돌 방지/진단 검증 10개입니다.
- 읽기 전용 한글 경로의 원본에서 사용자 실행 폴더로 복사, 실제 서버 시작·로그인·업무 저장, 반복 준비 후 실제 자료 유지, 원본 DB SHA-256 불변을 확인합니다.
- 다른 DB 덮어쓰기 차단, 변경된 원본 패키지 거부, 기존 프로그램 코드 보존, 실행 중 프로그램 갱신 차단, 예외 시 OS 잠금 해제, 정확한 잠금 파일 경로와 진단 기록을 확인합니다.
- 실제 RFC1918 인터페이스 HTTPS, 로그인·인증서 검증·불일치 거부, 저장된 사내망 설정·동일 포트 재시작과 비밀번호/인증서 유지 검사를 수행합니다.
- 최종 배포 ZIP을 새 폴더에 풀어 CRC·모든 manifest 파일 해시, 실행·업무 처리·백업·재시작, 105개 테스트와 읽기 전용 원본 이전·사내망 TLS 흐름을 재확인합니다. 실제 배포 검증 JSON은 해당 ZIP SHA-256과 결과를 기록합니다.

검증은 Linux 클라우드의 임시 DB/인증서/테스트 계정으로 수행합니다. 실제 Windows의 CreateFileW/LockFileEx·PowerShell/CSP·NTFS·Defender·OneDrive·Edge·방화벽, 고객의 실제 업무 DB 및 VPN은 직접 실행하지 못했습니다. Windows 실행 완료 또는 고객의 동일 오류 재현 완료라고 주장하지 않습니다. 시작 오류가 남으면 단계·경로·Windows 오류 코드가 담긴 진단 파일로 현장 원인을 확인할 수 있도록 했습니다. 실제 고객 DB·개인키·기기 설정·잠금/로그 파일은 배포에 넣지 않습니다.
