# V4.0.2 Windows 권한 오류 수정 안내

화면의 `[Errno 13] Permission denied`는 파일 접근 또는 잠금 권한 오류입니다. V4.0.1은 실패 단계와 경로를 표시하지 않아 화면만으로 어느 파일인지 확정할 수 없었습니다. 바탕화면·문서·다운로드·OneDrive에서 실행할 때의 쓰기 제한과 Windows 잠금 처리를 보완했습니다.

## 바로 실행하기

1. 기존 서버를 종료하고 기존 프로그램 폴더 전체를 백업합니다.
2. 새 ZIP을 새 폴더에 **전체 압축 해제**합니다. ZIP 안에서 BAT만 실행하지 않습니다.
3. 기존 자료를 계속 쓰려면 **첫 실행 전에** 기존 `data` 폴더 전체를 새 패키지의 `data`에 복사합니다. DB·첨부·기존 키를 함께 보존합니다.
4. **RUN_LAN_WINDOWS.bat**를 평소 Windows 사용자 계정으로 실행합니다. 이 실행 파일은 관리자 권한으로 실행하지 않습니다.
5. 프로그램은 `%LOCALAPPDATA%\YBY\app`에 실행 파일과 자료를 준비합니다. 화면에 실제 경로를 표시합니다. 기본 위치는 `C:\Users\사용자명\AppData\Local\YBY\app`입니다.
6. **OPEN_RUN_FOLDER.bat**를 실행하면 실제 실행 폴더가 열립니다. 그곳의 **LAN_CLIENT** 폴더만 접속할 다른 PC에 전달합니다.
7. 실제 실행 폴더의 **SETUP_SERVER_FIREWALL.bat**만 관리자 권한으로 실행합니다. 다른 관리자 계정으로 권한을 올리는 경우에도 실제 실행 폴더 안의 도구를 실행해야 합니다.

프로그램은 기존 계정·비밀번호·업무 자료를 유지합니다. 최초 가져온 원본 DB를 이후 매번 덮어쓰지 않습니다. 기존 사용자 실행 폴더와 새로 넣은 DB가 서로 다르면 자료 손실을 막기 위해 중단하고 경로를 안내합니다. 경고가 나오면 어느 자료를 사용할지 확인하기 전 폴더를 삭제하지 마세요.

**실제 사용 자료는 이제 사용자 실행 폴더의 data에 있습니다.** 다운로드/압축 해제한 폴더의 data는 최초 가져오기용 원본입니다. 이후 자료 이전·수동 백업·CLI 작업은 OPEN_RUN_FOLDER로 연 실제 실행 폴더를 기준으로 합니다. 화면의 전체 백업 기능도 실제 자료를 백업합니다. 프로그램 파일 갱신 시 바뀐 기존 코드는 program_backups에 보존하고 업무 자료와 인증서를 유지합니다.

## 무엇을 수정했나요?

- 다운로드 폴더에 실행 중 DB·설정·인증서·잠금 파일을 직접 생성하는 대신 사용자 전용 실행 폴더에서 운영합니다.
- 사용자 실행 폴더에서 파일 생성·쓰기·이름 변경이 가능한지 먼저 검사합니다.
- Windows 파일 잠금을 버퍼/파일 위치에 영향을 받는 CRT msvcrt.locking에서 Windows CreateFileW/LockFileEx 핸들 방식으로 변경했습니다. 프로세스가 종료되거나 핸들을 닫으면 잠금을 해제합니다. 중복 서버 실행 방지는 유지합니다.
- 읽기 전용 원본 자료는 원본을 보존하며 복사하고, 복사한 자료의 쓰기 권한을 설정합니다.
- 다른 업무 DB 발견 시 덮어쓰기 차단, 실행 중 갱신 차단, 원본 파일 무결성 검사와 기존 프로그램 파일 보존을 추가했습니다.
- 시작 실패 시 단계·대상 경로·errno/winerror와 호출 위치를 표시하고 진단 파일을 저장합니다. 환경변수나 지역변수·비밀번호를 덤프하지 않습니다.
- 종료·관리자 초기화·네트워크 진단·방화벽 BAT가 실제 실행 폴더를 사용하도록 수정했습니다.

## 다시 오류가 나면

창의 **단계**, **대상 경로**, **오류 진단 파일** 경로를 확인하세요. 진단 파일은 보통 `%LOCALAPPDATA%\YBY\diagnostics\startup_error_*.txt`입니다. 이 파일을 전달하면 어느 작업이 막혔는지 확인할 수 있습니다. 회사 보안 정책이 사용자 실행 폴더 접근까지 차단하면 해당 경로와 진단 파일을 IT 담당자에게 전달하세요. 보안 프로그램을 끄거나 정책을 우회하지 않습니다.

인증서·방화벽·다른 PC의 HTTPS 접속은 README_LAN_KO.md를 따릅니다. Windows 원격 PC와 회사 VPN은 현장 검증이 필요합니다. Linux에서는 기존 실행 경로를 유지합니다.
