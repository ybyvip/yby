# YBY V4.1.13 업데이트·사용 안내

작성일: 2026-10-20 (한국시간) / 기준 버전: V4.1.12

## 1. 업데이트 방법 — 업무 자료 유지

1. 최고관리자로 로그인하여 **시스템 관리 → 권한 & 비밀번호 관리 → 전체 백업 만들기**를 실행하고 현재 로그인 비밀번호로 확인합니다. Ctrl+J에서 ZIP 다운로드가 완료됐는지 확인해 별도 보관합니다. 상단 ‘데이터 백업’ JSON과 구별하세요.
2. 다른 사용자가 작업하지 않는 시간에 기존 서버 실행창에서 **Ctrl+C**로 종료합니다. 실행 중인 상태에서 교체하지 마세요.
3. V4.1.13 전체 ZIP을 **새 폴더에 완전히 압축 해제**합니다. 기존 서버와 **같은 Windows 계정**으로 **RUN_LAN_WINDOWS.bat**를 실행합니다.
4. 실제 실행 위치 `%LOCALAPPDATA%\YBY\app`의 기존 계정·업무 DB·첨부·인증서·사내망 설정을 유지하며 프로그램을 갱신합니다. 정상 업데이트에는 백업 ZIP을 복원하거나 압축 해제할 필요가 없습니다.
5. 화면 상단 버전 **V4.1.13**과 기존 자료를 확인하세요. 브라우저에 이전 화면이 남으면 Ctrl+F5 또는 로그인 전용창을 닫고 **CONNECT_SERVER.bat**로 다시 여세요. 서버 실행창은 계속 열어 둡니다. 접속 주소는 `https://localhost:5000`(서버 PC), `https://10.10.0.121:5000`(기존 회사 서버 IP가 그대로인 경우 다른 PC)입니다.

DB 스키마는 6을 유지합니다. 이번 ZIP에는 회사 운영 DB·첨부·인증서 개인키가 들어 있지 않습니다. 전체 백업에는 업무 DB/첨부 등이 들어가지만 TLS 인증서/개인키와 LAN 설정은 포함되지 않으므로 서버 PC 이동은 별도 준비가 필요합니다.

## 2. 지역별 배부·사용현황

- 법인카드의 지역별 현황과 같은 지점별 **펼치기/접기** 형식입니다. 지점을 누르면 사용자·차량과 한 묶음의 하이패스/유류대 정보를 볼 수 있습니다. Enter/Space로도 조작하며 자동 갱신 때 펼친 상태를 유지합니다.
- PC에서는 **등록 묶음 / 확인대기 / 불출중 / 회수중·완료 / 하이패스 카드 / 유류대카드** 여섯 지표를 한 줄에 배치합니다. 좁은 모바일에서는 읽기 쉽도록 줄을 바꿉니다.
- 모든 지표·지점 목록은 화면의 지점/분류/검색 조건을 따릅니다. 카드 수량과 불출/회수 집계는 **확인대기 제외**, 등록 묶음은 확인대기 포함입니다. 등록 묶음 수와 실제 카드 수량은 다를 수 있습니다.
- 현황 카드의 **상세 보기**로 입력 정보를 확인할 수 있습니다. 만료된 카드가 포함되면 별도 안내를 표시합니다.

## 3. 간결한 입력폼과 확인 후 이동

- 하이패스 관리와 수정 입력폼의 여백·높이를 줄이고 공통 정보, 하이패스, 유류대 정보를 일정한 간격으로 정렬했습니다. 등록·수정은 같은 구조를 사용합니다.
- **등록 · 미리보기** → 내용 검토 → **정보 확인 · 리스트 반영** 순서로 처리합니다.
- 등록 화면 하단에는 **확인대기 자료만** 남습니다. 확인된 자료는 즉시 이 목록에서 빠지고 **하이패스 리스트**로 이동합니다. 자료를 새로 복사하거나 이중 저장하는 것이 아니라 같은 묶음의 확인 상태를 바꿉니다.
- 창을 닫아 확인을 미뤘다면 등록 화면 하단의 **미리보기·확인**을 다시 누르세요.
- 기존 버전에 확인 상태가 없던 자료는 하이패스 리스트에 **기존자료 · 확인미기록**으로 계속 표시합니다.

## 4. 하이패스 리스트에서 수정·삭제

- 확인된 묶음의 **수정**을 누르면 하이패스/유류대 선택을 포함한 전체 입력창이 열립니다. 수정 사유와 **현재 로그인 계정 비밀번호**를 입력하여 저장합니다.
- 수정 후에는 **확인대기**가 되어 리스트에서 잠시 빠지고 등록 화면 하단으로 돌아갑니다. 바로 열린 미리보기에서 다시 확인하면 리스트에 반영됩니다. 확인 전 창을 닫았어도 등록 화면에서 이어서 확인할 수 있습니다.
- **삭제**도 삭제 사유와 현재 로그인 비밀번호가 필요합니다. 묶음 내 두 카드가 함께 삭제되며, 변경 이력·삭제 전 문서는 보존됩니다. 비밀번호를 업무 문서나 엑셀에 저장하지 않습니다.
- 하이패스 관리 권한이 있는 담당자는 자기 지점의 리스트도 열 수 있습니다. 리스트 조회 권한만 가진 담당자에게는 수정·삭제 버튼이 없으며 서버에서도 변경을 차단합니다. 다른 지점의 자료는 조회·수정·다운로드할 수 없습니다.

## 5. 배부 상태와 입력 확인 상태는 별도

입력폼의 **배부 상태**에서 실제 상황에 맞게 선택합니다.

| 배부 상태 | 의미 |
|---|---|
| 대기중 | 배부 대기·보관 상태 |
| 불출중 | 차량·사용자에게 배부하여 사용 중 |
| 회수중 | 회수 진행 중 |
| 회수완료 | 실제 회수를 마친 상태 |

- 새 등록 기본값은 **대기중**입니다. 배부한 카드라면 불출중으로 지정하세요. 상태 변경도 전체 수정과 동일하게 비밀번호/사유 및 재확인을 거칩니다.
- 회수완료에는 **실제 회수일**이 필요하며 오늘 이후 날짜로 완료 처리할 수 없습니다. 회수 진행 중에는 공통 ‘회수일 / 회수 예정일’에 예정일을 적을 수 있습니다.
- **확인대기/확인완료**는 입력 검토 여부입니다. 불출중인지 회수중인지와 구별됩니다. 상태 선택만으로 법인카드 불출·정산 결재를 새로 생성하지 않습니다.
- 기존 자료는 저장 내용을 임의로 바꾸지 않습니다. 배부 상태가 없으면 기존 회수일이 오늘 이전/당일이면 회수완료, 미래이면 회수예정, 그 외 확인대기면 대기중, 사용자 기록이 있으면 불출중으로 **표시만 추정**합니다. 실제와 다르면 수정 화면에서 명시적으로 지정하세요.

## 6. 등록·변경 이력과 문서

- 이력에 **당시 하이패스/유류대 카드번호**, 사용자/차량, 최초 등록일, 변경일, **현재 배부 상태**, 변경 사유/처리자와 문서 열람을 모았습니다.
- ‘현재 상태’는 최신 묶음 자료 기준이며 삭제된 자료는 삭제됨, 다른 지점으로 이관된 자료는 이관됨으로 구분합니다. 당시 카드번호와 현재 상태의 기준이 다름을 표시합니다.
- **변경 문서 열람**에는 문서번호·소속·묶음ID·처리자·최초등록/변경일·현재 상태·사유를 상단 표에 표시합니다. 아래는 **항목 / 변경 전 / 변경 후** 비교표이며 달라진 항목을 음영과 ‘변경’ 표시로 구분합니다. 인쇄/PDF 저장을 지원합니다.
- 과거 버전에 없던 날짜/변경 전 정보는 만들지 않고 미기록으로 표시합니다. 연결을 확인할 수 없는 과거 이력은 확인불가로 표시합니다.
- 엑셀도 현재 화면 조건을 반영합니다. 등록 엑셀은 확인대기만, 리스트 엑셀은 확인대기 제외, 현황 엑셀은 전체 조회 자료입니다. 이력 엑셀에는 최초 등록일시/변경일시/현재 배부상태를 추가했습니다. 변경 전·후 전체 비교는 문서/PDF를 이용하세요.

## 7. 대시보드·바로가기·정산 요약

- 종합 현황 대시보드에 **유류대카드 수량**을 추가했습니다. 클릭하면 지점·카드사·번호·사용자·차량·배부상태·확인상태를 상세 조회하고 보고서로 출력할 수 있습니다. 하이패스/유류대 대시보드 수량은 **확인대기 포함한 등록 카드 총수**이며 카드별 상세 조회 권한은 별도로 적용합니다.
- **바로가기 설정**에 현재 프로그램의 **전체 17개 화면**을 추가했습니다. 개수 제한 없이 선택합니다. 권한 없는 화면은 ‘권한 없음’으로 비활성화하고 권한이 바뀌면 바로가기에도 반영합니다. 저장 오류가 나면 설정창을 유지합니다.
- 사용정산 이력대장의 **현재 조회 결과 요약**은 글자·여백·표 높이를 줄이고 넓은 PC에서는 여섯 지표를 한 줄로 표시합니다. 인쇄/PDF 보고서의 지표와 계산 기준은 유지합니다.

## 8. 검증 범위

Python 서버 241개와 Node 이력 집계 12개를 통과했습니다. 실제 Chromium에서 등록/확인 후 목록 이동, 리스트 수정/재확인/삭제, 잘못된 비밀번호 차단, 변경 비교표/PDF/XLSX, 지점별 권한, 유류대 대시보드, 17개 바로가기와 저장 실패 처리, PC/모바일 화면을 확인했습니다. V4.1.12에서 기존 자료를 유지하는 업데이트·기동도 별도 확인합니다. 상세 결과는 동봉된 VALIDATION_V4_1_13.md를 참조하세요.

회사 Windows/Edge/WebView2·실제 인증서/방화벽·실제 Oracle 접속은 이 환경에서 실행하지 못하므로 회사 PC에서 최종 확인이 필요합니다. Oracle 연결 기능은 담당자 자료 대기 상태로 유지합니다.
