# YBY V4.1.21 전체 안정화 패키지

작성일: 2026-10-20 (한국시간). V4.1.20 기반, DB 스키마 9.

## 먼저 확인할 변경

- **기존 자료는 유지**합니다. 기존 실행 창에서 Ctrl+C로 종료하고 전체백업을 보관한 뒤, 새 ZIP을 새 폴더에 전체 압축 해제하여 RUN_LAN_WINDOWS.bat를 실행하세요. 실제 업무 자료는 기존 `%LOCALAPPDATA%\YBY\app\data`를 계속 사용합니다. 다운로드 폴더의 data로 덮어쓰지 마세요.
- **사용자 비밀번호 열람·복원 보관은 기본 꺼짐**입니다. 최고관리자는 초기화하고 사용자가 새 비밀번호로 변경하는 방식이 기본입니다. 이전 암호문은 자동 삭제하지 않습니다. 회사 정책에서 예외로 켠 경우에만 열람 기능이 동작하며, 신규 저장/로그인부터 캡처합니다.
- **관리자가 타인 비밀번호를 초기화하면 대상자의 기존 로그인은 종료**됩니다. 권한만 변경하면 로그인은 유지하며 권한은 즉시 적용됩니다. 회사 정책에서 초기화 시 세션 유지로 바꿀 수 있지만 침해 대응 시 강제 종료를 권고합니다.
- 최고관리자 자기 승인은 유지하되 기본적으로 **사유와 현재 비밀번호 재확인**이 필요합니다. 회사 정책에서 자기 승인을 금지하거나 재확인 정책을 선택할 수 있습니다. 자기 승인 기록은 업무 점검에 표시됩니다.
- 신규 설치는 admin만 기본 생성합니다. 기존 설치의 계정은 삭제하지 않습니다. 필요한 지점 계정은 권한 관리에서 생성하세요.

## 추가된 화면과 기능

1. **정산 및 통계 → 업무 점검 및 대사**: 조회월·지점별 YBY 승인/과거 이관/미기재/0원/미사용/승인취소를 구분합니다. 현재 미반납·정산 대기·재보고·만료 임박·하이패스 회수·자기 결재·보고 원본 변경을 모아 확인합니다. 실제 카드사·회계 명세를 대조한 문서명과 결과를 기록하고, 자료 변경 후에는 재점검 필요로 표시합니다. Excel/PDF를 출력합니다. 회계 마감이나 자동 카드사 대사 기능은 아닙니다.
2. **시스템 관리 → 회사 정책·지점 관리**: 지점 마스터, 비밀번호 표시, 자기 승인, 관리자 초기화 세션, 로그인 전 계정 목록 공개를 사유·재인증과 함께 관리합니다. 광주가 기본 목록에 포함되며 다른 지점도 추가할 수 있습니다. 계정·업무·외부 수신에서 사용 중인 지점은 삭제할 수 없습니다. 이름 변경은 자료 이동이 아닙니다.
3. **시스템 관리 → 백업·복구 관리**: 최근 로컬/별도 보관 성공, 실패·공간 경고, 파일 목록, 백업 보존/예약/암호화 별도 보관, 운영 자료를 교체하지 않는 시험 복원을 제공합니다.
4. **하이패스·유류대**: 불출 확정·최종 회수 시 대상자 및 선택한 실물 카드 각각을 확인합니다. 확인자·시각·체크 결과를 변경 이력에 보존합니다. 이미 불출한 실물 카드는 회수완료 전 삭제를 차단합니다. 묶음 수와 카드 수는 구별합니다.
5. **보고서**: 정산 복사본에 원본 지문을 연결하고 새 화면에서 복사 이후 원본 변경을 확인합니다. 원본의 현재 상태/금액과 복사 시점 차이를 열람 화면에 표시합니다. 본문이 자동으로 원본 변경을 따라 덮어써지지는 않습니다.
6. **첨부·재인증**: 허용 확장자·일부 파일 서명 검사, OOXML/ZIP 내부 실행 파일·매크로·중첩 압축 차단, 주요 재인증 공통 실패 제한을 추가했습니다. 백신·EDR을 대신하지 않습니다.
7. **화면 구조·성능**: HTML을 약 800줄로 줄이고 CSS와 역할별 JavaScript 6개로 분리했습니다. 지점 조회는 SQL 단계에서 해당 지점을 제한하며 동기화 요청 중첩·오래된 응답 반영을 차단하고 숨겨진 창의 조회를 줄였습니다. 사용하지 않는 브라우저 XLSX 라이브러리는 제거했습니다.

## 백업 사용

- 서버 PC에서 `INSTALL_BACKUP_ENCRYPTION.bat`를 최초 1회 실행하면 cryptography 50.0.0 바이너리 패키지를 현재 Python 사용자에 설치합니다. 회사 인터넷·패키지 설치가 제한된 경우 IT 담당자가 같은 Python에 설치해야 합니다. 일반 Windows 업무 실행은 기존처럼 표준 라이브러리/DPAPI로 가능합니다.
- 상단 데이터 백업은 **암호화 전체백업** 창을 엽니다. 관리자 암호와 별도의 12~128자 백업 암호를 입력합니다. AES-256-GCM 스트리밍 암호화와 PBKDF2-SHA256 600,000회 파생키를 사용하며 생성 후 복호·해시 검증을 합니다.
- `서버 인증서·LAN 설정·Windows CA 개인키도 포함`은 재해 복구용입니다. 서버 CA 내보내기가 회사 정책상 차단되면 완료로 처리하지 않습니다. 이 파일을 다른 접속 PC에 배포하지 마세요. 접속 PC에는 LAN_CLIENT만 전달합니다.
- 별도 보관은 설정 저장 시 첫 전체백업을 생성해 지정 폴더에서 암호화·검증하고, 이후 전체백업에도 적용합니다. 설정만 저장되고 첫 보관이 실패하면 별도 경고를 표시합니다. 폴더만 다르고 같은 물리 디스크면 장비 고장 대비가 되지 않습니다. 복구 암호는 파일과 분리해 회사 지정 장소에 보관하세요. 암호 변경 전 백업에는 이전 암호가 필요합니다.
- 자동 백업은 기본 최근14개/최대30일·최소2개를 유지합니다. 수동·업데이트 전·초기화 백업과 암호화 다운로드 파일은 자동 삭제하지 않으므로 담당자가 별도 관리합니다. 자동 백업은 서버 실행 중에만 동작합니다.
- 생성/복원 공통 전체8GiB·100,000파일 제한과 공간 사전 검사를 사용합니다. 첨부 업로드 제한은 기존 누적2GiB/파일20MiB입니다. 기존2GiB 전체복원 한도와의 충돌을 제거했습니다. 8GiB 실파일 복원을 인증한 수치는 아닙니다.

## 복구와 운영

- `BACKUP_RESTORE_WINDOWS.bat`로 파일 검증·암호화 백업·자료 복원을 안내받을 수 있습니다. 복원 시 서버를 먼저 중지하며 기존 data는 별도 폴더로 보존합니다. 서버 인증서는 자동 교체하지 않습니다.
- 동봉된 `RECOVERY_GUIDE_KO.md`, `ACCEPTANCE_CHECKLIST_KO.md`, `OPERATIONS_GUIDE_KO.md`, `REPORT_REMEDIATION_KO.md`를 확인하세요.
- Oracle 실제 수신·회계 전표 마감/세무/외화 정산·회사 SSO/MFA·이중화·전자서명·회사 Windows 실기 인증까지 완료한 버전은 아닙니다. 구현과 남은 검증을 대응표에서 구분했습니다.
