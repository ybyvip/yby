# V4.1.26 — V4.1.25 기반 메뉴·공지·사용자 분석·개별 점검 개선

V4.1.25 전체 ZIP을 별도 작업 폴더에 해제하여 요청하신 6개 항목을 반영했습니다. 기존 ZIP과 운영 자료는 덮어쓰지 않았습니다.

| 요청 | 반영한 내용 |
|---|---|
| 1. 메뉴 자동 숨김 | 왼쪽 가장자리의 ‘☰ 메뉴’에 마우스를 올리면 메뉴가 나타납니다. 메인 대시보드·법인카드·하이패스·정산/통계·내부보고서·시스템 관리의 상위 메뉴에 마우스를 올리면 해당 하위 메뉴를 표시합니다. 업무를 선택하면 메뉴를 숨기고 업무 화면을 왼쪽부터 전체 가용 폭으로 표시합니다. 클릭/터치·Alt+M·방향 이동에 필요한 키보드 접근도 지원합니다. |
| 2. 공지와 이동 창 | 공지 유형(일반/긴급/수시/점검안내/정책변경/행사안내), 중요도, 안내 대상, 안내 시작/종료일, 첨부를 입력합니다. 세부 내용 작성란을 확대했습니다. 프로그램 공통 창·로그인 창·외부자료 선택 창 등은 제목 영역을 드래그해 이동하며 화면 밖으로 벗어나지 않게 제한합니다. 공지 사진 배경을 더 선명하게 하고 양쪽 패널을 하단까지 채웠으며 목록 앞에 번호를 표시합니다. |
| 3. 사용자별 그래프 | 화면 제목뿐 아니라 실제 집계 기준도 사용자로 변경했습니다. 카드 실사용자/지정사용자, 업무 이력 사용자, 보고서·민원 작성자를 동일 소속·기록 이름별로 집계합니다. 사용자/소속 검색과 8명 단위 페이지, 그래프별 합계·최다 사용자 분석 문구, 전체 이름과 소속 범례를 제공합니다. |
| 4. 화면 디자인 | 공통 업무 테마를 적용했습니다. 차분한 청록색 중심의 버튼, 밝은 배경과 얇은 경계, 일관된 입력란·표·제목 크기·간격·모서리·선택 표시로 정리했습니다. 메뉴의 장식 아이콘을 줄이고 업무 화면 공간을 확보했습니다. 작은 화면에서는 기존 표 내부 스크롤과 세로 배치를 유지합니다. |
| 5. 주요 소식과 연결 표시 | 카드 이상/복구, 제출 후 보고·정산 변경, 반려·승인취소, 긴급공지를 중심으로 선별합니다. 통상 신규 카드·불출·일반 공지·최초 기안 등을 모두 나열하지 않습니다. 소식에 상태 변화·이상 내용·소속·카드 끝자리 설명을 추가하고 원문 연결 시 안내 띠와 선명한 행/상세 강조를 표시합니다. 정산 대기 → 이력대장 이동은 삭제로 표시하지 않고 처리 결과로 연결합니다. |

## 사용 방법

- **메뉴:** 화면 왼쪽 ‘☰ 메뉴’에 마우스를 올리거나 클릭하세요. 상위 메뉴를 선택한 뒤 하위 업무를 누르면 메뉴가 숨고 업무 화면이 넓어집니다. `Alt+M`으로 열고 `Esc`로 닫을 수 있습니다. 접속 계정의 권한이 있는 메뉴만 표시합니다.
- **창 이동:** 창 제목을 잡고 끌어 이동하세요. 제목에 키보드 초점을 두고 `Alt+방향키`로 이동하거나 `Home`으로 원위치에 둘 수 있습니다. 공통 업무 창은 닫은 뒤 새로 열면 기본 위치로 돌아갑니다. 파일 선택·인쇄 등 브라우저/운영체제 자체 창은 대상이 아닙니다.
- **공지:** 공지 알림 → 최고관리자 ‘공지 관리’에서 등록합니다. 안내 대상/기간은 설명 정보이며 예약 게시나 열람 권한 제한이 아닙니다. 기존 공지 열람 기록·첨부·관리자 전용 열람 현황은 유지됩니다.
- **사용자 분석:** 대시보드 ‘사용자별 보유·사용·특이사항 상세’를 누르세요. 같은 지점의 같은 기록 이름을 묶으며, 서로 다른 소속은 구분합니다. 이름이 없는 카드는 ‘미배정·미기록’으로 표시합니다. 계정 요약 권한만으로 사용자 이름을 볼 수 없고, 상세 업무 권한 범위에서만 집계합니다. 각 분석 문구는 **현재 페이지 사용자** 기준입니다.
- **주요 소식:** ‘해당 업무 보기’를 누르면 확인 기록을 남기고 실제 원문에 연결합니다. 소식의 시점과 현재 원문은 다를 수 있으므로 상단 연결 안내를 함께 확인하세요. 이전 발생 기록은 보존하며 화면에서 주요 사항만 선별합니다. 과거 기록이 이미 삭제되거나 시점이 없었던 경우의 복구 한계는 이전 버전과 같습니다.
- **개별 대조:** 업무점검 → 확인할 업무의 ‘명세대조 점검’ → 원본과 대조 명세값 확인/수정 → 문서명·결과·상태·확인·재인증 → ‘대조 내용 반영 · 점검 기록 저장’. 완료하려면 모든 대조 항목을 확인해야 합니다. 미완료 저장은 ‘보완·재점검’으로 이어서 처리합니다.

## 대조 수정과 업무 원본의 구분

대조 창 오른쪽에서 고친 값은 **명세대조 값과 점검 결과로 저장**되며, 업무 원본·승인 금액·반납 상태·결재 상태는 점검 저장만으로 바꾸지 않습니다. 항목별 원본/대조값/확인 여부/차이/사유를 함께 보존합니다. 원래 업무의 정정이 필요하면 창 안의 **‘업무 원문·정정 절차’** 버튼에서 기존 권한과 정정 절차로 처리하세요. 승인 건 정정은 최고관리자 승인취소·정정 흐름을, 이관 자료는 기존 수기정정 흐름을 사용합니다.

완료한 건은 확인할 업무에서 빠지고 하단 저장 목록에서 ‘점검완료’로 표시합니다. 미완료와 이전 기록도 남으며 후속 기록은 이전 기록 번호와 연결합니다. 원본이 바뀌면 이전 점검을 최신 원본에 대한 완료로 간주하지 않고 재점검 대상으로 구분합니다. 이전 월별/개별 점검기록은 삭제하지 않았습니다.

## 자료 보존·적용

스키마는 **13→14**입니다. 기존 공지와 점검 JSON에 선택적 정보를 추가하며, 이전 자료에 없는 유형은 일반공지로 표시합니다. 계정·암호 해시·인증서 관련 도구·기존 카드/정산/반납/첨부/점검 이력을 유지합니다. 새 운영 의존성이나 외부 AI 분석 서비스는 추가하지 않았습니다.

서버를 종료하고 DB·첨부·보안 자료를 포함한 전체 백업을 확보하세요. 새 폴더에 ZIP을 해제하여 기존 실행 방식으로 시작하고, 운영 data를 빈 data로 덮어쓰지 마세요. Windows 실행 폴더 설치는 기존 `%LOCALAPPDATA%\YBY\app\data`를 사용합니다. 운영 자료의 복사본에서 로그인·자료 건수·첨부·권한·인증서 접속을 먼저 확인한 뒤 반영하세요. 이전 프로그램으로 돌아갈 때는 이전 전체 백업을 기준으로 복원해야 합니다.

실제로 검사한 범위와 현장 미검증 항목은 `VALIDATION_V4_1_26_KO.md`를 보세요.
