# YBY V4.1.10 업데이트 및 사용 안내

작성일: 2026-10-19 (한국시간)

## 이번 변경

1. 불출·반납 관리 상단에 외부 신청서 수신 목록을 항상 표시합니다. 화면을 보고 있는 동안 서버 수신함을 10초마다 조회합니다. 검색(Enter), 전체·미적용·적용·회수/삭제 필터, 50건 단위 페이지, 마지막 확인 시각과 갱신 실패 표시를 제공합니다.
2. 관리자가 신청서의 내용을 확인하고 카드·실사용자를 검토한 뒤 **불출 적용**을 눌러 저장합니다. 단순 선택·입력은 미적용 상태이며 성공적으로 저장된 문서만 적용으로 표시합니다. 적용된 신청서의 실제 불출 카드는 기존 **카드 반납 회수 처리** 목록에 나타납니다. 수신만으로 자동 불출하지 않습니다.
3. **반납 회수** 창에도 해당 지점·카드 끝자리에 맞는 외부 정산서 수신 목록을 바로 표시하고 10초마다 조회합니다. 신청서와 정산서는 각각 독립된 문서입니다. 사용기간·사용자·금액을 직접 확인하고 선택하세요. 같은 끝자리 카드가 여러 장이면 관리자 확인이 필요합니다.
4. 정산서를 확인·선택하면 사용함으로 전환하고 기존 정산 양식의 건별 명세와 합계를 채웁니다. 최종 **반납 및 정산 신청**을 눌러야 반납·정산·문서 적용이 함께 저장됩니다. 다른 지점·다른 카드·이미 사용한 문서·회수 문서·변경된 버전은 새 적용을 차단합니다. 외부 결재 상태는 참고용이며 YBY 결재는 별도입니다.
5. 사용함 정산의 **반납·정산 저장 후 관련 보고서 초안 열기**를 체크하면 저장 성공 후 내부 보고서 작성 및 기안 화면으로 이동합니다. 신청자·실사용자·카드·날짜·목적·동행자·건별 명세·합계·비고와 원본 정산 식별 정보를 복사합니다. 보고서 작성 권한이 있어야 보입니다. 제목·내용을 보완하고 결재선을 선택해 별도로 상신하세요. 자동 상신·승인은 하지 않습니다.
6. 나중에도 정산의 **명세 보기/상세 보기 → 관련 보고서 초안 작성**으로 다시 작성할 수 있습니다. 작성 중인 보고서가 있으면 바꾸기 전에 확인합니다. 미상신 초안은 해당 화면에만 남으며 로그아웃하거나 창을 닫기 전에 필요하면 상신하세요. 같은 정산으로 여러 보고서를 작성할 수 있으므로 중복 기안에 유의하세요.
7. 보고서에는 증빙 파일명을 복사합니다. 첨부 파일 실물은 원본 정산에서 확인합니다. 상신 시 서버가 원본 정산 연결과 스냅샷을 보관합니다. 보고서 결재와 정산 결재는 서로 영향을 주지 않습니다. 복사 후 정산이 바뀌어도 보고서 본문은 자동으로 덮어쓰지 않습니다. 날짜·상태는 표시된 시점 기준입니다.

## Oracle 연결 범위

**실제 회사 Oracle DB 접속·조회·자동 수집은 아직 연결되지 않았습니다.** DBA의 테이블/뷰·컬럼·조회 SQL·변경 상태/키 정보 등을 기다리고 있습니다. 이번 자동 갱신은 YBY 서버 수신함에 저장된 정규화 문서를 브라우저가 10초 주기로 조회하는 기능입니다. Oracle에서 자료를 가져오는 주기와 브라우저 갱신 주기는 별개이며, 추후 어댑터 연결 후 실제 지연을 측정해야 합니다. 현재 화면은 ‘Oracle DB 직접 연결 대기’를 표시하고, 수신함이 비어 있으면 직접 입력을 안내합니다. 테스트 문서·회사 자료·DB 접속정보는 배포 ZIP에 넣지 않았습니다. 외부 첨부 수신과 원천 DB 쓰기 기능도 추가하지 않았습니다.

## 기존 서버 PC에서 업데이트

1. 현재 프로그램의 최고관리자로 로그인하고 **시스템 관리 → 권한 & 비밀번호 관리 → 전체 백업 만들기**를 실행합니다. 현재 관리자 비밀번호로 생성하고 Ctrl+J에서 ZIP 다운로드가 끝났는지 확인하여 따로 보관하세요. 상단의 데이터 백업(JSON)과 구별하세요.
2. 다른 사용자가 작업하지 않는 시간에 기존 서버 실행창에서 Ctrl+C 또는 STOP_SERVER.bat로 서버를 종료하세요.
3. V4.1.10 전체 ZIP을 새로운 폴더에 완전히 압축 해제하세요. 실행 파일 몇 개만 기존 폴더에 복사하지 마세요.
4. **기존 서버를 실행하던 Windows 계정으로** 새 폴더의 RUN_LAN_WINDOWS.bat를 실행하세요. `%LOCALAPPDATA%\YBY\app`의 기존 DB·계정·업무자료·첨부·인증서·사내망 설정을 유지하면서 프로그램 파일을 갱신합니다. 업무자료 ZIP을 수동으로 압축 해제할 필요가 없습니다.
5. 화면 버전이 V4.1.10인지 확인하고 기존 계정으로 로그인하세요. 창을 닫았다가 다시 접속할 때는 `https://localhost:5000`(서버 PC), `https://10.10.0.121:5000`(회사 PC, 기존 IP가 같을 때)을 사용하세요. 서버 실행창은 계속 열어 두세요. 다른 PC에는 자기 PC의 localhost가 아니라 서버 IP를 사용합니다.
6. 기존 자료·반납 대상 목록을 먼저 확인하고 실제 업무를 재개하세요. Oracle 연결 전에는 기존 YBY 직접 입력을 사용합니다. 실무 확인을 위해 허위 불출·정산을 운영 DB에 만들지 마세요.

DB 스키마는 V4.1.9와 같은 6입니다. 다운로드한 전체 백업은 장애 복구용입니다. 정상 업데이트에는 복원할 필요가 없습니다. 전체 업무 백업은 data 안의 DB·첨부·기존 업무용 키를 포함하며 app/certificates의 TLS 인증서나 서버 설정을 포함하지 않습니다. 다른 PC로 서버를 옮기는 작업은 별도 인증서/설정 준비가 필요합니다.

## 검증 범위

Python 서버 회귀·권한·동시 적용/롤백·백업 검증, Chromium에서 실제 10초 수신 목록 갱신·불출·반납·보고서 초안/상신, 기존 정정/재보고·집계/인쇄, 기존 버전에서 프로그램 갱신 및 자료 유지, ZIP 무결성을 확인합니다. 결과는 VALIDATION_V4_1_10.md를 참고하세요. 회사 Windows PC와 실제 Oracle 연결은 이 환경에서 직접 검증하지 못했으므로 사내 환경에서 최종 확인이 필요합니다.
