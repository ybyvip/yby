# YBY V4.1.14 검증 결과

검증일: 2026-10-20 (한국시간). 기준 소스: V4.1.13.

## 자동 검증

- Python 서버 **256개 통과** (137.551초, 실패/스킵 없음). 기존 241개에 신규 15개를 추가했습니다. 변경된 상태 정책에 맞춰 이전 기능 검증의 준비 자료도 수정했습니다.
- 임시저장/상태 흐름 신규 검증: 부분 입력 저장 및 재조회, 대기중/임시저장의 확정 API 차단, 새 등록에서 회수 상태 금지, 입력 완료 후 불출 확정, 임시 자료의 잘못된 날짜/분류/중복 번호 차단, 회수중의 하단 이동/최종 회수 후 리스트 이동, 비밀번호/사유/날짜/버전/재처리 검사, 허용되지 않은 상태 이동 차단, 회수완료 후 재준비 날짜 처리, 다른 지점 처리 차단, DB 오류 시 상태·이력 원자적 롤백, 지표별 단독/두 카드 집계·필터 엑셀, 실제 수정 문서와 확인 이력 연결, 최종 이력만 현재 상태 및 일련번호, 과거 같은 카드의 최신 행 구분을 확인했습니다.
- 마지막 빈 임시자료 저장 방지 보완 후 신규 상태 검증 **15개 재실행 통과** (9.644초). 중복 재실행은 총합에 더하지 않았습니다.
- Node 이력·집계 **12개 통과**, 실패/스킵 없음. 구별되는 자동 검증 총 **268개**입니다.
- 클라우드의 HTTP 프록시가 로컬 시험 요청을 차단했던 초기 환경 문제는 테스트 명령에 localhost/127.0.0.1 NO_PROXY를 지정해 해결했습니다. 실패한 초기 실행은 통과 건수에 포함하지 않았습니다. 원격 연결의 TLS 검증을 끄지 않았습니다.

## 실제 Chromium 기능 확인

1. 두 카드 선택 후 차량명만 입력하여 임시저장 → 창을 닫고 새 로그인 → 서버의 하단 임시자료 다시 열기 → 전체 내용 작성·저장 → 대기중으로 하단 보관 → 불출중으로 수정·저장 → 정보 확인/불출 확정 → 리스트 이동을 실제 화면으로 실행했습니다. 새 등록 선택에는 대기중/불출중만 있고 대기중 미리보기에는 확정 버튼이 없습니다.
2. 지표 순서 불출중 우선 및 여섯 지표 클릭 상세 목록을 검증했습니다. **하이패스 단독 1 + 유류대 단독 1 + 두 카드 묶음 1 = 등록 3묶음, 하이패스 2개, 유류대 2개**를 실제 자료와 비교했습니다. 지점 필터, 다른 지점 비노출, 실제 지표별 XLSX 파일 내용을 확인했습니다.
3. 리스트의 차량번호/유류대 발급사 수정 → 저장 → 재확인 후 **가장 최근 정보확인 문서**를 열어 실제 입력 변경 전·후를 확인했습니다. 이전 버전처럼 문서 연결 ID가 없어도 기록 버전으로 연결되는 경우를 확인했습니다. 양쪽 셀의 서로 다른 음영 색상도 실제 계산 스타일로 확인했습니다.
4. 비교표 PDF를 실제 생성하고 텍스트에서 변경 전/후 차량번호·유류대 발급사·두 카드번호·비교 열을 확인했습니다.
5. 리스트 수정 → 회수중 저장 → 하단 업무대기 이동 → 잘못된 비밀번호로 최종 회수 차단 → 올바른 비밀번호/사유/실제 날짜로 회수완료 → 리스트 복귀를 실행했습니다. 일련번호 중복 없음, 같은 묶음의 마지막 행만 현재 상태, 과거 행은 작업 완료, 실제 이력 XLSX의 일련번호를 확인했습니다.
6. 1600/1024/768px 지표 한 줄, 390/320px 입력폼/현황 가로 넘침 없음, 자동 다시 그리기 후 아코디언 펼침 유지, 지점 권한을 확인했습니다. JavaScript 실행 오류 없음. 화면 캡처도 시각 점검했습니다.

## 회귀·업데이트

- 기본 브라우저: 보고서 작성/승인, 업무 저장 실패 시 입력 보존, 실제 엑셀/전체 백업 ZIP 다운로드, 하이패스/민원/공지/메모/메시지 저장, 모바일·키보드 통과.
- V4.1.13 브라우저 회귀: 법인카드 구분 저장/수정, 두 카드 묶음 확인/재확인, 로그인 비밀번호/사유 수정·삭제, 삭제 전 문서 보존, 유류대 대시보드, 17개 바로가기와 권한·저장 실패 처리, 축소된 정산 요약 통과. 과거 이력의 상태 기대값은 새 ‘작업 완료’ 정책에 맞췄습니다.
- V4.1.11 보고서/반납/불출완료 이력과 최고관리자 본인 최종 승인, 외부 수신함·정산/보고서 독립 흐름 통과. 메신저 본문 직접 흐림과 기존 비밀번호 잠금도 통과.
- 실제 **V4.1.13 → V4.1.14** 프로그램 교체/기동/로그인: 시작 전 DB 바이트 동일, 기존 카드·불출반납·정산·보고서·계정·첨부·외부 수신 문서·확인완료 두 카드 묶음/버전 보존. 기존 대기중/확인완료와 회수중/확인대기 자료가 하단 엑셀에만 표시되는지 확인했습니다. 과거 변경 전·후 스냅샷과 확인 이력은 JSON 원본 동일하며 새 draftType을 임의로 채우지 않았습니다.
- 읽기 전용 한글 원본 → 사용자 전용 실행 폴더 설치/시작/로그인/업무 저장, 중복 실행 같은 PID, 반복 설치 자료 유지 확인.
- CA/개인키·LAN 설정 보존은 시험용 파일 바이트 비교이며 실제 회사 인증서 실행 확인이 아닙니다.

## 배포 확인과 한계

최종 ZIP CRC/파일별 SHA-256/추출본 bootstrap 무결성, Python 3.11 구문/JavaScript 구문, PowerShell BOM 및 V4.1.13과 파일 바이트 동일을 검사합니다. 배포는 명시된 파일 목록으로 구성해 운영 DB·개인키·로그·회사 문서·시험 수신 자료를 제외합니다. 게시 후 실제 다운로드 URL에서 다시 받아 ZIP 및 SHA-256를 비교합니다.

회사 Windows/Edge/WebView2, 실제 인증서 등록·회사 방화벽, 실제 Oracle DB는 이 환경에서 실행하지 않았습니다. 회사 PC에서 최종 실행 확인이 필요합니다. Oracle 연결은 담당자 자료 대기 상태를 유지합니다.
