# YBY V4.1.17 — 이전 Book1.xlsx 수신 오류 수정

작성일: 2026-10-20 (한국시간). 기준 버전: V4.1.16.

## 이번 오류의 원인과 수정

첨부 화면의 ‘등록 카드가 없습니다’는 엑셀을 읽지 못한 문제가 아닙니다. 이전 Book1.xlsx의 제목 5행과 업무 4행은 인식했지만, V4.1.16이 **자료 수신 단계에서도 등록된 전체 카드번호를 필수로 요구**하여 네 행을 모두 막았습니다.

V4.1.17은 **신청·정산 자료 수신**과 **실제 카드 확인·불출**을 구분합니다.

- 같은 원본 Excel을 그대로 올릴 수 있습니다. 등록 카드가 없어도 **수신 가능**으로 표시하고 신청/정산 목록에 넣습니다.
- 미등록은 ‘카드 등록 전 수신 가능’, 끝자리 중복은 ‘수신 후 불출 전 선택’으로 안내합니다. 엑셀만으로 전체 카드번호나 새 카드를 만들어 등록하지 않습니다.
- 실제 카드를 선택해 올렸다면 기존처럼 그 전체 번호와 카드 ID를 확인합니다. 다른 지점·끝자리의 잘못된 명시적 선택은 차단합니다.
- 카드가 없는 자료도 먼저 수신·매칭할 수 있습니다. 연결 목록에는 **매칭완료 · 카드 등록 후 불출**을 표시하며 **카드 등록 안내 → 법인카드 등록 화면**으로 이어집니다.
- 실제 전체 카드번호를 등록한 뒤 연결 목록을 다시 확인하면 **불출 준비**가 활성화됩니다. 그때 실제 카드·사용자·기한을 확인해 불출합니다. 실제 카드가 없는 상태에서 불출·반납·정산 저장·승인을 대신 완료하지 않습니다.

## 이전 첨부파일의 반영 결과

이전에 보내주신 **Book1.xlsx**를 등록 카드가 **0장**인 시험 서버에 직접 올려 검증했습니다.

| 항목 | 확인 결과 |
|---|---:|
| 제목 행 | 5행 |
| 업무 행 | 6~9행, 4건 |
| 수신 가능한 행 | 4건 |
| 신청서 | 4건 |
| 금액이 있는 정산서 | 1건, 합계 225,000원 |
| 금액이 없어 정산 미수신인 신청서 | 3건 |
| 자동 생성된 카드·업무 정산·승인 | 0건 |

이 수치는 첨부파일을 시험한 결과입니다. 사용자 PC에 회사 자료를 미리 넣어 배포한 것이 아닙니다. 업데이트 후 원래 Excel을 업로드하세요.

## 원본 열 → YBY 항목 대응

| 원본 열 | YBY 반영 |
|---|---|
| 순번 | 원본 참고 순번. 문서 고유키와는 별도 |
| 은행명 | 원본 카드사 표시. 등록 카드사를 임의 변경하지 않음 |
| 카드번호(뒤4) | 신청·정산의 카드 끝 4자리. 전체 번호로 보충하거나 새 카드를 만들지 않음 |
| 사용자 | 실제 사용자. 별도 신청자 열이 없으면 신청자 대체값으로 안내 |
| 사용횟수 | 원본 참고 사용횟수. 합계 1건을 여러 세부 거래로 만들어 부풀리지 않음 |
| 부서명·직급 | 사용 부서 / 원본 참고 직급 |
| 목적·사용목적 | 목적 구분 / 상세 목적. ‘출장’ 등 지원하는 구분은 불출 화면의 해당 체크 항목으로 전달 |
| 사용금액 | 정산 합계. 양수일 때 합계 1명세의 정산서 준비 |
| 지급일 | 원본 지급일. 별도 사용신청일이 없으면 신청일 대체값으로 표시 |
| 예정일 | 반납예정일 |
| 반납일 | 원본 반납일 참고. 실제 YBY 반납 완료로 자동 처리하지 않음 |
| 사용기간·전표·정리·처리확인·총분출횟수·불출·관리 | 원본 참고 항목. ‘완료’ 등이 있어도 YBY 결재/반납 상태로 자동 변환하지 않음 |
| 월 한도금액·월 사용금액·월 잔여한도 및 옆쪽 참고표 | 개별 신청·정산 금액으로 가져오지 않음 |

빈 사용금액을 0원으로 바꾸거나 정산서를 임의로 만들지 않습니다. 0원이 명시된 행도 신청서만 준비하고, 실제 미사용 여부는 반납 시 확인합니다. 별도 ‘사용신청일’, ‘신청자’, ‘소속지점’, ‘외부행ID’ 열을 사용한 파일도 기존대로 지원합니다.

## 사용하는 순서

1. **법인카드 관리 → 외부자료 매칭 → 엑셀 대량 업로드**를 펼칩니다.
2. **기본 소속 지점**을 선택하고 이전 **Book1.xlsx**를 지정합니다. 최고관리자는 행별 지점을 바꿀 수 있으며 지점 담당자는 자기 지점만 올립니다.
3. **미리보기 · 다시 검사**를 누릅니다. 이전 화면과 달리 카드가 없어도 4행이 수신 가능하고 신청서/정산서 예정 건수가 함께 표시됩니다.
4. 원본 카드 끝자리·신청자/사용자·부서·신청/예정/지급/반납일·목적·합계금액을 확인합니다. 수정 후에는 다시 검사합니다.
5. 업로드할 정상 행과 확인란을 체크하고 **선택 행 업로드**를 누릅니다.
6. 아래 **새 문서 매칭**에서 신청서와 정산서를 각각 전체 또는 선택 수신합니다. 한 건뿐이어도 자동 선택하지 않습니다.
7. 같은 원본 행의 신청서와 정산서를 각각 1건 선택하고 확인 후 매칭합니다. 금액이 없는 신청서 3건은 정산서가 아직 없는 상태로 남습니다.
8. 매칭한 자료는 새 수신 후보에서 빠지고 하단 **연결된 신청서 → 정산서** 목록에서 계속 관리합니다. 실제 카드가 없으면 등록 안내를 이용하고, 등록 후 불출 준비부터 진행합니다.

원본은 과거 신청·지급·반납 기록을 포함합니다. 업로드는 **원본 수신**이며 과거 불출/반납/승인을 자동 재실행하는 기능이 아닙니다. 이미 처리한 업무는 기존 이력을 먼저 확인하세요. 반납예정일이 지난 신청서를 새로 불출할 때는 실제 사용할 기한을 확인·보완합니다. YBY에서 값을 보완하면 그 사실을 구분합니다.

## 중복 방지와 기존 자료 보존

- 기존과 같이 외부행ID가 있으면 해당 지점과 ID를 사용하고, 없으면 지점·은행명·카드 끝자리·사용자·부서·지급일·사용목적을 원본 행 식별 기준으로 사용합니다.
- 파일명을 바꾸거나 행 순서를 바꿔도 같은 원본 행을 새로 생성하지 않습니다. 나중에 카드를 등록한 뒤 같은 파일을 올려도 카드 등록 전 수신했던 원문은 중복 제외합니다.
- V4.1.16에서 이미 올린 행의 중복 검사 방식도 호환합니다. 기존 원문·카드 선택·매칭·재무 이력을 덮어쓰지 않습니다.
- 같은 식별정보의 금액·날짜 등 업무 내용이 다르면 기존처럼 충돌로 표시합니다. 별도 실제 업무는 외부행ID로 구분해야 합니다. 고유번호가 없는 별도 업무나 Oracle/Excel 교차 수집을 완전히 자동 판별하지 않습니다.
- 원본 참고 상태는 최초 수신 시의 참고값입니다. 재업로드로 YBY 승인 상태나 과거 원문을 바꾸지 않습니다. 처리 후에는 기존 승인취소·정정 절차를 사용합니다.

## 업데이트

1. 최고관리자로 **시스템 관리 → 권한 & 비밀번호 관리 → 전체 백업 만들기**를 실행하고, 현재 로그인 비밀번호로 확인해 내려받은 전체 ZIP을 별도 보관합니다. 상단 데이터 백업 JSON과 구별합니다.
2. 다른 사용자의 작업을 마친 뒤 기존 서버 실행창에서 **Ctrl+C**로 종료합니다.
3. V4.1.17 전체 패키지를 **새 폴더에 완전히 압축 해제**하고 기존 서버와 같은 Windows 계정으로 **RUN_LAN_WINDOWS.bat**를 실행합니다.
4. `%LOCALAPPDATA%\YBY\app`의 업무 DB·계정·첨부·인증서·사내망 설정을 유지합니다. 정상 업데이트에는 백업을 복원하지 않습니다.
5. 상단 V4.1.17을 확인한 뒤 이전 Book1.xlsx로 다시 검사하세요. 이전 화면이 남으면 창을 닫고 CONNECT_SERVER.bat로 다시 엽니다. 서버 창은 계속 열어 둡니다.

서버 PC: `https://localhost:5000`, 다른 PC: 서버 IP가 같다면 `https://10.10.0.121:5000`. DB 스키마는 **8 유지**이며 기존 수신·매칭·정산 자료를 다시 작성하지 않습니다.

실제 회사 Excel은 패키지에 포함하지 않았습니다. 실제 첨부의 비공개 검증, 별도 시험 자료의 브라우저 검증 및 기존 V4.1.16 업데이트 검증 결과는 **VALIDATION_V4_1_17.md**를 참조하세요. 회사 Windows/Edge/WebView2·회사 인증서·방화벽은 현장 최종 확인이 필요합니다. 실제 Oracle 연결은 기존처럼 담당자 자료 대기 상태입니다.
