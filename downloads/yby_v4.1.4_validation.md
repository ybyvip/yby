# V4.1.4 검증 결과

2026-10-17 (한국 시간). Linux/Python 3.12 및 실제 Chromium에서 검증했습니다.

- 서버/API·정산·권한·세션·첨부·배포 인코딩 자동검사 164개 통과.
- 실제 로그인 화면에서 아이디 직접 입력, 비밀번호 마스킹, 목록 조회 중 입력값 유지, Enter 제출, 잘못된 인증/서버 오류의 인라인 표시, 중복 요청 방지 확인.
- 로그인/로그아웃/창 닫기 후 다시 로그인, 최초 비밀번호 변경, 최고관리자/지점 권한 적용 확인. 접속 PC localStorage에 시험 비밀번호가 들어가지 않음 확인.
- 320/390/480/1366px 화면에서 입력폼의 가로 넘침 없음. 별도 창의 로그인/업무 화면 크기 변경 요청 및 제목 전환 검사. 일반 브라우저에서는 크기 변경 요청 없음.
- 실제 정산 반납/건별 합계/영수증/승인취소/정정/재보고/재승인, 관리자 비밀번호 재인증, 지점 세션 유지, 공지 첨부 재시도/다운로드 확인.
- 따옴표/한글이 포함된 계정 생성·수정·로그인·최초 비밀번호 변경과 채팅 개인정보/반납/로그아웃 자료 정리 검사 통과. 오래된 브라우저 검사에서 자동 집계칸 직접 입력을 시도하던 부분을 현재 건별 입력칸 사용으로 갱신하여 동일 업무 결과를 확인.
- 최종 압축 해제본에서 실제 부트스트랩 설치, 중복 실행 PID 유지, 로그인/업무 저장 및 원본 DB 보존 확인.
- 실제 V4.1.3→V4.1.4 HTTPS 업데이트: 실행 중인 구버전 무변경, 파일 교체 전 DB 바이트 동일, 기존 계정/비밀번호/카드/취소·재보고 이력/첨부/CA·개인키 보존 확인.
- 실제 Chromium의 신뢰 CA 기반 HTTPS 로그인, HTTP→HTTPS 이동, Secure/HttpOnly 쿠키, 로그아웃·창 닫기 후 재접속 통과. 인증서 검증 우회 없음.
- PowerShell 4개 UTF-8 BOM과 구문 트리 유지. 시작 메뉴 수동 등록 경로, 전용 앱 모드·개별 프로필, Windows 자동실행 등록이나 인증서 검증 우회가 없음을 코드에서 확인.
- ZIP CRC·파일별 MANIFEST SHA-256 및 고객 DB/첨부/인증서/개인키 미포함 확인. 검사 후 안내문과 오래된 브라우저 시나리오만 정리했으며 배포 프로그램 코드는 압축 해제 검사본과 동일합니다.

## 플랫폼 한계

실제 Windows 시작 메뉴 .lnk 등록·WScript.Shell·Edge 앱 창 크기/위치·Windows 메시지창·DPAPI/NTFS·회사 정책은 여기서 실행하지 않았습니다. 창 크기 전환 검사는 API 요청을 기록한 브라우저 검사이며 실제 Windows 창 크기를 보증하지 않습니다. 해당 PC에서 시작 메뉴→YBY 로그인, 로그인/로그아웃 및 최대화 동작을 확인하세요. 브라우저 정책이 자동 크기 변경을 제한하면 최대화 버튼을 사용할 수 있습니다.

RUN_LAN_WINDOWS.bat의 Windows PowerShell 사전 구문 검사, VERIFY_WINDOWS.bat와 다른 PC CHECK_CONNECTION.bat로 실제 환경을 확인하세요. 서버를 종료하고 기존 실행 계정으로 적용해야 새 파일이 설치됩니다.
