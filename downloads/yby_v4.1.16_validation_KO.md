# YBY V4.1.16 검증 결과

검증일: 2026-10-20 (한국시간). 기준 소스: V4.1.15. DB 스키마 8.

## 첨부 문서 확인

Book1.xlsx는 제목 5행, 업무 자료 6~9행으로 확인했습니다. 등록 카드 대신 동일 끝자리의 시험용 카드만 사용해 실제 첨부의 구조·날짜·금액을 미리보기로 검사했습니다. 4행 모두 구조 검사를 통과했고 사용금액 있는 1행 / 없는 3행으로 구분했습니다. 원본에 있는 월 한도·월 사용금액 및 옆쪽 참고표를 개별 정산액으로 가져오지 않았습니다. 실제 회사 문서·개인정보는 배포 패키지나 공개 화면 캡처에 넣지 않았습니다.

## 자동 검증

- Python 서버 **294개 통과** (133.613초, 실패/스킵 없음). 이전 274개와 신규 20개입니다.
- Node 이력·통계 **24개 통과**, 실패/스킵 없음. 서로 다른 자동 검증 총 **318개**입니다. 반복 실행 건수는 합계에 더하지 않았습니다.
- 신규 검증은 미리보기 무저장, 한 행의 신청/정산 원본 연결, 합계 1명세와 원본 사용횟수 참고값 보존, 빈 금액/0원 정산 미생성, 재업로드·파일명/행 순서 변경·파일 안 반복행 중복 제외, 기존 금액 변경 충돌 차단, 외부행ID로 같은 날 별도 건 구분을 확인했습니다.
- 카드 끝자리 중복 시 직접 선택, 선택한 전체 카드번호·카드 ID의 이후 불출 일치 검사, 미등록 카드·잘못된 날짜·음수 금액·계산 결과 없는 수식 셀 차단, Excel 날짜 체계·앞자리 0 보존, 관리자 행별 지점과 지점 계정 범위 제한을 확인했습니다.
- 익명·권한 없는 계정 차단, 정규화 문서 주입 차단, 파일 해시·명시적 확인·선택 행 번호 검사, 정상 행만 부분 업로드, DB 실패 시 원문/가져오기 기록/업무 상태 원자적 롤백을 확인했습니다.
- 전체/개별 수신, 재수신 중복 제외, 문서 버전·지점 검사, 신청서/정산서 독립 수신, 새 원본 버전 재확인, 매칭 후 두 새 후보 목록 제외·원문 보존, 서로 다른 엑셀 원본 행 매칭 차단을 확인했습니다.
- 동일 원본 키/버전 재전송 시 수신 시각이 다시 쓰이지 않으며 수신 확인을 재생성하지 않습니다. 기존 Oracle 식별자와 Excel 식별자는 출처를 나누어 충돌하지 않습니다.
- 법인카드 XLSX 제목/값·지점·검색 범위·비밀 KEY 비출력, 전체 백업 ZIP 복원 시 엑셀 중복 검사 기록·버전별 수신 확인 및 스키마 8 복구를 검증했습니다.

## 실제 Chromium 기능 확인

1. 실제 XLSX 파일을 선택해 제목 5행을 인식 → 끝자리 중복 카드 직접 선택 → 다른 행의 지점을 서울에서 인천으로 변경 → 다시 검사 → 정상 3행 업로드를 실행했습니다. 신청서 3건/정산서 2건이 준비되며 금액 없는 행은 정산이 생성되지 않고, 카드와 업무 정산 상태가 자동 변경되지 않습니다.
2. 같은 파일 재검사에서 3행 모두 중복 제외·추가 업로드 비활성을 확인했습니다.
3. 미수신 신청서 개별 선택 수신 → 수신 완료 후보가 1건이어도 자동 선택 0/1 유지 → 남은 신청서 전체 수신 → 정산서 전체 수신 → 각각 1건 선택하여 1/1 표시 → 확인 후 매칭을 실행했습니다.
4. 매칭한 두 문서가 새 후보 및 불출/사용정산의 외부 수신 목록에서 사라지고 연결 목록에 남는지 확인했습니다. 연결 목록에서 불출 준비 → 원본 확인 → 정확한 실제 카드 1장만 후보 → 불출 → 연결 목록의 반납·정산 → 합계 12,000원 정산 1건 생성까지 확인했습니다. 엑셀 출처·원본 사용횟수 3과 실제 합계 명세 1건이 구별되어 보존됩니다.
5. 법인카드 목록의 **제목 14칸 / 실제 값 14칸** 일치, 신용/체크·사용 범위 칸의 정확한 값, 검색으로 1장 조회 → 실제 XLSX의 별칭·전체 카드번호·다른 카드 제외를 확인했습니다.
6. 실제 PDF를 생성해 별칭·체크·해외겸용·끝자리 5545가 모두 존재하는지 텍스트 추출로 확인했습니다. KEY는 표와 출력 대상에서 제외했습니다.
7. 지점 계정 기본 지점 고정/다른 지점 비노출, 1600/1024/768/390/320px에서 매칭·엑셀 미리보기·등록 목록의 페이지 가로 넘침 없음, JavaScript 실행 오류 없음을 확인했습니다. 긴 표는 영역 안에서 스크롤합니다. 실제 화면 캡처도 시각 확인했습니다.

- 이전 매칭/전체 통계: 처리 전 잘못된 연결 비밀번호 정정·이력, 처리 후 잠금, 정확한 불출 회차 연결, 별도 YBY 승인, 취소/과거 마이너스 중복 제외, 관리자 12,000원/지점 5,000원 통계, 실제 XLSX/PDF, 네 가지 요약과 통합 비교표·상태 색상 통과. 이전 검증의 수신 전제와 매칭 후 진입 위치를 새 정책에 맞게 조정했습니다.

## 배포 검사와 범위

최종 ZIP CRC·파일별 SHA-256·추출본 시작 무결성, Python 3.11 구문, 모든 JavaScript/인라인 스크립트 구문을 검사합니다. PowerShell은 V4.1.15와 바이트 동일 및 UTF-8 BOM을 검사합니다. 명시된 파일 목록만 패키지에 넣어 운영 DB·개인키·로그·실제 첨부 Excel·회사 개인정보를 제외합니다. 게시한 실제 URL에서 다시 다운로드하여 GET 200·ZIP CRC·전체 내부 파일 해시를 대조합니다.

실제 Oracle 연결, 회사 Windows/Edge/WebView2·인증서 등록·회사 방화벽은 이 클라우드에서 실행하지 않았습니다. Oracle SQL/뷰·컬럼·권한 자료는 대기 중이며 이번 수신 확인은 YBY 서버 대기함 기준입니다. 고유번호 없는 서로 다른 실제 업무나 Oracle/Excel 교차 수집의 동일성을 완전히 자동 판정하지 않으며, 안내문의 중복 기준·외부행ID 및 확인 절차를 사용해야 합니다. 회사 PC에서 최종 실행 확인이 필요합니다.
