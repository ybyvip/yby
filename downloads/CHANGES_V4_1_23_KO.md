## 자료·권한 보존

- 스키마 10 → 11 업그레이드 전 기존 DB·첨부 백업을 생성합니다. 계정·비밀번호 해시·기존 사고 이력·점검기록·인증서 관련 설정을 초기화하지 않습니다.
- 이전 분실 기록에 인지 시점·제보자 등이 없으면 사실을 만들어 채우지 않습니다. 기존 변경 사유와 저장 당시 카드정보를 표시하고 새로 접수·수정할 때 상세 정보를 입력합니다.
- 사고·사용제한/종료 카드의 신규 불출 제한, 임시저장과 실제 인계 확정의 분리, 권한·지점 격리, 요청 중복 방지와 변경 충돌 검사를 유지합니다.
- 대체는 새 카드 생성과 기존 카드 종료를 한 트랜잭션에서 처리합니다. 중복 번호나 저장 실패 때 한쪽만 반영하지 않습니다.
- 점검 완료는 원래 카드·반납·정산·결재 상태를 바꾸지 않습니다. 점검기록을 근거로 자동 승인하거나 회계 마감을 수행하지 않습니다.
- 문서 첨부는 파일 형식 검사, 소유자·용도·지점·메뉴 권한을 서버에서 확인합니다. 미리보기에는 입력 내용을 안전하게 텍스트로 표시합니다.

## 반영 방법

기존 서버를 종료하고 **기존 실행 폴더 전체(DB·첨부·인증서·설정 포함)를 별도로 백업**한 다음 ZIP을 새 폴더에 전체 해제하세요. 기존 `RUN_WINDOWS.bat`/`RUN_LAN_WINDOWS.bat` 또는 Linux 실행 절차를 사용합니다. Windows 원본 폴더와 실제 사용자 실행 폴더가 다를 수 있으므로 기존 운영 가이드를 함께 확인하세요. 기존 자료를 빈 새 DB로 덮어쓰지 마세요.

실제 고객 업무자료와 실제 Windows PC 적용은 현장 확인이 필요합니다. 구버전으로 되돌릴 때는 새 스키마 DB를 사용하지 말고 구버전 프로그램과 업그레이드 전 백업을 함께 사용하세요. 공개 ZIP에는 실제 계정 비밀번호·업무 DB·운영 인증서 개인키를 포함하지 않습니다.
