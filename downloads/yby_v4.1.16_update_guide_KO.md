# YBY V4.1.16 업데이트·엑셀 업로드 안내

작성일: 2026-10-20 (한국시간). 기준 버전: V4.1.15.

## 업데이트 순서

1. 최고관리자로 **시스템 관리 → 권한 & 비밀번호 관리 → 전체 백업 만들기**를 실행하고 현재 로그인 비밀번호로 확인합니다. Ctrl+J에서 전체 백업 ZIP 다운로드 완료를 확인해 별도 보관하세요. 상단의 데이터 백업 JSON과 다릅니다.
2. 다른 사용자가 작업을 마친 뒤 기존 서버 창에서 **Ctrl+C**로 종료합니다.
3. V4.1.16 전체 ZIP을 **새 폴더에 완전히 압축 해제**합니다. 기존 서버와 같은 Windows 계정으로 **RUN_LAN_WINDOWS.bat**를 실행합니다.
4. 실제 실행 폴더 `%LOCALAPPDATA%\YBY\app`의 업무 자료·계정·첨부·인증서·사내망 설정을 유지하며 프로그램을 교체합니다. 정상 업데이트에서는 백업을 복원하지 않습니다.
5. 상단 V4.1.16과 기존 자료를 확인합니다. 예전 화면이 보이면 창을 닫고 CONNECT_SERVER.bat로 다시 여세요. 서버 실행창은 계속 열어 둡니다.

서버 PC 접속은 `https://localhost:5000`, 다른 PC는 서버 IP가 그대로라면 `https://10.10.0.121:5000`입니다. HTTP가 아닌 HTTPS를 사용합니다.

DB 스키마는 **7 → 8**로 올라가며 엑셀 원본 행 중복 검사와 문서 버전별 수신 확인 테이블을 추가합니다. 업데이트 전 자동 전체 백업도 생성하며 실패하면 변경을 시작하지 않습니다. 기존 매칭·변경 이력·재무 자료는 보존합니다. 최신 DB를 이전 프로그램으로 직접 열 수 없습니다. 이전 버전으로 돌아가려면 업데이트 전 전체 백업과 해당 이전 프로그램을 함께 사용해야 합니다. 백업 복원은 자료를 이전 시점으로 되돌리는 작업입니다.

## 1. 엑셀 대량 업로드

위치: **법인카드 관리 → 외부자료 매칭 → 엑셀 대량 업로드**를 펼칩니다.

### 지원하는 파일

- `.xlsx`, 최대 **1MB / 2,000행**입니다. 큰 파일은 나누어 올립니다. 오래된 `.xls`는 Excel에서 `.xlsx`로 저장하세요.
- 제목 행의 위치를 자동으로 찾습니다. 이번에 보내주신 Book1.xlsx처럼 **5행 제목 / 6행 이후 자료**도 읽습니다. 여러 시트가 있으면 첫 검사 후 시트를 선택해 다시 검사할 수 있습니다.
- 제목 **카드번호(뒤4), 사용자, 지급일**을 기준으로 찾고 사용목적·사용금액·예정일·반납일·은행명·부서명 등을 읽습니다.
- 원본에 있는 월 한도금액·월 사용금액·월 잔여한도·옆쪽의 하이패스 참고표는 가져오지 않습니다. 한 행의 **사용금액**만 해당 정산 합계로 읽습니다.
- 엑셀 수식·외부 연결·매크로는 실행하지 않습니다. 필요한 셀의 수식 결과가 저장돼 있지 않으면 확인 필요로 표시합니다. Excel에서 계산을 마치고 저장한 뒤 다시 올리세요.

### 실제 작업 순서

1. **기본 소속 지점**을 선택하고 파일을 지정한 뒤 **미리보기 · 다시 검사**를 누릅니다. 최고관리자는 행별 지점을 바꿀 수 있으며 지점 담당자는 자기 지점만 올립니다.
2. 각 행의 **지점·실제 카드·사용자·지급일/반납일·합계금액·확인 사항**을 검토합니다. 화면을 확인하는 동안 서버의 업무 자료는 바뀌지 않습니다.
3. 카드번호는 끝 4자리로 후보를 찾습니다. 같은 지점에 후보가 **정확히 한 장**일 때만 선택값을 채우며, 여러 장이면 실제 카드를 직접 선택해야 합니다. 등록 카드가 없으면 먼저 법인카드를 등록하세요. 끝 4자리로 새 카드번호를 만들어 등록하지 않습니다.
4. 지점이나 카드를 수정했으면 **미리보기 · 다시 검사**를 다시 누릅니다. 확인되지 않은 변경 상태에서는 업로드를 막습니다.
5. 올릴 정상 행을 선택하고 확인란을 체크한 뒤 **선택 행 업로드**를 누릅니다. 오류 행은 선택되지 않으며 정상 행만 따로 올릴 수 있습니다. 저장 직전에 서버가 파일·지점·카드·중복을 다시 검사합니다.
6. 아래 **새 문서 매칭**에서 신청서/정산서의 미수신 자료를 각각 수신한 뒤 매칭합니다.

### 한 행에서 생성되는 자료

| 원본 상태 | 수신 대기함에 생성되는 자료 |
|---|---|
| 사용금액이 양수 | 신청서 1건 + 정산서 1건 |
| 사용금액 빈칸 | 신청서만 1건. 정산은 미수신으로 구분 |
| 사용금액 0원 | 신청서만 1건. 실제 미사용 여부는 반납 시 확인 |
| 잘못된 날짜·음수 금액·카드 미등록/모호함 | 확인 필요. 수정/등록 후 재검사 |

- 한 행의 신청서와 정산서에는 **동일 원본 행 식별정보**를 붙입니다. 두 문서는 서로 다른 문서 키로 저장합니다. 원본 행 번호와 엑셀 출처를 화면에서 확인할 수 있습니다.
- 신청서와 정산서를 같은 행에서 만들었더라도 자동으로 매칭하지 않습니다. 담당자가 각각 1건씩 선택·확인해야 합니다. 서로 다른 엑셀 원본 행끼리의 잘못된 매칭은 서버에서 차단합니다.
- 개별 사용처·상세 거래가 없으므로 정산은 **합계 1건**으로 준비합니다. 사용처는 ‘원본 미기재’로 표시하고 합계 자료임을 명시합니다. 필요하면 반납·정산 화면에서 실제 명세를 보완하세요. 합계가 변경되면 기존 정산 검사를 거칩니다.
- 원본의 ‘사용횟수’는 참고값으로 보존합니다. 이를 개별 거래 명세 수로 부풀리지 않습니다. 전체 통계의 사용 횟수는 여전히 YBY 건별 명세 수 기준입니다.
- 신청일이 없으면 **지급일**, 신청자가 없으면 **실사용자**, 예정일이 없으면 **지급일**을 대체값으로 표시하고 확인 사항에 안내합니다. 정식 신청일·신청자가 있다면 엑셀에 **사용신청일·신청자** 열을 추가할 수 있습니다. 실제 불출 전에 내용을 보완하세요.
- 원본 반납일은 참고로 보존합니다. **업로드만으로 실제 카드 불출·반납·승인·회계 반영을 완료하지 않습니다.** 기존 불출/반납 확인과 YBY 결재를 거칩니다. 과거 업무를 이미 처리했다면 새로 불출·정산하지 말고 기존 이력을 먼저 확인하세요.

### 중복·충돌 검사 기준

- 엑셀에 **외부행ID** 열이 있으면 해당 지점과 그 ID를 사용합니다. 별도 건이면 ID를 서로 다르게 지정하세요.
- ID가 없으면 **지점 + 은행명 + 카드 끝자리 + 사용자 + 부서 + 지급일 + 사용목적**으로 같은 행을 판단합니다. 순번·파일명·엑셀 행 위치를 기준으로 삼지 않으므로 파일명이나 행 순서만 바꿔 재업로드해도 중복 생성되지 않습니다.
- 같은 식별정보와 같은 내용은 **중복 제외**합니다. 파일 내부 반복 행도 검사합니다.
- 같은 식별정보인데 사용금액·반납일·선택 카드 등의 내용이 다르면 **기존 자료 충돌**로 표시하고 덮어쓰지 않습니다. 기존 수신·매칭·업무 내역을 먼저 확인하세요. 처리된 정산은 기존 승인취소·정정 절차를 사용합니다.
- 같은 날 같은 사람이 같은 카드·목적으로 실제 여러 번 신청한 별도 건은 외부행ID로 구분하세요. 원본에 고유번호가 없으면 내용만으로 별도 건인지 완전히 판별할 수 없습니다.
- Oracle 문서는 기존의 **원본 고유키 + 버전**, 엑셀은 위 원본 행 기준으로 중복 검사합니다. Oracle과 엑셀의 같은 업무를 교차 수집할 때에는 공통 고유번호가 아직 없으므로 자동으로 같은 건이라고 단정하지 않습니다. 같은 업무를 두 경로로 중복 입력하지 않도록 원본을 확인하세요.

## 2. 전체·개별 수신 및 1:1 선택

외부자료 매칭의 신청서와 정산서에는 각각 **수신 구분**이 있습니다.

- **미수신**: 서버 대기함에 있으나 담당자의 수신 확인을 거치지 않은 현재 버전입니다. 체크박스로 여러 개를 고른 뒤 **선택 수신**, 또는 **미수신 전체 수신**을 누릅니다. 전체 수신은 현재 검색 페이지만이 아니라 권한 범위의 미수신 전체가 대상이며 최대 5,000건입니다.
- **수신 완료 · 미매칭**: 수신 확인을 마쳤고 아직 매칭되지 않은 자료입니다. 신청서와 정산서를 각각 라디오 버튼으로 **정확히 1건씩** 선택합니다.
- **신청서 0/1 · 정산서 0/1** 표시로 선택 상태를 확인합니다. 한쪽 목록이 1건뿐이어도 자동 선택하지 않습니다. 둘 다 1/1이고 같은 사용 건 확인란을 체크해야 저장합니다.
- 금액이 없는 행처럼 신청서만 있으면 정산서가 수신되기 전에는 매칭을 완료하지 않습니다. 0원 정산서를 대신 만들지 않습니다.
- 같은 문서의 같은 버전은 수신 확인을 한 번만 기록합니다. 다시 눌러도 중복 수신되지 않습니다. 새 원본 버전은 새 확인 대상입니다.
- 기존 V4.1.15의 미매칭 자료도 이 화면에서 수신 확인할 수 있습니다. 과거 수신 시각·업무 내역은 지우지 않습니다.

**매칭 후 두 문서는 새 문서 후보와 불출·정산의 외부 수신목록에서 제외합니다.** 원문을 삭제하는 것이 아니며 하단 **연결된 신청서 → 정산서**에서 불출 준비·반납/정산·내용·이력을 계속 이용합니다. 매칭한 자료를 처리할 때는 이 연결 목록에서 시작하세요. 다른 담당자가 매칭했다면 새 후보로 중복 처리하지 않습니다.

저장 전에는 비밀번호·사유를 확인해 매칭 수정/해제를 할 수 있습니다. 해제하면 다시 미매칭 후보로 돌아오지만 원문을 새로 복제하지 않습니다. 반납·정산 저장 후에는 기존 정정 절차를 사용합니다. 외부 결재와 YBY 결재는 별도입니다.

## 3. 법인카드 등록 목록 정리·다운로드

기존에는 신용/체크·사용 범위 데이터 2칸이 추가된 상태에서 제목 2칸이 빠져, 카드사 이후 제목과 값이 어긋나 보였습니다.

- 화면과 표의 명칭을 정리하고 **번호 → 소속 지점 → 카드사 → 카드번호 → 신용/체크 → 사용 범위 → 사용자 구분 → 지정 사용자 → 카드 별칭 → 발급일 → 만료일 → 만료 잔여일 → 현재 상태 → 관리** 순서로 일치시켰습니다.
- 지점·카드사·카드번호 순으로 정렬하며 검색과 지점 필터를 제공합니다. 번호는 현재 조회 결과의 순번입니다. 수정·삭제는 기존 카드 ID로 처리합니다.
- **엑셀 다운로드**는 현재 검색/지점 조건과 권한 범위를 적용한 실제 XLSX 파일입니다. 엑셀에는 전체 카드번호가 들어갑니다. 관리 비밀값/KEY는 출력하지 않습니다.
- **보고서 / PDF → 인쇄 / PDF 저장**으로 조회한 목록을 문서로 저장합니다. 화면·PDF의 카드번호는 끝자리로 표시합니다.
- 등록 입력폼도 화면 폭에 맞춰 정리하고 사용하지 않는 비활성 KEY 입력칸을 없앴습니다. 기존 업무 자료의 비밀값을 새로 저장하거나 변경하는 작업은 아닙니다.

## 검증과 적용 범위

실제 첨부 Book1.xlsx의 제목 행과 4개 업무 행을 읽어 금액 있는 1행/없는 3행을 구분했습니다. 실제 회사 문서·개인정보는 배포 패키지에 포함하지 않았습니다. 검증용 별도 자료로 업로드·수신·매칭·불출·반납·정산·목록 출력·기존 버전 업데이트를 시험했습니다.

상세 결과는 **VALIDATION_V4_1_16.md**를 참조하세요. 실제 Oracle 접속은 담당자 SQL/뷰·컬럼·접근 권한 자료 대기 상태입니다. 이번 수신 확인은 YBY 서버 대기함 기준이며 Oracle 서버를 직접 조회하는 기능으로 표시하지 않습니다. 회사 Windows/Edge/WebView2·회사 인증서·방화벽은 회사 PC에서 최종 확인이 필요합니다.
