# YBY V4.1.12 업데이트 및 사용 안내

작성일: 2026-10-20 (한국시간)

## 법인카드 구분 추가

법인카드 등록/수정/삭제의 소속지점 옆에 **신용/체크**, **국내전용/해외겸용**을 추가했습니다. 등록·수정·등록 카드 리스트에 반영됩니다. 기존 카드에 해당 정보가 없으면 **미기록**으로 표시하며 신용카드나 국내전용으로 임의 추정하지 않습니다. 정보를 확인한 뒤 수정 화면에서 지정하세요.

## 하이패스 카드 관리 메뉴

1. **지역별 배부·사용현황**: 지점/사용분류/사용자·차량·카드번호 조건으로 묶음 수, 확인대기, 배부·사용중, 회수완료, 하이패스 수, 유류대카드 수와 지점별 사용자·차량 배부 상태를 봅니다. 법인카드 불출과 다른 기존 차량 배부 정보 기준이며, 별도 대여·정산 결재를 자동 생성하지 않습니다.
2. **하이패스 관리**: 종전 ‘하이패스 등록/수정/관리’ 화면입니다. 등록·전체 정보 수정·삭제·미리보기·확인을 수행합니다.
3. **하이패스 리스트**: 종전 ‘하이패스 문서함’ 위치입니다. 확인을 마친 묶음과 기존 자료의 현재 정보를 보여줍니다. 한 묶음 안에 하이패스·유류대카드가 함께 보입니다. 실제 카드번호·발급사는 각각 독립적입니다.
4. **등록·변경 이력**: 하이패스 메뉴 맨 아래에 분리했습니다. 등록·확인·수정·삭제의 처리자/일시/사유와 당시 변경 전·후 문서를 열람·인쇄/PDF 저장합니다. 기존 버전 이력은 당시 저장된 정보만 보여주고, 없던 변경 전 정보를 만들어내지 않습니다.

기존 하이패스 관리/리스트 권한을 가진 사용자는 새 현황·이력 화면도 사용할 수 있습니다. 관리자 권한 설정에는 현황·이력만 별도로 부여할 수 있는 항목도 추가했습니다. 서버가 지점 범위를 제한하며 다른 지점의 카드·변경 문서·엑셀은 조회할 수 없습니다. 최고관리자는 전체 지점을 조회합니다.

## 하이패스와 유류대카드 한 묶음 등록

- 등록 카드 선택에서 **하이패스**, **유류대카드**를 체크합니다. 한 종류만 등록하거나 둘 다 등록할 수 있습니다.
- 공통 정보: 소속지점, **임원/직원/직영승무원/업무용차량/기타**, 실사용자, 차량번호, 회수일, 불출지역, 운행노선, 등록·사용 사유를 입력합니다.
- 하이패스: 선불/후불, 발급사, 카드번호, 발급일, 만료일을 입력합니다.
- 유류대카드: 신용/체크, 국내전용/해외겸용, 발급사, 별도 카드번호, 지정/비지정, 지정 사용자, 발급일, 만료일, 카드 특정명을 입력합니다. 같은 묶음의 공통 지점·차량·실사용자 정보를 공유합니다. 회수일도 묶음 공통 정보입니다.
- **등록 · 미리보기**를 누르면 서버에 **확인대기**로 저장하고 입력 정보 미리보기를 엽니다. 아직 하이패스 리스트에는 나오지 않습니다.
- 내용이 맞으면 **정보 확인 · 리스트 반영**을 누릅니다. 확인완료로 바뀌고 하이패스 리스트로 이동합니다. 미리보기 창을 닫아도 하단 등록 리스트에 확인대기 자료가 남으며 다시 미리보기·확인할 수 있습니다.
- 기존 하이패스에 유류대카드를 추가하려면 **그 하이패스의 수정**에서 유류대카드를 체크해 입력하세요. 동일 차량/사용자로 따로 등록된 자료를 자동으로 합치지는 않습니다. 묶음 ID로 연결하므로 이름·차량번호가 같아도 서로 다른 묶음을 잘못 합치지 않습니다.
- 유류대카드를 법인카드 불출 관리에 자동으로 복제하거나 대여 처리하지 않습니다. 이번 기능은 하이패스·유류대의 차량 배부 묶음 관리입니다.

## 전체 정보 수정·삭제

1. 하이패스 관리 하단 등록 리스트의 **수정**을 누릅니다.
2. 하이패스/유류대카드 선택 체크와 **전체 입력창**이 열립니다. 소속지점은 최고관리자만 바꿀 수 있고 일반 담당자는 자기 지점으로 고정됩니다.
3. 필요한 내용을 바꾸고 **수정 사유**, **현재 로그인 계정의 비밀번호**를 입력하여 변경 저장을 누릅니다. 잘못된 비밀번호, 사유 누락, 중복 카드번호, 잘못된 날짜 등은 저장을 막습니다.
4. 수정하면 다시 **확인대기**가 되어 하이패스 리스트에서 잠시 제외됩니다. 저장된 변경 정보를 다시 미리보고 **정보 확인 · 리스트 반영**을 눌러 반영하세요. 확인대기 상태는 자료 삭제를 뜻하지 않습니다.
5. 변경 전·후 정보, 사유, 처리자, 시각이 별도 변경 이력에 보존됩니다. 지점 이관 시에는 이전/새 지점에 각 지점 자료만 보이도록 나눠 보관합니다. 삭제도 로그인 비밀번호와 사유가 필요하고, 삭제 전 정보와 이력은 유지됩니다.
6. 동시에 다른 사용자가 수정/확인했다면 최신 내용을 다시 열어 확인해야 합니다. 오래 열어 둔 창의 정보로 덮어쓰지 않습니다.

## 조회·엑셀·기존 자료

- 관리/리스트/현황/이력의 필터를 적용한 뒤 **엑셀 다운로드**를 누르면 실제 .xlsx 파일로 받습니다. 하이패스와 유류대는 동일 묶음ID로 이어지는 두 행으로 저장되므로 Excel에서도 같은 묶음을 확인할 수 있습니다. 리스트는 확인대기 자료를 제외하며, 관리·현황은 확인대기를 포함합니다.
- 이력 엑셀은 작업·일시·처리자·사유와 처리 후 정보(삭제는 삭제 전 정보)를 보관합니다. 전체 변경 전·후 정보는 이력의 변경 문서에서 확인하거나 PDF로 저장하세요.
- 기존 자료는 원래의 카드·이력을 보존하고 **미분류**, **기존자료 · 확인미기록**으로 구분합니다. 기존 자료는 리스트에 계속 표시합니다. 필요한 항목을 보완·수정한 뒤 새 확인 절차를 거칠 수 있습니다. 오래된 자료에 필수 날짜 등이 없으면 먼저 수정에서 보완하세요.
- 하이패스/유류대 번호는 공백·하이픈을 제외해 중복 검사합니다. 기존 카드번호를 카드 종류와 지점만 바꿔 중복 등록하지 마세요.
- 비밀번호는 변경 문서·엑셀·업무 이력에 저장하지 않습니다. 로그인 계정의 비밀번호이며 초기 비밀번호나 다른 담당자 비밀번호를 입력하는 곳이 아닙니다.

## 기존 서버 업데이트

1. 현재 최고관리자 계정으로 **시스템 관리 → 권한 & 비밀번호 관리 → 전체 백업 만들기**를 실행합니다. Ctrl+J에서 ZIP 다운로드 완료를 확인하여 별도 보관합니다. 상단 데이터 백업(JSON)과 구별하세요.
2. 다른 사용자가 작업하지 않는 시간에 서버 실행창에서 **Ctrl+C** 또는 STOP_SERVER.bat로 종료합니다.
3. 새 V4.1.12 전체 ZIP을 새로운 폴더에 완전히 압축 해제하고 **기존 서버와 같은 Windows 계정**으로 **RUN_LAN_WINDOWS.bat**를 실행합니다.
4. `%LOCALAPPDATA%\YBY\app`의 계정·DB·첨부·인증서·사내망 설정을 유지하며 프로그램을 갱신합니다. 정상 업데이트에는 업무 백업 ZIP을 복원하거나 압축 해제할 필요가 없습니다.
5. 화면 버전 V4.1.12와 기존 자료를 먼저 확인하세요. 이전 화면이 남으면 브라우저 Ctrl+F5 또는 로그인 전용창을 닫고 CONNECT_SERVER.bat로 다시 여세요. 서버 실행창은 계속 열어 둡니다.

DB 스키마는 6을 유지합니다. 새 묶음 자료를 구버전으로 다루는 것은 지원하지 않으므로 되돌려야 한다면 업데이트 전 전체 백업과 이전 프로그램을 함께 사용하세요. 이번 버전에서 인증서/네트워크/메신저/보고서 결재 방식은 변경하지 않았습니다. Oracle 실제 연결은 기존처럼 DB 담당자 자료를 기다리고 있습니다.

검증 결과는 VALIDATION_V4_1_12.md를 참고하세요. 회사 Windows PC·실제 인증서/방화벽 정책은 별도로 최종 확인이 필요합니다.
