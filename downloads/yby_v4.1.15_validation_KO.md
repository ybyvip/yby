# YBY V4.1.15 검증 결과

검증일: 2026-10-20 (한국시간). 기준 소스: V4.1.14. DB 스키마 7.

## 자동 검증

- Python 서버 **274개 통과** (124.871초, 실패/스킵 없음). 기존 256개와 신규 외부자료 매칭 18개입니다.
- Node **24개 통과**, 실패/스킵 없음. 기존 이력 집계 12개와 신규 전체 통계 12개입니다. 서로 다른 자동 검증 총 **298개**입니다. 반복 실행 건수는 합계에 더하지 않았습니다.
- 서버 매칭 검증: 두 문서 명시적 확인·1:1 연결, 같은 지점/문서 종류/카드/원문 버전 검사, 중복 연결 차단, 변경 사유·로그인 비밀번호·동시 수정 버전 검사, 해제 후 원문과 변경 이력 보존, 타 지점 목록·조회 건수·이력 비노출, 익명·단순 조회 계정 차단을 확인했습니다.
- 실제 신청서 원문 키·불출 이벤트 ID·지점·카드번호를 기준으로 하나의 반납과 정산에 연결하는지 확인했습니다. 같은 끝자리 또는 다른 불출 회차로 바꿔 적용하지 못하며, 매칭된 정산서 대신 수동 정산 또는 다른 정산서를 적용하는 것도 차단합니다. 미사용 반납은 기존 흐름을 유지합니다.
- 원문 갱신·회수 및 매칭 버전 변경 후 재확인, 처리 후 매칭 수정·해제 잠금, 기존 승인취소·정정에서 원문 연결 보존, 일반 상태 저장으로 재무 연결정보 위조 차단, DB 오류 시 매칭·이력·업무 저장 원자적 롤백을 검증했습니다.
- 전체 백업 ZIP 복원 후 매칭과 매칭 변경 이력 및 스키마 7이 복구되는지 확인했습니다. 업데이트 전 백업 오류가 나면 DB 스키마 변경을 시작하지 않는 것도 검증했습니다.
- 통계는 네 차원별 합계 일치, 정산 대기/반려/승인취소/과거 마이너스 정정 제외, 신청 목록·이력 중복 제거, 지점 범위 제한, 동명 사용자 지점 구분, 카드·카드사 필터, 명세 수와 수량 구분, 같은 기준월/비교월, 비교월에만 존재하는 항목, 옛 쉼표 금액, 잘못된 금액, 복합 목적 중복 합산 방지를 확인했습니다.

## 실제 Chromium 기능 확인

1. 사용 정산 및 결재의 독립 입력창이 제거되고 반납과 동일한 외부 정산서 수신 목록이 표시됨을 확인했습니다.
2. 신청서와 잘못 선택한 정산서를 연결 → 실제 카드 불출 → 처리 전 매칭 수정(오류 비밀번호 차단/올바른 비밀번호 저장) → 변경 전·후 문서 이력을 실제 화면으로 확인했습니다.
3. 정산 화면의 수신 문서 선택 → 연결된 정확한 불출 건 반납 화면 → 정산 내역 확인 → 반납·정산 저장 → 정산 1건 생성과 신청서·정산서 원문 연결 보존 → 매칭 잠금 → 별도 YBY 승인을 실행했습니다.
4. 전체 통계에서 관리자 12,000원/서울 지점 5,000원을 시험 자료와 대조했습니다. 취소 9,000원과 옛 마이너스 정정은 중복 포함되지 않습니다. 네 가지 요약과 통합 3행을 확인했습니다.
5. 실제 XLSX 파일을 내려받아 네 차원과 통합 내역을 검사했습니다. 통계 인쇄의 고정 높이·스크롤 잘림을 수정한 뒤 실제 PDF를 생성해 제목·네 가지 요약·통합 비교표·사용자·총액 텍스트가 모두 존재하는지 확인했습니다.
6. 하이패스 최종 대기중/불출중 배경의 실제 계산 색상이 서로 다르고 상태 문구도 남는지 확인했습니다. 1600/1024/768/390/320px의 매칭·통계 가로 넘침과 지점 제한, JavaScript 실행 오류 없음을 확인했습니다. 화면 캡처를 시각 점검했습니다.

## 회귀·업데이트

- 기본 화면: 보고서 작성/승인, 저장 오류 시 입력 보존, 실제 XLSX 및 비밀번호 재확인 전체 백업 ZIP 다운로드, 하이패스·민원·공지·메모·메신저 저장, 모바일·키보드 동작 통과.
- V4.1.14 하이패스 임시저장 → 재로그인 → 대기중 하단 보관 → 불출 확정 → 리스트 수정 → 회수중 하단 이동 → 비밀번호/날짜 확인 후 회수완료, 여섯 지표 상세·카드 개수·엑셀, 실제 변경 전/후 문서·PDF, 마지막 이력만 현재 상태 통과.
- V4.1.13 카드 구분·두 카드 묶음·확인·수정·삭제 문서·유류대 대시보드·권한·바로가기 회귀 통과. 새 매칭 화면을 포함한 바로가기 선택 항목은 18개입니다. 이전 검증의 선택 항목 수만 새 화면에 맞춰 조정했습니다.
- V4.1.11 외부 수신함 → 불출 → 반납 → 보고서 초안, 본인 1차 검토 및 최고관리자 본인 최종 승인, 정산과 보고서 별도 결재, 반납 시 불출완료 표기·실제 엑셀 통과.
- **실제 V4.1.14 → V4.1.15 프로그램 교체·기동·로그인**: 시작 전 DB 바이트 동일, 기존 카드·불출반납·정산·계정·보고서·첨부·하이패스/유류대 자료·과거 변경 스냅샷·수신 문서와 적용 연결 보존을 확인했습니다. 스키마 6→7에 빈 매칭 테이블만 추가되며 임의 매칭을 만들지 않습니다.
- 실제 시작 시 생성한 **업데이트 전 전체 백업**을 열어 스키마 6과 기존 외부 문서 적용 연결이 담겨 있음을 확인했습니다.
- 읽기 전용 한글 경로 원본 → 사용자 전용 실행 위치 설치 → 실제 기동/로그인/업무 저장, 중복 실행 같은 PID, 재설치 자료 보존 통과.
- CA·개인키·LAN 설정 보존은 시험 파일 바이트 비교이며 실제 회사 인증서를 실행한 검사는 아닙니다.

## 배포 검증과 한계

최종 ZIP CRC/파일별 SHA-256/추출본 설치 무결성, Python 3.11 구문, JavaScript 구문을 검사합니다. PowerShell 파일은 기존 V4.1.14와 바이트 동일 및 UTF-8 BOM을 검사합니다. 명시된 배포 파일 목록을 사용해 운영 DB·개인키·로그·실제 회사 문서·수신 시험 자료를 제외합니다. 게시 후 실제 다운로드 URL에서 GET 200과 파일 해시·ZIP 내부 파일 해시를 다시 확인합니다.

회사 Windows/Edge/WebView2, 실제 인증서 등록·방화벽 정책, 실제 Oracle DB는 이 클라우드에서 실행하지 않았습니다. Oracle 조회 SQL/뷰·컬럼·접속 권한 자료 대기 상태이며 현재는 YBY 서버에 정규화되어 저장된 수신함의 매칭·조회·처리 검증입니다. 회사 PC에서 최종 실행 확인이 필요합니다.
