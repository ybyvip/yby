# YBY V4.1.14 업데이트·사용 안내

작성일: 2026-10-20 (한국시간). 기준 버전: V4.1.13.

## 업데이트 방법

1. 최고관리자로 **시스템 관리 → 권한 & 비밀번호 관리 → 전체 백업 만들기**를 실행하고 현재 로그인 비밀번호로 확인합니다. Ctrl+J에서 ZIP 다운로드 완료를 확인해 별도 보관하세요. 상단 ‘데이터 백업’ JSON과 구별합니다.
2. 다른 담당자가 작업하지 않는 시간에 기존 서버 실행창에서 **Ctrl+C**로 종료합니다.
3. V4.1.14 전체 ZIP을 **새 폴더에 완전히 압축 해제**하고 기존 서버와 **같은 Windows 계정**으로 **RUN_LAN_WINDOWS.bat**를 실행합니다.
4. `%LOCALAPPDATA%\YBY\app`의 업무 DB·계정·첨부·인증서·사내망 설정을 유지하며 프로그램을 교체합니다. 정상 업데이트에는 백업 ZIP을 복원할 필요가 없습니다.
5. 상단 **V4.1.14**와 기존 자료를 확인하세요. 이전 화면이 남으면 Ctrl+F5 또는 창을 닫고 CONNECT_SERVER.bat로 다시 엽니다. 서버 실행창은 계속 열어 둡니다.

서버 PC 주소는 `https://localhost:5000`, 다른 PC는 기존 서버 IP가 그대로라면 `https://10.10.0.121:5000`입니다. DB 스키마는 6을 유지합니다. 기존 원본 업무 자료와 과거 변경 문서를 임의로 다시 작성하지 않습니다.

## 1. 지역별 지표 — 클릭해서 상세 조회

지표 순서를 **불출중 → 등록 묶음 → 확인대기 → 회수중·완료 → 하이패스 카드 → 유류대카드**로 정리했습니다. 각 박스를 클릭하면 해당 지점·분류·검색 조건의 상세 표를 열고 엑셀/인쇄/PDF로 받을 수 있습니다. 지표 상세는 창을 연 시점의 자료입니다.

| 지표 | 집계 기준 |
|---|---|
| 불출중 | 입력 확인을 마친 불출중 묶음. 확인 전 임시저장/불출 준비는 제외 |
| 등록 묶음 | 현재 저장된 모든 등록 건. 임시저장·대기·불출·회수중·회수완료 포함 |
| 확인대기 | 입력 확인 전 자료. 임시저장 포함 |
| 회수중·완료 | 회수중/기존 회수예정/회수완료 묶음 |
| 하이패스 카드 | 하이패스 선택 + 번호가 입력된 현재 등록 카드 수. 대기/회수/임시저장 포함 |
| 유류대카드 | 유류대 선택 + 번호가 입력된 현재 등록 카드 수. 대기/회수/임시저장 포함 |

**등록 묶음은 ‘두 카드를 동시에 쓰는 사람 수’가 아닙니다.** 한 묶음에 하이패스만 있거나 유류대만 있어도 1건, 두 카드가 함께 있어도 1건입니다. 이름이 같아도 별도 등록하면 각각 1건이며 사람 수를 중복 제거한 지표가 아닙니다. 삭제한 묶음은 제외하며 삭제 이력은 유지합니다.

예: 하이패스 단독 1건 + 유류대 단독 1건 + 두 카드 함께 1건 = **등록 3묶음 / 하이패스 2개 / 유류대 2개**입니다. 등록 묶음 상세 상단에서 이 세 종류의 건수를 바로 확인할 수 있습니다. 예전 버전은 카드 수량에서 확인대기를 제외해 등록 묶음과 비교하기 어려웠으므로, 이번에는 번호가 입력된 전체 현재 등록 카드 기준으로 통일하고 기준을 화면에 표시했습니다. 미입력 번호는 카드 수에 넣지 않습니다.

## 2. 임시저장과 대기중 보관

- 새 등록의 배부 상태는 **대기중 / 불출중** 두 가지만 선택합니다. 회수중/회수완료는 새 등록에서 선택할 수 없습니다.
- **임시저장**은 작성 도중 누를 수 있습니다. 사용자·차량·카드 정보 중 한 항목 이상 있어야 하며, 모든 입력칸이 빈 새 자료는 저장하지 않습니다. 필수 정보를 아직 다 쓰지 않아도 저장하지만 입력된 날짜·분류·중복 카드번호는 검사합니다.
- 임시저장한 자료는 **하단 업무대기 목록**에 남습니다. 화면을 닫고 다시 로그인해도 유지됩니다. ‘불출중’을 선택해 임시저장했더라도 불출을 확정하지 않습니다.
- 하단 **이어서 작성**을 눌러 내용을 보완하세요. 기존 자료를 수정할 때는 **현재 로그인 비밀번호와 수정 사유**가 필요합니다. 작성 중 다시 임시저장할 수 있습니다.
- 입력을 마쳤으면 **변경 저장**으로 미리보기를 엽니다. 신규 화면에서는 **입력 저장 · 미리보기**를 사용합니다.
- **대기중**은 모든 내용을 입력해 저장해도 하단에 보관하며 다음 단계로 넘기지 않습니다. 미리보기에도 불출 확정 버튼을 표시하지 않고 서버에서도 확정을 거부합니다.
- 실제 배부할 때는 **불출중**으로 바꾸어 변경 저장한 뒤 **정보 확인 · 불출 확정**을 누릅니다. 그때 하단에서 빠지고 **하이패스 리스트**로 이동합니다. 임시저장은 먼저 필수 입력을 완료해야 확정할 수 있습니다.

## 3. 리스트 수정과 회수 흐름

| 처리 | 자료가 표시되는 곳 |
|---|---|
| 임시저장 / 대기중 | 하이패스 관리 하단 업무대기 목록 |
| 불출중 선택, 아직 입력 확인 전 | 하단 업무대기 목록 |
| 불출중 입력 확인·불출 확정 | 하이패스 리스트 |
| 리스트에서 회수중으로 변경 저장 | 하단 업무대기 목록 — 최종 회수 대기 |
| 실제 회수를 마쳐 회수완료 처리 | 하이패스 리스트 — 회수완료 기록 |

1. **하이패스 리스트 → 수정**에서 불출중인 자료는 불출중/회수중/회수완료를 선택할 수 있습니다.
2. **회수중**으로 바꾸어 사유·로그인 비밀번호를 입력하고 변경 저장하면 즉시 하단 업무대기 목록으로 이동합니다. 별도 불출 확정 절차를 반복하지 않습니다.
3. 실물 카드가 돌아오면 하단의 **최종 회수**를 누릅니다. **실제 회수일 / 회수 확인 사유 / 현재 로그인 비밀번호**를 입력하고 **회수완료 처리**를 누릅니다. 해당 묶음의 하이패스·유류대 전체 회수를 뜻합니다.
4. 회수완료 자료는 하단에서 빠지고 리스트에 **회수완료**로 남습니다. 실제 회수일은 필수이며 오늘 이후 날짜로 완료 처리할 수 없습니다.
5. 리스트 수정에서 실물 회수를 이미 마쳤다면 회수완료를 직접 선택할 수도 있습니다. 동일한 날짜·사유·비밀번호 검사를 거칩니다.
6. 회수완료 카드를 다시 배부하려면 수정에서 대기중/불출중으로 바꾸고 **이전 회수일을 비워** 새 준비를 합니다. 다시 불출하려면 입력 확인을 거칩니다.

허용 이동은 다음과 같습니다. 화면 선택과 별도로 서버에서도 검사합니다.

- 대기중 → 대기중 / 불출중
- 불출중 → 불출중 / 회수중 / 회수완료
- 회수중 → 회수중 / 회수완료
- 회수완료 → 회수완료 / 대기중 / 불출중 (재준비 시 이전 회수일 삭제)

불출 전 자료를 회수중으로 넘기거나 불출중을 곧바로 대기중으로 바꾸는 등의 이동은 차단합니다. 이미 불출한 자료는 임시저장 대신 비밀번호·사유를 확인하는 변경 저장으로 처리합니다. 동시에 다른 담당자가 수정했다면 최신 자료를 다시 열어야 합니다.

기존 V4.1.13의 대기중/회수중 자료도 이 표시 규칙에 따라 하단에서 찾을 수 있습니다. 원본 상태를 강제로 바꾸지 않고 표시 위치를 정리합니다. 예전 자료에 명시적 배부 상태가 없으면 기존 회수일/확인상태/사용자 정보로 표시하던 규칙을 유지합니다. 미래 회수일만 기록된 기존 ‘회수예정’ 자료는 회수 업무대기로 분류합니다.

## 4. 변경 전·후 문서 보완

기존의 **정보수정** 이력은 실제 입력 변경 전·후를 보관하지만 그다음 생성되는 **정보확인** 이력은 확인 상태만 바꾸므로, 두 문서의 입력값이 같아 보일 수 있었습니다.

- 정보수정 문서는 당시의 변경 전·후 자료를 표시합니다.
- 그 뒤 정보확인 문서를 열어도 **연결된 정보수정 문서의 실제 입력 변경 전·후**를 보여줍니다. 연결 문서번호와 수정 사유를 함께 표시합니다.
- V4.1.13 확인 이력에도 버전 연결 정보가 있으면 같은 방식으로 연결해 표시합니다. 연결 근거가 없는 옛 기록은 추정해 만들지 않고 당시 기록만 표시합니다.
- 바뀐 항목의 **변경 전은 연한 황색**, **변경 후는 연한 녹색**으로 두 칸 모두 음영 처리합니다. 바뀌지 않은 값은 기본 배경으로 유지합니다. 차량번호·발급사·카드번호·날짜 등 실제 입력값 비교에 적용합니다.
- 원래 감사 이력의 전·후 스냅샷은 보존합니다. 화면에서 관련 수정 문서를 연결하는 것이며 과거 기록을 덮어쓰지 않습니다. 비교표는 인쇄/PDF 저장할 수 있습니다.

## 5. 일련번호와 최종 현재상태

- 등록·변경 이력에 **일련번호**를 추가했습니다. 새 이력은 서버에서 번호를 발급하고 검색 조건을 바꿔도 번호가 유지됩니다. 이전 번호가 없던 기록은 원래 순서에 따른 번호를 표시하며 과거 원본을 재작성하지 않습니다.
- 같은 등록 묶음의 **마지막 이력 한 행에만** 대기중/불출중/회수중/회수완료 등 현재 상태를 표시합니다. 삭제/이관도 구분합니다.
- 지나간 행은 **등록 완료 / 변경 완료 / 확인 완료 / 회수처리 완료** 등 당시 작업 완료로 표시합니다. ‘과거 작업 완료’와 ‘최종 이력 · 현재 상태’를 구분합니다. 과거의 ‘변경 완료’는 현재 실물 회수가 완료됐다는 뜻이 아닙니다.
- 필터로 과거 행만 조회해도 그 행에 현재 상태를 반복 표시하지 않습니다. 최신 이력은 전체 권한 범위의 같은 묶음 이력을 기준으로 판단합니다.
- 이력 엑셀에도 일련번호와 동일한 상태 기준을 적용합니다. 하단/리스트 엑셀도 현재 화면의 이동 규칙을 따릅니다.

## 권한·보존·검증 범위

최고관리자는 전체 지점을, 지점 담당자는 자기 지점 자료만 조회·처리·다운로드합니다. 수정·삭제·최종 회수는 현재 로그인 비밀번호와 사유가 필요하며 비밀번호를 업무 문서/엑셀에 저장하지 않습니다. 읽기 전용 담당자의 변경은 서버에서도 차단합니다. 오류가 나면 업무 자료와 변경 이력을 함께 되돌려 중간 상태가 남지 않도록 처리합니다.

검증 결과는 동봉된 **VALIDATION_V4_1_14.md** 및 별도 검증 결과 다운로드를 참조하세요. 회사 Windows/Edge/WebView2, 실제 인증서·방화벽 정책과 실제 Oracle 접속은 이 클라우드에서 실행하지 않았으므로 회사 PC에서 최종 확인이 필요합니다. Oracle 연동은 담당자 자료 대기 상태를 유지합니다.
