## 추가 서버 검증의 주요 항목

음수·누락·미등록 카드 정산 거부, 임의 카드 상태/직접 불출 거부, 반납·정산의 원자성, DB 실패의 전체 롤백, 응답 재시도 중복 방지, 동시 불출 한 건만 성공, 동일 상태/revision, 변경 없는 조회의 데이터 재구성 생략, 사용자 활동/절대 세션 만료, 보조 파일 실패와 실제 DB 결과의 일치, 비밀번호 및 권한 변경의 DB 롤백, 변경 성공 후 세션 폐기, 인증 중 비밀번호 변경 경합, 개인 대화/메모 보호, KEY 비노출, 정산 첨부의 현재 권한 재검사, 실제 2단계 결재, 본인 승인 거부, 원본 보존 정산 정정, 부분 저장의 다른 자료 보존, 관리자 권한 부여 재인증, 서버 등록 ID·지점, 전체 백업/복원과 악성 경로 거부, 정상 구형 DB 이전과 손상·미래 버전 원본 보존, OS DB 잠금, 업무 감사, 페이지 검색과 작업자 제한을 포함합니다.

장애 주입 검증에서 예상된 ERROR 로그가 발생할 수 있습니다. 이것은 의도적으로 실패 조건을 만든 것이며, 통과 여부는 unittest의 결과와 실제 DB·세션·응답 검증으로 판단했습니다. 로그의 ERROR 문자열만으로 테스트 실패라고 해석하지 마세요.

## 최종 배포 ZIP 확인

배포 파일은 새 임시 폴더에 다시 풀어 일반 Python으로 RUN_LINUX.sh를 실행하고, 버전·DB·로그인·최초 변경 강제·카드 불출/반납·정산·전체 백업·CLI 검증·정확한 서버 종료·재시작과 자료 보존을 확인했습니다. 배포 ZIP의 압축 CRC와 전체 파일 체크섬도 확인했습니다. 이 최종 확인 결과는 별도 배포 검증 요약에 함께 기록합니다.

## 미검증 또는 추가 작업 대상

- 실제 Windows BAT·PowerShell 종료·Edge·Excel 데스크톱 실행. CI 예시를 포함했지만 Windows CI 실행 완료를 주장하지 않습니다.
- 고객의 실제 업무 DB·첨부·키를 사용한 이전·복원. 제공된 ZIP에는 실제 DB가 없었습니다.
- 실제 사내 CA·방화벽·다른 PC·VPN·프록시 환경.
- 장시간 운영, 장애 복구 훈련, 회사별 성능·복구 목표 달성.
- 스크린리더·모바일 전 기능·접근성 표준 인증.
- 카드사·은행·ERP·SSO/MFA·악성 파일 검사 서비스, 회사별 마감·대리승인 정책.

이 기록은 검증한 범위의 결과이며 “모든 PC와 모든 업무 자료에서 검증이 끝났다”는 보증이 아닙니다. 실제 업무 전 원본 보관 및 현장 이전 확인이 필요합니다.
