# YBY V4.1.11 업데이트·사용 안내

작성일: 2026-10-19 (한국시간)

## 화면 간소화

- 불출 화면의 **신청 자료 출처** 영역과 중복 **외부 신청서 선택** 버튼을 제거했습니다. 상단 **외부 신청서 수신 목록 → 지금 갱신**, 각 문서의 **선택·확인**을 사용하세요. 자동 10초 갱신은 유지합니다.
- 신청일부터 반납예정일까지 여섯 입력란의 글자·높이·여백을 줄였습니다. 넓은 화면(1500px 이상)은 한 줄, 중간 화면은 3/2열, 작은 화면은 1열로 배치합니다. 실제 사용자와 신청자는 계속 따로 입력할 수 있습니다.
- 반납창의 **정산 자료 출처** 영역과 중복 **외부 정산서 선택·확인** 버튼도 제거했습니다. 해당 카드의 **외부 정산서 수신 목록**에서 직접 선택합니다. 검색·상태 필터는 펼칠 때만 표시하고, 한 페이지에 들어오는 목록의 불필요한 이전/다음 버튼을 숨겼습니다. 마지막 수신함 확인 시각, 적용·미적용 수, 원문 외부 결재 상태를 유지합니다.
- 수신 문서를 선택하면 목록 안에 선택 문서와 **선택 해제**만 간단히 표시합니다. 선택 해제는 원본 연결을 풀고 입력값은 유지합니다. 최종 저장 전에는 계속 미적용입니다. 이미 적용한 문서나 갱신·회수된 문서의 중복 적용을 막습니다.

## 보고서 본인 검토·최고관리자 최종 결재

1. 사용함 반납에서 **반납·정산 저장 후 관련 보고서 초안 열기**를 체크하고 저장하면 기존처럼 보고서 초안을 엽니다. 정산 상세의 **관련 보고서 초안 작성**으로도 열 수 있습니다.
2. **1차 검토자**는 기본적으로 현재 로그인한 본인입니다. 본인 검토를 선택하고 **결재 기안 상신**을 누르면 서버가 ‘기안 상신 시 본인 검토 완료’를 1차 검토 이력에 기록하고 **최종 결재대기**로 보냅니다. 별도로 본인 검토 버튼을 다시 누를 필요가 없습니다. 다른 검토자를 지정한 경우에는 기존 1차 검토 단계를 거칩니다.
3. **최종 승인자**는 최고관리자 계정입니다. 최고관리자가 작성하면 기본 최종 승인자도 본인으로 지정합니다. 일반 사용자는 admin 최고관리자가 있으면 기본 지정하며, 최고관리자가 여러 명이고 admin 계정이 없으면 원하는 최고관리자를 선택하세요.
4. 최고관리자는 본인이 최종 승인자로 지정된 **자기 보고서도 최종 승인/반려**할 수 있습니다. **내부 보고서함 → 해당 문서 → 최종 승인**으로 처리합니다. 다른 사람이 1차 검토자로 지정되어 있으면 먼저 그 검토를 완료해야 합니다. 지정되지 않은 다른 최고관리자가 결재를 대신 처리하지는 않습니다.
5. 일반 사용자는 본인 검토까지 가능하고 최종 결재는 최고관리자만 할 수 있습니다. 최고관리자 권한이 회수되면 기존 최종 승인자로 지정되어 있어도 최종 결재할 수 없습니다. 문서 **보기**에서 1차 검토·최종 결재의 시각/계정/본인 처리 여부를 확인합니다.
6. 보고서 결재와 카드 정산 결재는 독립적입니다. 보고서를 승인해도 사용정산은 자동 승인되지 않습니다. 상신·결재 이력과 복사 원본 정산 스냅샷을 보존합니다. 이미 승인/반려한 문서를 다시 결재하지 않습니다.

## 불출/반납 이력대장

- 불출 행: 해당 불출 건에 연결된 반납이 생기는 즉시 **불출완료**로 표시합니다. 사용 여부나 정산 승인/반려/정정 상태에 따라 불출 완료 여부를 바꾸지 않습니다.
- 아직 반납하지 않은 현 불출 행: **대여중 · 반납대기**를 유지합니다.
- 반납 행: **반납완료 · 미사용**, **반납완료 · 승인대기**, **반납완료 · 승인완료** 등 실제 반납·정산 진행 상태를 유지합니다.
- 화면·엑셀·출력 보고서에 같은 계산을 적용합니다. 연결이 불확실한 과거 이력은 완료로 단정하지 않고 확인 필요로 둡니다.

## 기존 서버 업데이트

1. 최고관리자로 **시스템 관리 → 권한 & 비밀번호 관리 → 전체 백업 만들기**를 실행하고 Ctrl+J에서 ZIP 다운로드가 완전히 끝났는지 확인해 따로 보관하세요. 상단 데이터 백업(JSON)과 구별하세요.
2. 업무 중인 사용자가 없는 시간에 서버 실행창에서 **Ctrl+C** 또는 STOP_SERVER.bat로 기존 서버를 종료합니다.
3. V4.1.11 전체 ZIP을 **새 폴더에 완전히 압축 해제**합니다.
4. 기존 서버를 실행하던 **같은 Windows 계정**으로 새 폴더의 **RUN_LAN_WINDOWS.bat**를 실행합니다. 실제 실행 폴더 `%LOCALAPPDATA%\YBY\app`의 업무자료·계정·첨부·인증서·접속 설정을 유지하며 프로그램 파일만 갱신합니다. 정상 업데이트에 백업 ZIP 복원은 필요 없습니다.
5. 로그인 후 화면 버전 V4.1.11과 기존 자료를 확인하세요. 브라우저에 이전 화면이 남으면 Ctrl+F5로 새로 고침하고, 로그인 전용창은 닫았다가 CONNECT_SERVER.bat로 다시 여세요. 다른 PC도 새 화면을 불러와야 합니다. 서버 실행창은 열어 두세요.
6. 서버 PC 주소는 `https://localhost:5000`, 다른 회사 PC는 기존 서버 IP가 같을 때 `https://10.10.0.121:5000`입니다. 접속 방식·인증서 설치·방화벽 규칙은 이번 버전에서 변경하지 않았습니다.

## 메신저 화면 흐리게

- 메신저에서 **화면 흐리게**를 누르면 대화 목록·제목·메시지·첨부 미리보기·작성 중인 내용을 직접 흐리게 표시합니다. 전체 화면을 덮는 농도 선택 창은 띄우지 않습니다.
- 메신저 도구줄에 나타나는 **흐림 농도** 슬라이더(20~100%)를 움직이면 즉시 반영됩니다. 농도가 높을수록 더 강하게 흐려집니다. 도구줄과 농도 조절기는 선명하게 유지하므로 바로 조절할 수 있고, **흐림 해제**를 다시 누르면 원래 표시로 돌아옵니다.
- 일반 업무 화면은 흐려지지 않습니다. 별도 메신저 대화창에서도 같은 방식으로 적용됩니다. 화면 효과만 바꾸므로 메시지와 입력 중인 문장을 바꾸지 않습니다.
- 기존 **화면 보호** 버튼의 비밀번호 잠금은 별도 기능으로 유지합니다. 화면 흐리게는 비밀번호 잠금이 아닙니다.

## Oracle 및 검증 범위

실제 회사 Oracle DB 수집은 아직 DBA의 테이블/뷰·컬럼·조회 SQL 등을 기다리는 상태입니다. 이번 버전은 **YBY 서버 수신함 조회와 업무 처리 화면**을 개선했습니다. 실제 Oracle 자료를 수집한다고 표시하지 않습니다. 테스트 문서·회사 자료·DB 접속정보는 배포 ZIP에 넣지 않았습니다.

DB 스키마는 V4.1.10과 같은 6입니다. 최종 시험 결과는 VALIDATION_V4_1_11.md를 참고하세요. 회사 Windows PC·실제 Oracle 연결은 이 환경에서 직접 실행하지 못했으므로 사내 환경의 최종 확인이 필요합니다.
