## 사고·사용관리 저장 오류 분석

V4.1.24는 서버에서 `external_documents.short(..., required=True)`의 기본 200자 제한으로 변경 사유를 검사했습니다. 빈 값·공백 또는 200자를 넘는 값에 모두 ‘변경 사유 형식 오류’를 반환했습니다. 화면은 별도 변경 사유를 필수로 안내했지만 실제 저장 전에 필수 입력·길이를 검사하지 않았습니다. 이상징후 내용과 조치사항을 채웠더라도 **별도의 변경 사유**가 비면 이 경로로 실패했습니다.

V4.1.25에서는 변경 사유를 필수 textarea(1~1,000자)로 바꾸고 저장 전 항목별 검증을 적용했습니다. 서버도 빈 사유·초과 길이를 구체적으로 안내하며 문자열 이외 값과 누락된 접수 내용은 계속 거절합니다. 빈 사유의 실패 및 자료 불변, 200자를 넘는 여러 줄 사유의 정상 저장·이력 보존을 재현해 검사했습니다. 변경 사유를 임의로 만들거나 필수 접수 정보를 생략해 저장하지 않습니다. 운영 당시의 실제 입력값과 DB는 제공되지 않아 그 입력 자체를 재현했다고 주장하지 않습니다.

## 기간 조회·확인의 기준

- 기간은 한국 시간의 변경 발생일 기준이며 양 끝 날짜를 포함합니다. 새 버전 적용 후 주요 업무 자료의 등록·변경·삭제를 업무 저장과 같은 DB 트랜잭션에서 기록합니다. 저장 실패 때 기록도 함께 롤백됩니다.
- 대상은 공지·불출예정·불출반납·정산결재·정산이력·법인카드 관리·하이패스·민원·보고서입니다. 목록은 50건씩 페이지를 넘겨 모든 일치 내역을 확인할 수 있습니다. 이전 버전의 100건 제한을 없앴습니다.
- **적용 전 기록은 현재 남아 있는 자료와 카드 관리 이력으로 초기 구성합니다.** 이미 삭제되었거나 덮어써져 원본 이력이 없는 과거 사건은 복구할 수 없습니다. 날짜 미기록 자료는 전체 기간에서 보이고, 날짜를 정하면 제외됩니다.
- 목록은 변경 발생 요약 기록입니다. 이전 사건에서 ‘해당 업무 보기’를 누르면 현재 원문으로 연결합니다. 원문이 삭제된 경우에는 삭제된 기록 안내를 표시합니다. 예전 원문 전체를 복원해 보여주는 기능은 아닙니다.
- 업무 행 확인과 메뉴 녹색 점 확인은 별도입니다. 메뉴를 열었다고 개별 행을 모두 확인한 것으로 바꾸지 않습니다. 변경된 원문은 별도 새 행이므로 이전 행 확인이 새 변경까지 확인 처리하지 않습니다.
- 공지 열람은 공지 화면을 열어 본 기록입니다. 공지 내용이 바뀌면 새 내용 기준으로 다시 구분하고, 이전 내용의 열람 기록도 DB에서 보존합니다. 다른 계정 대신 열람 처리할 수 없습니다.
- 그래프는 담당 지점과 조회 권한 범위에서 집계합니다. 금액은 승인완료 일반 정산 중 기록된 금액 합계이며, 미기록 카드 분류는 종류별 집계에서 빠질 수 있습니다. 대여·관리 제한·만료는 서로 겹칠 수 있으므로 특이사항 수를 총보유 수와 단순 합산하지 않습니다.

## 보존 및 적용

스키마는 12→13입니다. 업무 발생 요약, 건별 확인, 공지 내용별 열람 기록을 별도 테이블에 저장하고 표시 설정은 기존 계정별 설정을 확장합니다. 확인·표시 설정이 원래 불출·반납·정산·결재 상태 또는 업무 버전을 바꾸지 않습니다. 기존 계정·암호 해시·인증서 관련 도구·사고 이력·대체 연결·첨부·점검기록을 유지합니다.

운영 서버 종료 → DB·첨부·보안 자료를 포함한 전체 백업 → 새 폴더에 ZIP 해제 → 기존 실행 방식으로 시작하는 순서로 적용하세요. 기존 운영 data를 빈 data로 덮어쓰지 마세요. Windows 실행 폴더 설치는 기존 `%LOCALAPPDATA%\YBY\app\data`를 계속 사용합니다. 운영 자료의 복사본에서 계정별 로그인·자료 건수·이력·첨부·인증서 접속을 먼저 확인하세요. 이전 프로그램으로 되돌릴 때에는 이전 전체 백업 기준으로 복원해야 합니다.

실제 검사와 미검증 범위는 `VALIDATION_V4_1_25_KO.md`를 참고하세요.
