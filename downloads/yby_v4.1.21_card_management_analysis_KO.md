## 카드관리 보조업무·사용내역·통계 분석자료

YBY V4.1.21 · 2026년 10월 20일 · 한국시간


> 종합 판단: 본사·지점의 카드 소재와 불출·반납 이력을 관리하는 보조 도구로 활용 가치가 있습니다. 다만 현재의 사용 반납은 YBY 정산 작성과 묶여 있어, 별도 시스템에서 정산하는 회사에 그대로 맞는 전용 보조관리 모드는 아닙니다.


회사의 공식 사용정산·결재는 다른 시스템에 입력하고, YBY는 카드 관리와 현황 파악을 지원한다는 실제 업무를 기준으로 평가했습니다. 사용내역과 통계가 무엇을 포함하고 제외하는지, 현황을 믿을 수 있는 조건까지 분석합니다.

| 변경 여부 | 프로그램·회사 자료 수정 없음. 회사 서버·Oracle에 접속하지 않음 |


두 번째 「회사 업무용 적합성·완성도 분석자료」는 보안·복구·구조와 전체 기능을 평가합니다. 본 분석자료는 카드 관리 보조업무와 통계 해석을 더 깊게 다룹니다. 독립 외부기관의 인증 보고서는 아닙니다.


## 01. 사용 가능 여부와 도입 판단

사용 목적을 좁힐수록 유용성이 명확해짐


| 사용 범위 | 판단 | 근거·조건 |
| --- | --- | --- |
| 보유 카드·현재 사용자·반납 예정 파악 | 조건부 적합 | 지점별 범위·이력·현재 대여 상태 구현. 실물 보관자 확인과 입력 시점 준수 필요 |
| 반납·연체·불출 이력 조회 | 조건부 적합 | 불출/반납 이벤트 연결과 필터·정정 보호. 분실·정지 전용 상태는 부족 |
| 사용내역 보조 조회·자료 이관 | 조건부 적합 | 출처/명세/과거 이관 보존. 외부 원본과 일치하는지 별도 대조 필요 |
| 전사 사용금액·횟수 보고 | 조건부 참고 | YBY에 수록된 승인·이관 자료 기준. 별도 시스템의 전체 확정 실적은 아님 |
| 외부 정산만 사용하는 단순 실물 반납 | 현재 구조 보완 필요 | 사용함 반납은 YBY 정산과 연결. 권한·입력 미충족 시 실물 회수해도 화면상 대여중으로 남음 |
| Oracle 실시간 통합 현황 | 현재 사용 불가 | 수신함·정규화·매칭은 있으나 실제 Oracle 연결·SQL·증분 처리가 없음 |


### 도입 판단의 핵심


보조 도구라는 이유로 자료 보호·복구를 생략할 수는 없습니다. 카드 소재와 담당자 기록이 잘못되면 실제 업무가 멈추거나 책임 추적이 어려워집니다. 반면 회계 전표·세무·외화 마감을 YBY가 맡을 필요는 없으므로, 그 부족만으로 보조 관리 도입 전체를 부정할 이유도 없습니다.


> 권고: 소수 지점에서 실물 대장을 병행하며 시험하고, 사용 반납과 외부 정산 확인을 분리하는 보완을 우선합니다. 미사용으로 거짓 반납하거나 임의 1원 정산을 만드는 우회는 금지합니다.


## 02. 두 시스템의 업무 책임 구분

어느 자료가 최종 기준인지 먼저 확정


**현장·지점 담당자**：카드 신청·실물 인계 → 사용 → 실물 회수 확인


**YBY 관리 보조**：현재 보관자·불출/반납 이력·미회수·참고 사용내역·대조 결과


**별도 정산시스템**：정식 사용명세·증빙·결재·정산 확정 → 공식 문서번호·상태


**본사 관리 담당**：실물과 YBY 대조 + 외부 확정자료와 YBY 수록자료 대조


| 자료 | 권장 최종 기준 | 충돌 시 처리 |
| --- | --- | --- |
| 실물 인계·반납 시각/확인자 | YBY의 실물 확인 기록 + 인수 증거 | 정산 완료를 근거로 반납을 자동 확정하지 않음 |
| 실제 결제 거래·증빙·최종 결재 | 회사 지정 외부 정산/회계시스템 | YBY 금액을 수정해 덮기보다 출처·정정 사유 기록 |
| 카드 거래 승인·정지·취소 | 카드사/회사 지정 금융 원본 | YBY 대여가능 표시가 금융 사용가능을 뜻하지 않음 |
| 지점·부서·사용자 | 회사 조직·인사 마스터 | 현재 이름과 당시 소속을 구분. 이름만으로 동일인 단정 금지 |


현재 YBY의 승인/반려는 YBY 내부 상태입니다. 외부 결재 상태를 수신해 표시하더라도 두 결재는 독립입니다. “반납완료”, “외부정산완료”, “YBY 승인완료”를 한 상태로 합치지 않아야 합니다. [E02,E08]


## 03. 불출·반납의 실제 동작과 불일치

직접 재현한 보조관리 운영상의 핵심 제약


| 합성 시험 | 관찰 결과 | 현업 의미 |
| --- | --- | --- |
| 불출 권한만 있고 정산 권한이 없는 담당자가 사용 반납 | 403 / 카드 상태 대여중 유지 | 정산 메뉴를 숨기기만 하면 정상 사용 반납이 막힘 |
| 사용함 선택 후 내부 정산 생략 | 400 정산 형식 오류 / 대여중 유지 | 별도 시스템에서 이미 정산해도 YBY 반납은 별도 입력을 요구 |
| 정상 내부 정산과 사용 반납 | 200 / 카드 사용가능 + 내부 승인대기 | 실물 회수와 별개로 YBY 미결 업무가 새로 생김 |
| 실제 미사용 반납 | 200 / 카드 사용가능 / 정산 0건 | 미사용은 간단히 반납 가능하나 사용 건의 우회 경로가 되어서는 안 됨 |


이는 이번 요구에 대한 업무 적합성 차이이며, 권한 검사가 뚫린 보안 결함을 의미하지 않습니다. 정산 저장 실패 시 반납까지 함께 취소되는 원자성은 현재 설계의 장점이지만, 실물 회수만 먼저 완료해야 하는 회사에는 상태 지연을 유발합니다. [E02,관찰 O01~O04]


### 우선 필요한 개선 — 아직 미구현


- 사용 여부·실물 회수 시각·회수자·실제 보관 위치를 저장하면 카드 소재를 갱신하는 “실물 반납” 절차를 별도로 둡니다.
- 외부정산 상태를 미확인/미작성/진행/완료/반려·철회 등으로 따로 보관하고, 공식 문서번호·확인일·확인자를 연결합니다.
- 외부 정산 기준 운영 모드에서는 YBY 건별 재입력과 재결재를 필수로 요구하지 않도록 합니다. 기존 내부 정산 모드는 유지하되 구분합니다.


## 04. 사용내역·두 이력대장의 신뢰도

기록의 양보다 기준·출처·연결이 중요


| 화면 | 실제 의미·장점 | 읽을 때의 주의 |
| --- | --- | --- |
| 불출/반납 이력대장 | 실물 이동 이벤트, 신청자/사용자, 처리자·시각·연결 ID·입력경로 | 불출 1행 + 반납 1행은 거래 2회가 아님. 과거 이관 시각과 실제 당시 시각 구별 |
| 사용정산 이력대장 | 정산 문서·건별 명세·결재/이관·정정 경로 | 모든 외부 결제의 자동 수집 대장이 아님. 외부 미수록 건은 나타나지 않음 |
| Excel 직접 이관 | 한 원본 행에서 정산1건·불출/반납 이력을 준비, 원본 결측 보존 | 엑셀 합계 1행은 결제 여러 건일 수 있음. 이관완료는 YBY 결재완료가 아님 |
| 수기 정정·재보고 | 사유·재인증·전후/원본 추적으로 일방 덮어쓰기 제한 | 외부 시스템의 정정까지 자동 전파되지 않음. 양쪽 담당자가 확인해야 함 |


### 사용내역에 함께 표시해야 할 항목 — 권고


입력경로·수신 배치, 공식 원본 문서번호/개정번호, YBY 불출 ID, 카드 내부 식별자, 당시 지점/부서/사용자 ID, 실제 거래일, 원본 합계 여부, 원본 결재상태와 최종 수신 시각을 한 화면에서 확인하도록 합니다. 현재 일부 출처·참조는 존재하지만 이 전체가 통합된 외부 확정 대장은 아닙니다.


카드 끝4자리+지점은 후보 탐색에 유용하나 유일키로 보장되지 않습니다. 같은 지점에 동일 끝4자리 카드가 존재하거나 재발급될 수 있습니다. 카드 내부 ID·발급사·유효기간과 관리자의 전체번호 대조로 확정해야 합니다. [E06,E08]


## 05. 통계화면의 실제 집계 기준

전체·개인·지점·부서·목적별 통계를 종합 평가


| 집계 항목 | V4.1.21 실제 기준 | 해석 |
| --- | --- | --- |
| 집계 모집단 | 유효 승인완료 + EXCEL_LEDGER 과거 이관완료 중 유효 자료 | 외부 정산 전체가 아닌 YBY 수록 자료 |
| 제외 | 대기·반려·승인취소·대체된 정정/재보고, 미사용 이관, 금액 누락·0원 등 | 사유별 제외 건수는 별도 확인해야 함 |
| 정산 문서 건수 | group + requester + id 단위 중복 제거 | 외부 거래 고유키 기반 중복 제거와는 다름 |
| 사용 횟수 | lineItems 수, 명세 없으면 1 | 실제 카드 승인 거래 수를 보장하지 않음 |
| 조회월 | 정산 문서 date의 YYYY-MM | 명세가 여러 달이면 문서 기준 달에 전액 귀속 |
| 개인·부서·지점·목적 | 문서 사용자/부서/지점/목적값으로 분류 | 개인별은 카드 소지자 이름 기준. 사번 단위 인사통계 아님 |
| 전체 통합 | 각 차원 요약과 지점→부서→개인→목적 비교표 | 차원별 합계는 같은 실적을 다른 기준으로 본 것. 모두 더하면 중복 |


통계 모델과 화면·Excel은 같은 집계 모델을 사용하며 금액의 안전한 정수 범위를 검사합니다. 이력대장을 우선해 같은 ID 중복을 제거하고 승인취소·이전 정정 제외를 고려한 점은 장점입니다. 다만 정확성의 범위는 “YBY 수록 자료와 해당 정의”까지입니다. [E03]


## 06. 통계의 경계 사례와 수치 해석

합성 자료로 재현. 회사 실제 오류 건수는 아님


| 사례 | 현재 관찰 | 필요한 해석·보완 |
| --- | --- | --- |
| 10/31 100원 + 11/1 200원을 한 정산 명세로 등록 | 문서일 10/31,10월300원·2회 / 11월0원 | 월별 실제 거래 분석은 명세 거래일 기준으로 따로 집계해야 함 |
| 225,000원짜리 Excel 합계1행, 세부 거래 없음 | 문서1건·사용1회·225,000원 | 결제 횟수 불명. 합계자료의 “1회”를 실제 사용1회로 보고하지 않음 |
| 한 문서 목적 [출장,접대] | 출장·접대라는 복합 목적 한 그룹 | 출장/접대 각각의 금액 배분이 아님. 명세별 목적 배분 필요 |
| 승인300원 + 이관225,000원 | 통계 합계225,300원 | 현 화면은 합산. 금액 원천별 분리·대사 필요 |
| 동일 ID 중복 / 다른 ID의 동일 경제 거래 | 같은 ID는1건 / 다른 ID 두 개는 합산 | 재업로드 키 보호와 별개로 수기+외부+Excel의 교차 중복 대사 필요 |
| 구형 금액 문자열 “300” | 통계는300으로 허용, 업무점검은 원본 형식 경고 가능 | 정상 신규 입력의 오류는 아님. 구형/외부 자료의 검증 정책 통일 권고 |


> “금액 합계가 맞는다”는 것과 “정식 확정금액·기간·횟수·부서 귀속이 맞는다”는 것은 다릅니다. 사용 횟수의 명칭을 명세행 수로 명확히 하거나 실제 거래 수·정산 문서 수를 분리하는 것이 좋습니다.


현재 날짜 처리와 집계는 문서 기준으로 일관된 동작입니다. 본 분석자료는 이를 회사가 원하는 실제 거래월 통계로 오인할 위험으로 평가합니다. [E03,E04,통계 관찰 S01~S07]

대시보드 하이패스·유류대 숫자는 등록된 활성 옵션/번호 기준의 수치이며, 항상 실물 불출중만 센 값이 아닙니다. 최고관리자와 지점의 집계 경로·구형 결측 자료 조건에서도 해석을 확인해야 합니다. [E05,E09]


### 신선도 표시가 필요


화면 폴링은 YBY 서버의 변경을 가져옵니다. 외부 Oracle를 주기적으로 읽는 기능과는 다릅니다. 화면에 YBY 최종 갱신, 외부 최종 성공 수신, 외부 자료 기준시각, 실패/지연 배지를 따로 두어야 “실시간 현황”을 과장하지 않습니다.

## 09. 본사·지점 권한과 책임 분담

단일 서버 공유, 개인별 계정, 최소 권한

| 지점 확인자 | 자기 지점 조회·실물 대사·미결 확인 | 담당/확인자 분리 기준을 회사가 정해야 함 |

합성 시험에서 ALL 계정의 메뉴권한을 비워도 카드 등록이 가능했습니다. 이는 설계된 최고관리자 범위로, 무권한 사용자의 승격을 발견한 것은 아닙니다. 메뉴 숨김만으로 본사 조회전용을 만들면 안 됩니다. [E05,O06]


각 지점은 회사 라우팅망 또는 승인된 VPN을 통해 같은 본사 서버를 사용해야 합니다. 같은 회사라도 서로 다른 사설망이면 자동 연결되지 않습니다. 지점마다 서버를 독립 실행하면 중앙 단일 원장이나 자동 동기화가 되지 않습니다.
