# V4.1.2 검증 결과

검증일: 2026-10-17 (한국 시간). 환경: Linux, Python 3.12, 실제 Chromium.

- 서버/API/권한/정산/세션/첨부/오류경로 자동검사 158개 통과.
- 최초 반납 정산과 정정·재보고의 기본정보/사용 및 금액/건별 명세가 같은 필드·컨트롤 구조임을 실제 브라우저에서 확인.
- 너비 1366, 1024, 768, 390, 320px 각각에서 두 화면의 입력폼/건별 명세 가로 넘침이 없고 입력칸이 창 안에 있음 확인.
- 두 건의 수량·단가·합계, 변경한 기본 날짜와 별도 건별 날짜, 영수증 첨부, 여러 줄 비고의 저장·재표시 확인.
- 실제 반납 → 본인 승인 → 사유를 포함한 승인취소 → 동일 양식에서 정정 → 기존 증빙 유지 → 금액 수정·재보고 → 재승인 통과.
- 승인취소 이력 행·배지·상세 요약의 음영, 신청/결재 일시 인접 배치, 원 승인/취소 시각 구분 확인.
- 상세보고서 인쇄 모드에서 취소 시각 표시, HTML 특수문자 이스케이프, 다른 모달에 정산창 너비가 남지 않는 것 확인.
- 기존 다중 사용자 권한 변경/비밀번호 변경 시 접속 유지·최고관리자 재인증·건별 정산/엑셀 내보내기 브라우저 검사 통과.
- 기존 승인취소/반려/재보고 재처리와 공지 첨부 실패 후 재시도·다운로드 브라우저 검사 통과.
- 실제 V4.1.1 실행 → 종료 → V4.1.2 설치 → HTTPS 재시작 검증. 실행 중인 구버전의 파일은 교체하지 않음 확인.
- 교체 직후 DB 바이트 보존, 재시작 후 회사 계정/비밀번호·카드·승인취소 원본·재보고 대기/메시지/행·증빙·CA/개인키 보존 확인. DB 스키마는 기존 5를 유지.

배포 ZIP의 CRC·매니페스트 SHA-256·개인 DB/인증서/키 미포함 및 압축 해제본의 실행 검증은 외부 yby_v4.1.2_package_verification.json에 기록합니다.

## 실제 환경에서의 확인

회사 Windows/Edge, Python 3.14, Windows DPAPI·인증서 저장소·NTFS 권한·회사망/VPN은 이 환경에서 직접 실행하지 않았습니다. 서버의 VERIFY_WINDOWS.bat와 다른 PC의 CHECK_CONNECTION.bat를 실행하고, 실제 사용 권한으로 반납·정정 업무를 확인하세요. 검사 통과는 모든 향후 입력과 외부 정책 환경을 보증하지 않습니다.
