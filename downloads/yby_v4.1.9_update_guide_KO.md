# YBY V4.1.9 신청자·신청일·자료 출처 개선

2026년 10월 19일 · V4.1.8 기준 전체 패키지

## 바로 사용할 수 있는 변경

불출 및 반납 관리의 불출 양식을 다음과 같이 보완했습니다.

- **사용신청일**: 한국 시간 오늘 날짜가 기본값입니다. 실제 신청일이 다르면 선택하여 바꿀 수 있습니다. 실제 카드 불출일은 서버에서 처리한 날짜로 별도 기록합니다. 신청일은 반납예정일 이후가 될 수 없습니다.
- **실제 카드 사용자명**: 기존 사용자명을 실제 사용자임이 드러나도록 표시했습니다.
- **사용 신청자명**: 실제 사용자와 별도로 입력합니다. ‘실제 사용자와 같습니다’가 선택되어 있으면 사용자명을 따라갑니다. 신청자가 다르면 체크를 해제하고 신청자명을 입력하세요.
- **처리자**: 위 두 이름과 별도로 실제 저장을 수행한 YBY 로그인 계정을 이력에 기록합니다. 신청자 이름을 적는 것으로 다른 사람의 계정으로 처리되는 것은 아닙니다.
- **자료 출처**: 새 직접 입력은 ‘YBY 직접 입력’, 외부 수신 문서를 선택해 확인한 건은 ‘외부 Oracle 자료’로 표시합니다. 과거에 출처를 저장하지 않은 이력은 ‘기존 자료 · 출처 미기록’으로 표시합니다.

입력 도중 목록이 갱신되어도 신청일·다르게 입력한 신청자명·선택 가능한 카드값을 유지합니다. 저장이 완료되면 양식을 초기화하고 신청일을 다시 오늘로 준비합니다.

신청일·신청자·사용자·자료 출처는 반납 회수 목록, 불출/반납 이력과 엑셀/인쇄, 정산 상세에 남습니다. 카드를 반납한 뒤 다음 사람이 빌릴 때는 이전 신청자 정보가 새 대여 건으로 넘어가지 않습니다. V4.1.8의 최신순 이력·사용자별 누적 횟수·정산 지표·요약 보고서도 유지합니다.

## Oracle 연결 준비 상태

**이번 버전은 실제 Oracle 접속·조회·주기적 동기화 기능을 활성화하지 않습니다.** 담당자 자료와 접속/조회 구조가 아직 도착하지 않았기 때문입니다. 현재 프로그램에는 수신 자료가 없습니다. 시험용 외부 문서나 회사 원본 문서를 배포 패키지에 넣지 않았습니다.

다만 나중에 연결할 수 있도록 **서버 수신함과 문서 선택 → 내용 확인 → 기존 양식 입력 → 최종 저장** 구조를 구현했습니다. 실제 수신이 시작되기 전에는 ‘선택할 외부 수신 자료가 없습니다’와 연결 준비 안내가 보입니다. 직접 입력 업무는 계속 사용할 수 있습니다.

외부 DB 자료를 직원 PC의 파일이나 DB 목록에서 직접 선택하는 방식이 아닙니다. 회사 YBY 서버가 읽어온 **사용신청서·사용정산서 문서**를 선택하는 구조입니다. DB 종류·접속정보를 일반 사용자에게 입력하게 하지 않습니다.

## 외부 신청서의 향후 사용 순서

1. 불출 화면의 ‘외부 신청서 선택’을 누릅니다.
2. 자기 지점(최고관리자는 전체)의 수신 문서를 조회합니다.
3. 문서번호·신청자·실제 사용자·지점·사용목적·일자를 확인하고 확인 체크를 선택합니다.
4. ‘확인한 내용으로 입력’을 누르면 신청 양식에 채워집니다. 해당 지점의 대여 가능한 카드 중 실제 카드를 확인하고 목적 구분 등을 보완합니다.
5. ‘불출 등록’을 눌러야 실제 불출됩니다. 문서 선택·확인만으로 카드 상태가 바뀌지 않습니다.

외부 신청자와 실제 사용자가 다를 수 있습니다. 원본에 실제 사용자가 없으면 입력/확인해야 하며 기안자 이름을 실제 사용자로 자동 대입하지 않습니다. 외부 문서에서 목적 구분을 확정할 수 없는 현재 단계에서는 ‘기타’를 기본 선택하므로 담당자가 알맞게 바꿉니다.

## 외부 정산서의 향후 반납 처리 순서

1. 기존처럼 반납할 카드의 ‘반납 회수’를 누릅니다.
2. ‘외부 정산서 선택·확인’을 누릅니다. 해당 카드 지점과 끝자리 4자리에 맞는 수신 정산서를 보여줍니다.
3. 원본 문서번호·기안자·외부 결재 상태, 실제 사용자, 카드, 기간, 건별 명세와 총액을 확인합니다.
4. 확인 체크 후 ‘확인한 내용으로 입력’을 누르면 **기존과 같은 정산 양식**의 날짜·사용자·목적·건별 명세·합계가 채워지고 ‘사용함’이 선택됩니다. 입력 중인 정산 명세는 선택한 문서로 대체되므로 내용을 먼저 확인하세요.
5. 필요한 사항을 보완하고 ‘반납 및 정산 신청’을 누릅니다. 이때 반납·정산·외부 문서 연결이 함께 저장됩니다. 확인 단계에서 닫으면 기존 입력을 유지합니다.

YBY에서 직접 불출한 카드에도 독립된 외부 정산서를 선택할 수 있습니다. 불출 출처와 정산 출처를 따로 보관합니다. 반대로 외부 신청서로 불출했어도 YBY에서 직접 정산할 수 있습니다. ‘직접 입력/직접 정산으로 전환’은 외부 연결 선택을 해제하므로 보존된 입력을 담당자가 직접 확인해 저장해야 합니다.

외부 신청서와 정산서 사이에 연결번호가 있다는 가정을 하지 않습니다. 담당자가 정확한 불출 회차와 정산서를 확인하여 연결합니다. 같은 끝자리라도 다른 지점이면 표시·연결하지 않습니다.

외부 결재는 참고 상태이며 YBY 결재는 별도로 진행합니다. 외부 ‘결재중’이어도 YBY의 정산·결재가 가능합니다. 이력의 외부 상태는 **연결한 시점**의 수신 정보입니다. 외부 상태의 실시간 갱신은 Oracle 동기화 구현 후 별도 반영합니다.

**외부 첨부파일·영수증은 아직 가져오지 않습니다.** 필요한 증빙은 기존 양식에서 따로 첨부하세요. 외부 내용과 다르게 보완한 경우 ‘YBY에서 보완’ 표시를 남기고 연결 시점의 원본과 버전을 별도 보관합니다.

## 연결 보호와 남은 범위

- 문서 내용 확인, 지점·카드·문서 종류 일치, 원본 버전을 서버에서도 검사합니다. 다른 지점·이미 연결한 문서·회수된 문서·확인 후 갱신된 문서는 새 처리에 바로 사용할 수 없습니다.
- 같은 신청서/정산서의 중복 연결은 막습니다. 한 문서가 여러 카드나 여러 회차에 걸치는 처리, 분할 정산 등은 실제 DB 구조 확인 후 설계합니다. 현재는 문서 한 건당 최초 업무 연결 한 번이 기준입니다. 정정·재보고는 기존 YBY 흐름을 통해 원래 출처를 유지합니다.
- 브라우저에서 임의 내용을 ‘Oracle 원본’으로 업로드하거나 출처 이름만 바꿀 수 있는 기능은 없습니다.
- Oracle 접속 계정·읽기 권한·테이블/뷰/상태코드·일자 매핑·첨부 저장 방식·증분 수신과 오류 보류 정책은 담당자 회신 후 연결합니다. 기존 정보 요청서를 다시 요청할 필요는 없습니다.

## 서버 PC 적용 방법

1. 현재 프로그램의 **시스템 관리 → 전체 백업 만들기**로 전체 백업 파일을 보관합니다. 헤더의 JSON 내보내기는 외부 수신 원본·첨부 실물 등을 포함한 전체 백업이 아닙니다.
2. 다른 사용자가 저장·로그아웃한 뒤 기존 서버 검은 실행창에서 **Ctrl+C**로 서버를 종료합니다.
3. 새 ZIP을 새 폴더에 **전체 압축 해제**합니다.
4. 기존 서버를 사용한 **동일한 Windows 계정**으로 `RUN_LAN_WINDOWS.bat`을 실행합니다.
5. **READY V4.1.9** 및 화면 상단 **V4.1.9**를 확인합니다. 서버 실행창은 유지합니다.

실제 실행 폴더 `%LOCALAPPDATA%\YBY\app`의 기존 DB·계정·첨부·인증서 설정을 보존하는 방식입니다. 데이터 형식을 버전 6으로 갱신하여 외부 수신함과 연결 원본 보관 공간을 추가하며, 이전 형식이면 갱신 전에 자동 전체 백업을 생성합니다. 수신함은 실제 자료를 수신하기 전까지 비어 있습니다. `data`·`certificates`·잠금 파일을 삭제하지 마세요.

새 데이터 형식을 사용한 뒤 예전 프로그램만 덮어써서 되돌리지 마세요. 복귀가 필요하면 서버를 종료하고 업그레이드 전 전체 백업과 해당 구버전을 함께 사용합니다. 다른 PC는 로그인창을 닫았다가 다시 열면 되며 기존 인증서는 일반적으로 다시 설치할 필요가 없습니다.

검사 결과와 실제 Windows 확인 범위는 `VALIDATION_V4_1_9.md`에 기록합니다.
