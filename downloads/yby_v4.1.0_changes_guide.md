# V4.1.0 개선 사항과 사용법

## 1. 창을 닫은 뒤 재접속

V4.0.4의 5000번 포트는 HTTPS 전용이므로 `http://localhost:5000` 또는 `http://10.10.0.121:5000` 요청을 TLS로 읽다가 연결을 끊었습니다. V4.1.0은 동일 포트에서 일반 HTTP 탐색 요청을 구분해 **HTTPS로 308 이동**합니다. 아이디·비밀번호를 평문 HTTP로 처리하지 않으며 인증은 계속 HTTPS로만 합니다. 등록되지 않은 Host에 임의 이동하거나 HTTP POST를 인증 처리하지 않습니다.

서버 시작/서버 CONNECT_SERVER.bat/다른 PC INSTALL_AND_CONNECT.bat의 접속 확인이 성공하면 바탕화면에 **YBY 로그인** 바로가기를 만듭니다. 다음에는 이 아이콘을 사용하세요. Edge 또는 Chrome이 설치되어 있으면 주소창 없는 전용 로그인 창을 사용하며 없으면 기본 브라우저를 사용합니다. 브라우저 인증서 경고는 우회하지 않습니다.

다른 PC 접속 도구는 공개 파일만 사용자 AppData에 보관하므로 ZIP/USB 원본을 옮겨도 바로가기가 유지됩니다. 바탕화면 생성이 회사 정책으로 차단되면 기존 BAT를 사용할 수 있습니다. 로그인 창을 닫아도 **서버 PC의 RUN_LAN 실행 창은 열어 두어야** 합니다. 서버가 꺼져 있으면 바로가기나 HTTP 이동 기능도 접속을 대신할 수 없습니다.

## 2. 권한·비밀번호 관리

- 일반 권한/비밀번호 저장으로 다른 사용자나 대상 사용자의 현재 세션을 종료하지 않습니다. 변경한 권한은 서버에서 매 요청마다 적용하고 화면은 다음 동기화 때 갱신합니다.
- 관리자 비밀번호 재설정 후 기존 접속은 유휴/절대 만료까지 유지하고, **다음 로그인부터 새 비밀번호와 최초 변경 요구**를 적용합니다. 기존 비밀번호로 새로 로그인할 수 없습니다.
- 계정 행의 **접속 종료** 버튼을 누르면 선택한 계정만 명시적으로 로그아웃시킬 수 있습니다. 계정 삭제·본인 비밀번호 변경·시간 만료에 따른 기존 세션 보호는 유지합니다.
- 관리자 화면에 별도 **비밀번호 변경 내역** 공간을 추가했습니다. 대상 계정·수정자·변경 시각·구분/IP를 확인하고 검색할 수 있습니다. 과거 비밀번호 원문을 이력에 남기지는 않습니다.
- 계정 행의 **현재 비밀번호 보기** → 현재 최고관리자 비밀번호 재인증 → 현재 비밀번호를 30초간 표시합니다. 창을 벗어나거나 닫거나 로그아웃하면 지웁니다. 조회 자체는 비밀번호 값 없이 감사 기록에 남습니다. 재인증 실패 반복은 제한합니다.
- 현재 비밀번호 표시는 요청에 따라 추가한 기능으로, 인증 해시 외에 **표시용 암호화 자료**를 별도 보관합니다. Windows는 현재 서버 실행 사용자의 DPAPI, Linux는 검증된 Fernet 암호화를 사용합니다. 평문 비밀번호를 DB·일반 상태·목록 응답·감사 로그에 기록하지 않습니다.
- 기존 V4.0.4에 해시만 저장된 비밀번호는 역으로 복원할 수 없습니다. **해당 사용자가 V4.1.0에서 로그인하거나 비밀번호를 변경하면** 표시용 암호화 자료를 만들 수 있습니다. 미확인 계정에는 명확히 안내합니다. 로그인으로 최초 표시 등록할 때 기존 비밀번호 변경 시각을 덮어쓰지 않습니다.

암호화 자료가 포함된 전체 백업은 민감 자료로 관리하세요. Windows DPAPI는 Windows 사용자/PC에 연결되므로 다른 계정/PC로 이전한 뒤에는 해당 사용자가 로그인하거나 비밀번호를 변경해 표시용 자료를 다시 등록해야 할 수 있습니다. 로그인 해시는 별도이므로 이것이 업무 로그인 비밀번호를 자동 변경하지는 않습니다. Linux는 `admin_password_vault.key`도 전체 백업에 포함합니다.

## 3. 건별 정산과 본인 결재

반납 회수 → 사용함 선택 → **건별 세부 정산 명세**를 작성하세요. `+ 사용 건 추가`로 행을 늘립니다. 각 행에는 사용일, 구분, 사용처, 상세내역, 수량, 단가, 비고를 입력하고 금액은 수량×단가로 자동 계산합니다. 상단/하단 합계도 자동 계산하며, 기본 구분은 위 정산 구분을 사용할 수 있습니다. 수량/원화 단가는 양의 정수, 최대 100건, 합계는 1조원 이하입니다.

전체 사용 목적·참석자·증빙 첨부는 기존 양식을 유지합니다. 반납과 모든 정산 행을 한 트랜잭션으로 저장하므로 금액/첨부 검증 실패 시 카드만 반납 처리되지 않습니다. 서버도 각 행의 금액과 전체 합계를 재계산하고 일치하지 않는 요청은 거부합니다.

대기 목록 **명세 보기**, 최종 이력의 **상세 보기**, 보고서 인쇄/PDF, 엑셀에 건별 명세를 제공합니다. 통계에는 정산 문서의 합계가 한 번만 반영됩니다. 이전 단일 금액 정산도 그대로 조회할 수 있습니다. 승인 취소·정정 기록은 기존 절차와 원본 보존 정책을 유지합니다.

**최고관리자(ALL)는 본인의 정산도 승인/반려**할 수 있습니다. 본인 처리 여부·결재자·시각을 기록합니다. 일반 지점 사용자는 결재 권한이 없으며, 내부 보고서 결재는 기존의 본인 문서 결재 제한을 유지합니다.

## 업데이트와 검증

1. 업무 작업을 마무리하고 새 ZIP을 새 폴더에 전체 압축 해제합니다.
2. 새 폴더의 STOP_SERVER.bat로 기존 서버를 종료합니다.
3. RUN_LAN_WINDOWS.bat 일반 더블클릭 → 필요 시 인증서 등록 승인 → 로그인. 기존 AppData의 data/계정/비밀번호/인증서를 유지합니다. 첫 V4.1.0 자료 초기화 전에 이전 DB·첨부의 전체 백업을 만듭니다.
4. OPEN_LAN_CLIENT.bat → 새 LAN_CLIENT.zip을 다른 PC에 배포합니다. 다른 PC도 새 ZIP을 풀고 INSTALL_AND_CONNECT.bat를 한 번 실행해야 새 로그인 바로가기를 사용할 수 있습니다.
5. 서버 VERIFY_WINDOWS.bat, 다른 PC CHECK_CONNECTION.bat로 실제 Windows/회사망을 검사합니다. VERIFY_WINDOWS에는 HTTP 이동과 실제 Windows DPAPI 왕복 검사도 포함합니다.

Windows 서버는 Python 표준 라이브러리와 Windows API를 사용합니다. Linux 서버는 최초 한 번 가상환경에서 `python -m pip install -r requirements.txt`로 cryptography를 설치해야 합니다.

실제 클라우드 검증 결과와 한계는 VALIDATION_V4.md에 기록합니다. Windows API/Edge 전용 창/회사 네트워크는 이 Linux 클라우드에서 직접 실행한 결과와 구분합니다.
