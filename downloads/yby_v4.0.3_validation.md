# V4.0.3 인증서 파일 접근권한 수정 검증

2026년 10월 15일(한국 시간). 사용자 Windows/Python 3.14 로그로 인증서 생성 후 root-ca.cer 읽기 PermissionError를 확인했습니다. Windows 복사·잠금·인증서 생성은 사용자 로그에서 진행됐지만 해당 클라우드에서 직접 수행한 결과는 아닙니다.

수정: 폴더에만 상속 가능한 ACE를 적용하고 파일에는 직접 F 권한을 적용하며, 기존 파일 로드 전에 권한을 복구합니다. /T와 폴더 상속 ACE를 합쳐 파일 전체에 적용하던 경로를 제거했습니다. 현재 사용자·SYSTEM·관리자만 대상으로 하며 파일 내용과 업무 DB를 변경하지 않습니다.

검증:

- 기존 105개 + ACL 범위·오류 전파·로드 전 복구·키 비노출·빈 파일 거부·인증서 바이트 보존 7개, 총 112개 테스트.
- Windows 명령 계약 검사에서 각 파일은 직접 F, 폴더는 (OI)(CI)F로 분리되는지와 /T 부재를 확인합니다. 이 검사는 Windows에서 해당 명령을 실행했다는 뜻이 아닙니다.
- 기존 인증서에 복구를 반복 적용해 모든 인증서/키 파일 SHA-256과 CA 지문이 바뀌지 않는지 확인합니다. 실제 읽기·SSLContext 인증서/키 로드를 검사합니다.
- 최종 ZIP의 CRC·전체 manifest 파일 해시 및 새 폴더에서 112개 테스트, 읽기 전용 한글 경로의 복사/실행/업무 저장/원본 DB 보존, 실제 사설 IP의 HTTPS·로그인·인증서 검증·재시작을 검사합니다. 배포 검증 JSON은 해당 ZIP SHA-256과 수행 결과를 기록합니다.
- 작은 복구 ZIP은 전체본과 동일한 certificate_permissions.py, BAT, 한글 안내만 포함합니다. DB·인증서·키·사용자별 설정을 포함하지 않습니다.

테스트 실행 환경은 Linux/Python 3.12입니다. 실제 Windows ACL·CSP·Python 3.14·회사 네트워크를 이 클라우드에서 실행했다고 주장하지 않습니다. 복구 도구는 해당 Windows PC에서 Python의 실제 파일 읽기·SSL 로드를 수행하고 PASS/실패를 출력합니다. 해당 PASS는 권한과 로드 확인이며 다른 PC와 VPN의 전체 연결 보증은 아닙니다.
