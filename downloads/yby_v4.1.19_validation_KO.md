# YBY V4.1.19 검증 결과

검증일: 2026-10-20 (한국시간). 기준 V4.1.18, DB 스키마 8 유지.

## 자동 검사

- Python 서버 전체 **332개 통과**, 실패·스킵 없음, 160.900초. 신규 11개 포함.
- 최종 정정 전후 기본값·변경 없음 검사 보완 후 신규 **11개 재실행 통과**, 9.805초. 반복 건수는 합계에 더하지 않음.
- Node 이력·통계 **28개 통과**, 실패·스킵 없음.
- 고유 자동 검사 합계 **360개**. 브라우저와 반복 검사는 중복 합산하지 않음.

## 실제 브라우저 확인

Chromium에서 서버와 실제 HTTP 통신으로 다음을 확인했습니다.

- 서로 다른 파일을 두 번 업로드하고, 처리한 행이 미리보기에서 제거되는지 확인.
- 다시 누르면 ‘이미 업로드가 완료’ 안내가 표시되고 중복 기록이 생기지 않음.
- 3행 중 1행만 반영한 뒤 미처리 2행만 남고, 이어서 2행을 반영하는 과정 확인.
- 작성기준일·번호 저장 후, 더 과거의 사용일을 나중에 올려도 입력순 번호가 큰 행이 먼저 표시됨.
- 사용정산이력 15개, 불출반납이력 18개 열에 필터가 있으며 실제 각 열의 조건을 입력해 조회 확인. 번호 정확 일치·범위·이상 조건 확인.
- 완료 안내의 두 대장 버튼이 해당 업로드 건만 보여주고, 일반 메뉴에서는 전체 자료 범위로 복귀.
- 현재 업로드 한정/열 조건을 적용한 실제 XLSX를 내려받아 작성기준일·정정부서와 다른 업로드 건 제외 여부를 내부 XML로 확인.
- 잘못된 정정 비밀번호 입력 시 내용 보존·비밀번호 비우기, 올바른 비밀번호로 정정 성공.
- 사용 여부·반납일·부서·진행상태가 연결된 두 대장에 반영됨. 같은 끝자리 카드의 다른 행은 변경되지 않음.
- 반납일 누락 행에 반납 이력이 추가되고 번호가 새로 부여됨. 미사용 정정 시 원본 금액은 남고 유효 사용 합계에서는 제외됨.
- 원본 상세 화면의 사유·처리자·일시·변경 전/후 표와 서로 다른 음영색 확인.
- JavaScript 실행 오류 없음. 1920/1440/1024/768/390/320px에서 문서 전체의 가로 넘침 없음. 넓은 대장은 표 영역 안에서 스크롤.

## 서버 정정·보호 검사

- 등록 시각·번호가 사용일과 독립적이며 정정 후에도 유지.
- 자기 지점 권한/최고관리자 허용, 타 지점·단순 조회 권한·잘못된 암호 차단.
- 사유 필수, 변경 없음·허용 외 항목·지급일 이전 반납일·반납일/진행상태 모순 차단.
- 다른 사용자가 먼저 정정한 경우 버전 충돌 처리.
- 반납 이력 추가 → 반납일 삭제 시 정정취소 보존 → 반납일 복원 시 같은 이력 재사용. 중복 생성 없음.
- 원본 스냅샷·금액·운영 카드·승인대기 자료·다른 원본 행 보존. 일반 상태 API로 정정/번호/작성기준일 위조 차단.
- DB 저장 실패 시 두 대장·원본 등록부·정정 내역을 함께 롤백.
- 전체백업 복구 후 번호·원본·정정 이력 보존.
- 기존 최대 **2,000행** 업로드 검사도 전체 서버 검사에 포함: 정산이력 2,000건 / 불출 2,000건 / 반납 2,000건 / 재검사 중복 2,000행. 자동백업 도래 상태에서도 저장 완료.

## 이전 실제 첨부와 회귀 확인

- 이전 실제 **Book1.xlsx**의 제목 5행/업무 6~9행 → 정산이력4·불출4·반납3·금액미기재3·합계225,000원·재검사 중복4.
- 사용정산 일련번호1~4, 불출반납 일련번호1~7과 작성기준일 생성 확인. 사용자·부서·카드 끝자리·날짜·금액 등 원본 대응 항목 대조.
- 실제 첨부 파일과 개인정보는 배포 ZIP·시험 로그·공개 캡처에 넣지 않음.
- 기존 업로드 확인창 취소·실패 입력 보존·재시도, 실제 XLSX/PDF 출력 회귀 확인.
- 수신함 방식의 기존 신청/정산 수신·매칭·불출·반납 및 법인카드 목록 XLSX/PDF 회귀 확인.
- 일반 보고서 결재·저장 실패 보존·전체백업 재인증과 ZIP 다운로드·하이패스 등록·공지·메모·메신저 저장 회귀 확인.
