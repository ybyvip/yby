# V4.1.21 백업·복구 안내

## 미리 준비

1. 전체백업을 만들고 별도 디스크/회사 보관소에 보관합니다. 백업 암호는 파일과 따로 지정된 담당자가 관리합니다.
2. 서버 고장까지 대비하려면 암호화 백업에서 `서버 인증서·LAN 설정·Windows CA 개인키(PFX)도 포함`을 선택합니다. 일반 전체백업과 재해 복구 자료는 다릅니다.
3. Windows의 복원 비밀번호 표시 암호문은 Windows 사용자 DPAPI에 종속될 수 있습니다. 일반 로그인용 PBKDF2 해시 계정과 업무 자료는 백업됩니다. 다른 PC에서 표시용 암호문이 안 열린다고 계정 DB를 지우지 마세요. 기본 정책은 표시를 끕니다.

## 기존 PC의 업무 자료 복원

1. 회사 사용자 접속을 종료시키고 서버 창에서 Ctrl+C로 정상 중지합니다. 잠금 파일을 지우지 않습니다.
2. 새 패키지 전체를 새 폴더에 해제합니다. `INSTALL_BACKUP_ENCRYPTION.bat`로 같은 Python에 암호화 지원을 설치합니다.
3. 새 폴더의 `BACKUP_RESTORE_WINDOWS.bat` 실행 → 1번으로 백업 검증 → 다시 실행 → 3번 자료 복원입니다.
4. 실제 자료 폴더와 백업 버전/건수를 확인하고 `복원`을 입력합니다. 기존 data는 data_before_restore_시각으로 보존됩니다. 프로그램 파일을 백업의 구버전으로 덮어쓰지 않습니다.
5. RUN_LAN_WINDOWS.bat 실행 후 관리자·지점 로그인, 카드/정산 금액·건수, 첨부·수기 정정·매칭/중복·하이패스 상태를 확인합니다. 구버전 프로그램으로 스키마9 DB를 열지 않습니다.

## 새 Windows 서버 PC로 교체

1. 회사 IT 담당자가 Python3.11 이상, Edge/WebView2, 실행 사용자와 사내 IP·방화벽·디스크 보호를 준비합니다.
2. 새 패키지의 `BACKUP_RESTORE_WINDOWS.bat` 3번을 먼저 이용하면 실행 폴더를 준비하고 DB/첨부를 복원할 수 있습니다. 먼저 빈 서버로 운영을 시작하거나 기존 data를 임의 복사해 덮어쓰지 마세요.
3. 재해 복구 자료가 포함되었다면 `%LOCALAPPDATA%\YBY\app\recovery_review_시각`으로 제한된 접근권한으로 추출됩니다. 운영 인증서는 자동 교체하지 않습니다.
4. Windows에서 만든 `root-ca.pfx`가 있으면 파일을 더블클릭하여 **현재 사용자 → 개인(인증서 저장소 My)**에 백업 암호로 가져옵니다. 백업의 lan_settings.json에 있는 root_thumbprint가 해당 인증서와 맞는지 IT 담당자가 확인합니다. 다른 회사 인증서를 지우지 마세요.
5. 복구 검토 폴더의 certificates와 lan_settings.json을 실행 폴더에 복구합니다. 새 PC에 이미 인증서/설정이 있다면 IT 담당자가 기존 것을 별도 보존하고 올바른 CA를 결정한 뒤 적용합니다. 백업 검토 폴더를 LAN_CLIENT로 공유하지 않습니다.
6. 새 서버의 IP/호스트명이 달라지면 RUN_LAN_WINDOWS.bat로 새 서버 IP를 지정합니다. 기존 CA 개인키가 정상 복구되면 같은 CA로 새 IP/이름에 맞는 서버 인증서를 발급할 수 있습니다. CA를 복구할 수 없으면 새 CA를 만들고 모든 클라이언트에서 새 지문을 확인·등록해야 합니다.
7. 다른 PC에는 새 LAN_CLIENT만 배포합니다. 서버/지점에서 HTTPS 인증서·주소·로그인·권한·첨부를 확인합니다. 브라우저 인증서 경고를 무시하는 방식으로 완료 처리하지 않습니다.
8. `backup-policy-public.json`은 설정 참고용입니다. 별도 보관 폴더·암호를 새 서버의 백업·복구 관리에서 다시 설정하고 저장/시험 복원을 실행합니다. 서버 사용자에 종속된 자동 보관 암호 저장소를 무작정 복사하지 않습니다.

## 명령줄이 필요한 담당자

실제 실행 폴더에서 `python backup_tool.py verify <백업파일>` 또는 `python backup_tool.py restore <백업파일> --data-dir <실제data경로>`를 사용합니다. 암호화 파일은 비밀번호를 프롬프트로 받으며 명령 인자에 비밀번호를 적지 않습니다. `extract-recovery <파일> --output-dir <새폴더>`는 접속 환경만 새 경로에 추출합니다.

## 완료 판정

- DB 무결성·파일 해시·계정·원본 금액·정산/불출/반납 건수·정정/매칭/중복 이력 일치
- 서버 CA 개인키/주소·클라이언트 신뢰·권한·첨부 정상
- 허용 자료 손실량(RPO)과 복구 시간(RTO)을 회사가 정하고 실측

프로그램의 임시 폴더 시험 복원은 새 회사 PC·인증서 저장소·보안 정책 시험을 대신하지 않습니다.
