# YBY V4.1.1 가정 개발·회사 적용 안내

작성: 2026-10-16 / Windows용 / 가정 전용 실행도구 추가판  

이 패키지는 V4.1.1 프로그램 전체와 가정 개발·회사 배포 보조도구를 포함합니다.  
새 업무기능을 추가한 버전은 아니며, 집에서 개발할 수 있는 실행 환경을 제공합니다.  
지금 ChatGPT가 사용자 PC에 원격 설치한 것은 아닙니다. 아래 파일을 내려받아 직접 실행하세요.  

집에서는 http://127.0.0.1:5100/ 으로 접속합니다.  
회사에서는 https://10.10.0.121:5000/ 으로 접속합니다.  
집에서 10.10.0.121을 입력하면 회사 서버에 자동 접속되는 것은 아닙니다.  
집 전용 실행은 다른 PC에서 접속할 수 없으며 인증서 설치가 필요 없습니다.  


## 1. 오늘 집 PC 최초 준비

1) Python이 없으면 https://www.python.org/downloads/windows/ 에서  
   Python 3.11 이상을 설치하세요. Python 3.13 64비트를 권장합니다.  
   설치 화면에서 Add python.exe to PATH 항목이 보이면 선택합니다.  
   명령 프롬프트에서 py -3 --version 또는 python --version으로 확인합니다.  
   Windows 실행은 별도의 pip 패키지 설치 없이 가능합니다.  
2) 다운로드한 YBY_HOME_DEV_4_1_1.zip을 ZIP 안에서 실행하지 마세요.  
   탐색기에서 전체 압축 해제하세요.  
   권장 위치: C:\Users\자신의계정\source\YBY_HOME_DEV_4_1_1  
   Win+R에 %USERPROFILE% 를 넣으면 자신의 사용자 폴더를 열 수 있습니다.  
   그 아래 source 폴더를 만들고 압축 해제한 폴더를 옮기면 됩니다.  
   HOME_START.bat, app.py, templates, dev_tools가 같은 폴더에 있어야 합니다.  
3) HOME_START.bat를 일반 권한으로 더블클릭합니다.  
   RUN_LAN_WINDOWS.bat나 RUN_WINDOWS.bat는 집 개발 작업에 사용하지 마세요.  
   HOME_START는 소스를 직접 실행하므로 수정 후에도 원본 MANIFEST 검사로 막히지 않습니다.  
4) 로그인 화면이 자동으로 열립니다. 안 열리면 브라우저 주소창에  
   http://127.0.0.1:5100/ 를 정확히 입력합니다. 집 실행은 http입니다.  
5) 계정은 admin입니다. 첫 실행 검은 창에 출력되는  
   [최초 임시 비밀번호] admin: ... 값을 입력하세요.  
   회사 비밀번호와 별개로 새로 발급됩니다. 로그인하면 새 비밀번호로 변경합니다.  
   이 임시값은 첫 생성 때만 출력되므로 창을 닫기 전에 확인하세요.  
6) 비밀번호를 놓쳤다면 HOME_START 실행 창에서 Ctrl+C로 서버를 종료하고  
   HOME_RESET_ADMIN.bat를 실행하여 집의 admin 비밀번호를 다시 정하세요.  
   10~128자 새 비밀번호를 두 번 입력합니다. 입력 중 문자가 보이지 않아도 정상입니다.  
   다시 HOME_START.bat를 실행합니다. 회사 비밀번호에는 영향을 주지 않습니다.  


## 2. 다시 접속 / 개발 / 종료

- 검은 실행 창은 열어 두세요. 브라우저만 닫았다면 HOME_LOGIN.bat를 실행하면 됩니다.  
- 실행 창까지 종료했다면 HOME_START.bat를 다시 실행하세요.  
- 프로그램 종료: HOME_START 실행 창에서 Ctrl+C. 잠금파일은 지우지 마세요.  
- VS Code 등에서 이 개발 폴더를 열어 편집합니다.  
  화면: templates/index.html  
  서버/API: app.py, operations.py  
  정산 승인취소·정정·재보고: settlement_workflow.py  
  검증: domain.py / DB 저장: storage.py  
- 수정 반영: 서버 Ctrl+C → HOME_START 재실행 → 브라우저 Ctrl+F5.  
- 집의 시험자료: 개발 폴더의 data. AppData\Local\YBY\app 자료를 사용하지 않습니다.  
  실행도구는 회사 경로를 가리키는 V3_/V4_ 환경설정을 제거하고 집 data 경로를 지정합니다.  
- 시험 카드·가상 직원·가상 첨부만 사용하세요. 회사 실제 자료를 개인 PC로 옮길 때는  
  회사의 허용 범위를 먼저 확인하세요.  
- 보안인증서나 방화벽을 완화할 필요가 없습니다. 공유기 포트포워딩도 필요 없습니다.  
- 한 가지씩 수정하고, 그 기능의 성공·실패·권한별 동작을 확인하세요.  
  새 .py/화면/정적파일을 만들면 dev_tools/EXTRA_FILES.txt에 상대경로를 한 줄씩 적으세요.  
  기존 파일 수정은 등록하지 않아도 됩니다. DB·인증서·키는 등록할 수 없습니다.  
- Python으로 개발하려면 회사에도 같은 Python 버전을 사용하는 편이 좋습니다.  
  집에서만 설치한 외부 모듈에 의존하도록 수정하면 회사 실행이 실패할 수 있습니다.  


## 3. 오늘 작업을 회사로 가져갈 ZIP 만들기

1) 수정 내용을 저장하고 집 서버를 Ctrl+C로 종료하세요.  
2) BUILD_COMPANY_UPDATE.bat를 실행합니다.  
   실제 ZIP에 들어갈 소스 복사본에서 문법 검사와 전체 자동 테스트를 실행합니다.  
   수십 초~수 분 걸릴 수 있습니다. 오류가 있으면 ZIP을 새로 생성하지 않습니다.  
   실패 시 dist 폴더의 *_tests.txt를 확인하세요. 실패한 검사를 무시하지 마세요.  
3) 성공하면 dist 폴더가 열립니다. 새로 만들어진 최신 파일은  
   YBY_COMPANY_UPDATE_4_1_1_날짜시각.zip 입니다. 시각은 UTC입니다.  
   ZIP과 같은 이름의 .zip.sha256 파일을 같이 가져갑니다.  
   *_tests.txt도 검증 기록으로 보관하세요.  
4) 이 ZIP은 집의 data DB·첨부·계정·비밀번호·인증서·LAN 설정을 제외합니다.  
   시험자료가 회사 업무자료를 덮어쓰지 않도록 허용된 프로그램 파일만 묶습니다.  
   MANIFEST.json을 수정된 소스에 맞춰 새로 생성하며 원본 개발 폴더는 바꾸지 않습니다.  
5) USB 또는 회사에서 허용한 전송수단으로 가져갑니다.  
   개발 폴더 전체 또는 집의 data를 회사 실행폴더에 복사하지 마세요.  
   앱 안에서 파일에 직접 적은 비밀값까지 자동 탐지하지는 못하므로  
   코드·설정에 실제 비밀번호/API 키/업무정보를 적어두지 마세요.  


## 4. 내일 회사에서 적용하기 — 기존 자료 유지

반드시 실제 서버 PC에서, 원래 서버를 실행하던 동일 Windows 계정으로 진행하세요.  
다른 지점 PC에서 실행하면 서버 업데이트가 되지 않습니다.  

1) 사용 중인 직원에게 잠시 접속을 중단하도록 알립니다.  
   업데이트로 서버가 재시작되므로 기존 로그인은 종료되고 다시 로그인해야 합니다.  
2) 가져온 ZIP의 SHA-256을 확인하세요.  
   PowerShell에서 다음 명령을 쓰고 .zip.sha256 파일의 64자리 값과 비교할 수 있습니다.  
   Get-FileHash -Algorithm SHA256 '가져온ZIP의전체경로'  
3) ZIP을 바탕화면/다운로드의 별도 새 폴더에 전체 압축 해제합니다.  
   기존 AppData\Local\YBY\app 안에 압축 해제하지 마세요.  
   패키지의 BUILD_INFO.json에는 빌드 시각·변경 파일·자동검사 결과가 들어 있습니다.  
4) 기존 회사 서버 실행 창에서 Ctrl+C로 정상 종료하고 기다립니다.  
   기존 창을 찾지 못했다면 새 패키지의 STOP_SERVER.bat를 실행할 수 있습니다.  
   data.runtime.lock을 수동 삭제하지 마세요.  
5) 새로 푼 폴더의 APPLY_COMPANY_UPDATE.bat를 일반 권한으로 실행합니다.  
   관리자 실행이나 다른 관리자 계정 실행을 하지 마세요.  
   이 도구는 다음 순서로 동작합니다.  
   - 새 프로그램 무결성과 집의 DB·인증서가 섞이지 않았는지 확인  
   - 기존 회사 서버/유지보수 잠금을 확인; 실행 중이면 변경 없이 중단  
   - 기존 업무 DB 무결성 확인  
   - 기존 실행폴더 전체(자료·첨부·프로그램·설정·인증서·키 포함)를 ZIP 백업  
   - 백업 CRC 및 파일별 SHA-256 검증  
   - 프로그램만 교체하고 기존 data·계정·비밀번호·인증서·LAN 설정 유지  
   - 회사 사내망 서버 재시작  
   백업 실패 시 프로그램 교체를 시작하지 않습니다.  
6) 백업은 이 위치에 생성됩니다.  
   %LOCALAPPDATA%\YBY\pre_update_backups\runtime_before_update_날짜시각.zip  
   필요하면 BACKUP_COMPANY_BEFORE_UPDATE.bat로 백업만 따로 만들 수 있습니다.  
   여기에는 회사 업무자료와 개인키가 있으므로 회사 내부에서 보호해서 보관하세요.  
   원래 실행폴더가 너무 크면 백업에 시간·디스크 공간이 필요합니다.  
7) 회사 기존 admin 비밀번호로 로그인합니다. 집 비밀번호를 쓰지 않습니다.  
   서버: https://localhost:5000/  
   지점: https://10.10.0.121:5000/  
   회사 IP가 바뀌었다면 기존 사내망 설정 절차를 따르세요.  
8) 새 패키지의 VERIFY_WINDOWS.bat를 실행합니다.  
   서버 버전·프로세스·DB·HTTPS·인증서·중복실행 등을 실제 Windows에서 확인합니다.  
   같은 V4.1.1 수정빌드끼리는 화면 버전이 같을 수 있습니다.  
   %LOCALAPPDATA%\YBY\app\BUILD_INFO.json의 빌드 시각으로 적용본을 구분하세요.  
9) 새로 고친 기능을 admin/지점 계정으로 각각 확인합니다.  
   예: 공지 첨부 열기·다운로드, 불출/반납, 정산 세부합계,  
   본인 승인·정정 이유·재보고·승인/반려, 다른 지점의 세션 유지.  
   업데이트 전 기존 카드/정산 건수와 첨부파일도 확인하세요.  
   문제없음을 확인한 뒤 다른 직원의 사용을 재개합니다.  
10) 동일 서버·IP·인증서를 유지하면 다른 PC의 인증서 재설치는 보통 필요 없습니다.  
    접속이 안 되면 서버 OPEN_LAN_CLIENT.bat로 최신 LAN_CLIENT.zip을 열어 전달하고,  
    다른 PC에서 압축 해제 후 INSTALL_AND_CONNECT.bat 및 CHECK_CONNECTION.bat를 실행합니다.  


## 5. 문제가 있으면 원래 상태로 되돌리기

업데이트 직후 점검 중 문제가 생기면 새 업무 입력을 중단하고 진행합니다.  
1) 업데이트한 서버를 Ctrl+C/STOP_SERVER.bat로 종료합니다.  
2) Win+R → %LOCALAPPDATA%\YBY 를 엽니다.  
3) 현재 app 폴더를 app_failed_날짜시각 으로 이름을 바꿉니다. 삭제하지 마세요.  
4) 이번 업데이트 직전의 pre_update_backups\runtime_before_update_...zip을  
   임시 폴더에 전체 압축 해제합니다. 안쪽 app 폴더를 %LOCALAPPDATA%\YBY\app 로 복사합니다.  
   app\app 형태가 되지 않게 주의합니다. app 바로 아래에 app.py, data가 있어야 합니다.  
   SNAPSHOT_MANIFEST.json은 백업의 파일별 체크섬이며 업무폴더 밖에 있습니다.  
5) 복원한 %LOCALAPPDATA%\YBY\app\RUN_LAN_WINDOWS.bat를 실행합니다.  
   새 수정본 폴더의 RUN_LAN_WINDOWS를 실행하면 다시 업데이트될 수 있으니 사용하지 마세요.  
6) 백업 시점으로 DB와 프로그램이 함께 복원됩니다.  
   업데이트 후 입력한 자료는 복원본에 없습니다. app_failed 폴더를 보존하고 별도 검토하세요.  
   새 DB에 옛 프로그램만 덮어쓰면 스키마 차이로 실행이 거부될 수 있습니다.  
   Windows 암호화 비밀번호 보관값은 원래 PC·원래 사용자 계정에서 복원해야 합니다.  


## 검증 범위

자동 테스트는 정산/권한/세션/첨부/API와 분리 실행·백업·배포 제외항목을 검사합니다.  
최종 ZIP 생성은 전체 테스트 통과를 요구하지만 화면의 모든 수동 동작을 보장하지 않습니다.  
Linux에서 가정 실행·로그인·재접속·ZIP생성·회사자료 보존을 검증했습니다.  
사용자 집/회사 Windows에 원격 설치하거나 Edge·회사 보안정책을 직접 확인한 것은 아닙니다.  
집 PC에서 처음 HOME_START가 정상 실행되고 로그인되는지 먼저 확인하세요.
